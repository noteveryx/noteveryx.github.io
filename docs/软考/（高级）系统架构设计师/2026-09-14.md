## 今日核心概念

### 1. 系统安全架构设计
定义：从架构层面保障信息系统机密性、完整性、可用性、可控性和不可否认性的整体设计方法，涵盖物理安全、网络安全、主机安全、应用安全、数据安全和管理安全六个层次。
关键要点：安全三要素CIA——机密性（Confidentiality，防未授权访问）、完整性（Integrity，防篡改）、可用性（Availability，防服务中断）；等保2.0五级——用户自主保护级、系统审计保护级、安全标记保护级、结构化保护级、访问验证保护级；等保三级技术要求分五层面——安全物理环境、安全通信网络、安全区域边界、安全计算环境、安全管理中心；应用安全核心机制——身份认证（口令/生物特征/数字证书/双因素）、访问控制（DAC/MAC/RBAC/ABAC）、安全审计、输入校验、会话管理；数据安全——传输加密TLS/国密SSL、存储加密AES-256/SM4、敏感数据脱敏、数据库加密TDE、密钥管理KMS/HSM；常见攻击与防护——SQL注入（参数化查询）、XSS（输出编码+内容安全策略）、CSRF（Token校验）、中间人攻击（证书固定+HSTS）；安全架构原则——纵深防御、最小权限、默认拒绝、安全左移、不信任任何输入。

### 2. 系统可靠性设计与高可用架构
定义：通过冗余、容错、故障隔离、快速恢复等手段，使系统在部分组件失效时仍能持续提供约定服务水平的架构设计方法。
关键要点：可靠性四性——成熟性、容错性、易恢复性、依从性；可用性公式A=MTTF/(MTTF+MTTR)，99.99%年宕机≤52.56分钟；高可用三剑客——负载均衡（分摊流量）、故障转移（主备切换）、数据冗余（多副本）；主备架构模式——冷备（恢复慢成本低）、温备（部分同步）、热备（实时同步秒级切换）、双活（同城双活/异地多活）；故障检测机制——心跳检测、健康检查探针、超时重试、断路器；降级与限流——降级牺牲非核心保核心、限流防止流量打垮系统；灾备关键指标——RTO恢复时间目标、RPO恢复点目标、NRO网络恢复目标；容错设计——故障隔离舱壁模式、冗余设计N+1/M+N、优雅降级、熔断快速失败；软件容错——N版本程序设计（多个独立实现同时运行表决）、恢复块技术（主模块失败回退到备用模块）、防卫式程序设计（断言、输入校验、异常处理）。

### 3. 软件架构演化与维护
定义：软件系统在其生命周期内，为适应业务变化、技术债务、性能瓶颈、安全威胁等而进行的结构、行为和属性的持续变更过程。
关键要点：架构演化四个维度——结构演化（模块拆分合并）、行为演化（流程调整）、数据演化（ schema 变更迁移）、质量属性演化（性能/安全提升）；架构演化的驱动力——业务需求变化、技术栈更新、性能容量不足、安全合规要求、组织结构调整；架构腐化信号——循环依赖、上帝类、重复代码、接口膨胀、技术债务累积；遗留系统演化策略——淘汰（业务废弃）、继承（继续使用）、改造（局部重构）、集成（ESB/API网关封装）；再工程三活动——逆向工程（从代码恢复设计）、重构（不改变外部行为优化内部结构）、正向工程（从设计生成新系统）；架构维护四类型——改正性维护（修复缺陷）、适应性维护（环境变化）、完善性维护（新增功能）、预防性维护（降低风险）；架构演化的原则——小步快跑、兼容性优先、自动化回归测试、监控驱动、回滚预案。

### 4. 面向服务的架构（SOA）与企业服务总线（ESB）
定义：SOA是一种将业务功能封装为可复用、松耦合、标准化服务的架构范式；ESB是实现服务间互联互通、协议转换、路由编排、安全管控的基础设施中间件。
关键要点：SOA三角色——服务提供者（Provider）、服务请求者（Consumer）、服务注册中心（Registry）；SOA三操作——发布（Publish）、查找（Find）、绑定（Bind）；服务设计原则——服务自治、松耦合、可复用、可组合、可发现、标准化契约；SOA实现技术栈——WebService（SOAP/WSDL/UDDI）、RESTful API、SCA、SDO；ESB核心能力——路由（内容/策略/动态路由）、协议转换（HTTP/HTTPS/JMS/FTP/SOAP/REST）、消息转换（XML/JSON/二进制）、服务编排（BPEL）、安全（认证授权审计）、监控管理；ESB vs API网关——ESB侧重企业内部异构系统集成（重ESB/重协议转换），API网关侧重南北向流量入口（轻网关/路由鉴权限流）；SOA与微服务区别——SOA服务粒度粗、共享数据库、ESB集中式治理；微服务粒度细、独立数据库、去中心化治理；SOA适用场景——大型企业异构系统集成、跨部门服务复用、遗留系统Wrapper化。

### 5. 软件架构评估方法体系
定义：运用系统化方法对软件架构满足质量属性需求程度进行评价、预测和选择的过程，是降低架构风险、支撑决策的重要手段。
关键要点：ATAM（架构权衡分析法）——以质量属性效用树为核心，识别风险点、非风险点、敏感点、权衡点；SAAM（软件架构分析法）——ATAM前身，关注可修改性，通过场景评估架构对变更的支持能力；CBAM（成本效益分析法）——在ATAM基础上引入经济性，计算架构策略的成本与收益；ARID（主动评审中间设计）——针对尚未完成的架构设计进行评审；ADD（属性驱动设计）——从质量属性需求出发递归分解设计决策；质量属性场景六要素——刺激源、刺激、环境、制品、响应、响应度量；常见质量属性——性能（响应时间/吞吐量）、可用性（故障恢复）、安全性（防护能力）、可修改性（变更成本）、可测试性、易用性、可移植性、可伸缩性；评估输出物——风险清单、敏感点清单、权衡点清单、架构改进建议、质量属性效用树。

## 案例分析题

**题目**：
某省级政务一体化平台已建成运行5年，日均业务量80万笔，高峰期TPS达3000。系统采用传统单体架构，使用Oracle数据库，部署在政务云单可用区。随着"一网通办"业务扩展，系统面临以下问题：

1. 单体应用代码超过150万行，核心开发人员离职率高，新人上手周期长达3个月，需求平均交付周期从2周延长至6周；
2. 数据库Oracle单节点CPU长期85%以上，夜间批处理时段经常超过95%，历史数据累积导致全表扫描SQL响应从200ms恶化至8秒；
3. 系统去年因政务云存储故障中断服务4小时，因数据库主库故障切换耗时45分钟，全年可用性仅99.45%；
4. 等保2.0三级测评中发现：数据库明文存储身份证号、接口未做防重放攻击、缺少完整操作审计日志、管理员权限过大；
5. 新上线的"医保报销一件事"需要对接人社、医保、税务、银行4个部门原有系统，接口协议各异（SOAP/XML、REST/JSON、FTP文件、Socket长连接）。

请作为系统架构设计师回答：
(1) 请给出整体架构演化方案（单体拆分、数据库优化、高可用改造）；
(2) 请设计安全架构整改方案，满足等保2.0三级要求；
(3) 请设计跨部门系统集成方案，说明技术选型和数据一致性保障。

**参考答案**：

问题一：整体架构演化方案

一、单体应用拆分：
1. 采用"绞杀者模式"逐步演进，而非一次性重构；优先拆分高频变更、性能瓶颈明显的业务域。
2. 按DDD限界上下文划分为6个核心微服务：用户认证服务、事项申报服务、材料管理服务、审批流转服务、统一出证服务、综合查询服务。
3. 技术栈：Spring Boot 3.x + Spring Cloud Alibaba（Nacos注册配置中心、Sentinel限流熔断、Seata分布式事务）；服务间采用RESTful + gRPC，异步事件采用RocketMQ。
4. 前端按业务域拆分为独立SPA，通过统一门户集成，后端通过API网关统一接入。

二、数据库优化：
1. 读写分离：Oracle主库写入，2个只读从库承载查询，报表类查询路由到从库，关键业务强制走主库。
2. 分库分表：按事项类型+时间维度拆分历史数据，近6个月热数据保留Oracle，历史数据归档到TiDB或达梦分析库。
3. 索引优化：对高频查询字段（身份证号、事项编码、申请时间）建立复合索引；删除冗余索引；对慢SQL建立监控和治理机制。
4. 引入分布式缓存Redis Cluster：缓存用户会话、事项配置、字典数据，降低数据库查询压力50%以上。
5. 批处理优化：大事务拆分为小事务，夜间批处理错峰执行，引入分布式任务调度XXL-JOB。

三、高可用改造：
1. 同城双活：政务云双可用区部署，应用层无状态多实例，数据库采用Oracle DataGuard或MySQL MGR主从架构。
2. 负载均衡：入口F5/SLB + 应用层Nginx，应用多实例部署至少3节点。
3. 故障自动转移：数据库主从自动切换RTO<30秒；Redis Cluster哨兵模式；Nacos集群部署。
4. 服务治理：Sentinel熔断降级，非核心服务异常时不影响核心申报和审批流程；线程池隔离防止雪崩。
5. 目标可用性：从99.45%提升至99.95%（年宕机<4.38小时），核心业务99.99%。

问题二：安全架构整改方案

一、等保2.0三级技术层面：
1. 安全物理环境：机房门禁、视频监控、环境监控已具备，重点补全电磁屏蔽和冗余电力。
2. 安全通信网络：政务外网与互联网边界部署防火墙、入侵检测/防御系统、VPN网关；南北向流量全TLS 1.3加密；内部服务间mTLS双向认证。
3. 安全区域边界：部署Web应用防火墙WAF防SQL注入、XSS、CC攻击；API网关统一接入并实施限流、黑白名单、防重放攻击。
4. 安全计算环境：服务器安全加固、漏洞扫描、恶意代码防护、基线核查；容器化后使用镜像安全扫描。
5. 安全管理中心：集中日志审计、堡垒机、数据库审计、态势感知平台；统一身份认证IAM。

二、数据安全专项：
1. 敏感数据加密存储：身份证号、手机号、银行卡号等字段采用SM4国密算法加密；数据库启用TDE透明加密。
2. 数据脱敏：前端展示身份证110101********1234、手机号138****8000；测试环境使用脱敏数据。
3. 密钥管理：部署KMS密钥管理服务或HSM硬件加密机，密钥分级管理、定期轮换。
4. 访问控制：RBAC+ABAC双层模型，最小权限原则，管理员操作需双人复核、动态授权。

三、应用安全与审计：
1. 身份认证：政务网用户数字证书+USBKey双因素认证；公众用户短信验证码+人脸识别。
2. 防重放攻击：接口请求携带时间戳和Nonce随机数，服务端5分钟内拒绝重复Nonce。
3. 安全审计：用户操作、管理员操作、数据库访问、接口调用全量留痕，日志保留≥180天，日志防篡改。
4. 安全开发：SDL安全开发生命周期，代码审计、渗透测试、漏洞响应机制。

问题三：跨部门系统集成方案

一、集成架构设计：
1. 采用企业服务总线ESB/API网关作为统一集成层，屏蔽异构协议差异；内部微服务通过ESB调用外部系统。
2. 协议适配：人社SOAP/XML接口→协议转换适配器；医保REST/JSON接口→直接透传；税务FTP文件交换→文件传输适配器；银行Socket长连接→长连接池适配器。
3. 统一数据标准：定义事项编码、申请单号、材料清单、办理结果等统一数据字典；通过数据映射组件完成字段转换。
4. 异步解耦：非实时业务采用RocketMQ消息队列异步处理，避免同步阻塞；实时查询采用同步调用+熔断降级。

二、数据一致性保障：
1. 强一致场景（医保报销金额扣减+银行转账）：采用TCC补偿事务或Seata AT模式，Try预留额度、Confirm确认扣减、Cancel释放额度。
2. 最终一致场景（申报材料同步、办理结果通知）：采用本地消息表+RocketMQ可靠消息+幂等消费；失败消息进入死信队列人工处理。
3. 对账机制：每日凌晨与税务、银行、医保系统进行业务对账，发现差异自动告警并触发补偿流程。
4. 幂等性设计：所有跨系统调用携带全局业务流水号，接收方通过数据库唯一索引或Redis去重表防重。

三、服务编排与监控：
1. 使用BPMN/BPEL定义"医保报销一件事"跨部门业务流程，状态机驱动：提交→人社核验→医保审核→税务核验→银行打款→结果通知。
2. 全链路追踪：通过TraceId串联各系统调用，SkyWalking/Zipkin可视化展示跨部门调用链。
3. 熔断与限流：外部系统故障时触发熔断，返回"办理中"状态并异步补偿；每个外部系统配置独立QPS配额。

**踩分要点**：
- 单体拆分必须体现"绞杀者模式"、DDD领域划分、Spring Cloud Alibaba技术栈、API网关统一接入
- 数据库优化必须包含读写分离、分库分表/历史归档、索引优化、Redis缓存、批处理优化
- 高可用必须包含同城双活/多可用区、主从自动切换、负载均衡、服务治理、可用性目标
- 安全整改必须对应等保2.0三级五个技术层面，并具体化数据加密、脱敏、防重放、审计、最小权限
- 跨部门集成必须包含ESB/API网关协议转换、统一数据标准、异步解耦、分布式事务/最终一致/对账、服务编排、全链路追踪
- 关键数字：80万笔/日、3000TPS、150万行代码、99.45%→99.95%、RTO<30秒、日志180天

## 记忆口诀

安全三要素口诀：「CIA机密完整可用」
- 机密性+完整性+可用性

等保2.0三级五层面口诀：「物通界算管」
- 安全物理环境+安全通信网络+安全区域边界+安全计算环境+安全管理中心

应用安全六字诀：「认证授权审计」
- 身份认证+访问控制+安全审计

常见攻击防护口诀：「SQL参数化、XSS输出编、CSRF带Token、MITM固定证」
- SQL注入用参数化查询、XSS做输出编码、CSRF校验Token、中间人攻击证书固定

可用性公式口诀：「可用=MTTF除MTTF加MTTR」
- A=MTTF/(MTTF+MTTR)，降低MTTR比提升MTTF更见效

高可用三剑客口诀：「负转冗」
- 负载均衡+故障转移+数据冗余

主备四模式口诀：「冷温热双」
- 冷备+温备+热备+双活

灾备两指标口诀：「RTO看时间、RPO看数据」
- RTO恢复时间目标、RPO恢复点目标

软件容错三技术口诀：「N版恢复防卫式」
- N版本程序设计+恢复块技术+防卫式程序设计

架构演化四维度口诀：「结行数质」
- 结构演化+行为演化+数据演化+质量属性演化

遗留系统四策略口诀：「淘继改集」
- 淘汰+继承+改造+集成

再工程三活动口诀：「逆重正」
- 逆向工程+重构+正向工程

维护四类型口诀：「改适完预」
- 改正性+适应性+完善性+预防性

SOA三角色三操作口诀：「提请注、发查绑」
- 服务提供者+服务请求者+服务注册中心；发布+查找+绑定

ESB六能力口诀：「路协转编安管」
- 路由+协议转换+消息转换+服务编排+安全+管理监控

- ESB重企业内部东西向集成，API网关轻南北向入口

- SOA服务粗粒度+共享数据库+ESB集中治理；微服务细粒度+独立数据库+去中心化

- 架构权衡分析+软件架构分析+成本效益分析+主动评审中间设计+属性驱动设计

ATAM四象限口诀：「风非敏权」
- 风险点+非风险点+敏感点+权衡点

质量场景六要素口诀：「源激环制响度」
- 刺激源+刺激+环境+制品+响应+响应度量

- 传输TLS加密、存储SM4国密、展示脱敏、操作审计、密钥KMS管理

- 请求带时间戳+随机数，服务端限制时间窗口内Nonce唯一
