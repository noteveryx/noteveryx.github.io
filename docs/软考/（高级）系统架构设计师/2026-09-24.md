## 今日核心概念

### 1. 零信任架构（Zero Trust Architecture）
定义：以"永不信任，持续验证"为核心原则，通过身份认证、动态授权、最小权限、加密传输等机制，对每一次访问请求进行严格的身份验证和授权，不依赖网络位置判定信任。
关键要点：
- 核心原则：Never Trust, Always Verify（永不信任，持续验证）
- 三大组件：策略引擎PE（Policy Engine）、策略管理器PA（Policy Administrator）、策略执行点PEP（Policy Enforcement Point）
- 关键能力：微分段（Microsegmentation）、最小权限（Least Privilege）、动态访问控制、设备信任评估
- 标准框架：NIST SP 800-207 零信任架构标准
- 适用场景：远程办公、混合云、多分支机构、第三方协作访问

### 2. 纵深防御（Defense in Depth）
定义：通过在不同网络层次、不同位置部署多种安全防护措施，形成多层防御体系，即使某一层被攻破，其他层仍能提供保护，提升整体攻击成本。
关键要点：
- 七层防御：数据层、应用层、主机层、网络层、物理层、管理层、用户层
- 核心思想：冗余性（多层叠加）、多样性（不同技术）、层次性（外到内）
- 典型技术：防火墙+IDS/IPS+WAF+防病毒+数据加密+访问控制+日志审计
- 优势：提高攻击成本、降低单点失陷风险、增加检测时间窗口
- 实施策略：从外到内多层防护，每层都有专门防御手段，形成纵深体系

### 3. 密码学基础（对称/非对称加密、签名与证书）
定义：通过数学算法对数据进行加密保护，保证数据的机密性（Confidentiality）、完整性（Integrity）、不可否认性（Non-repudiation）。
关键要点：
- 对称加密：AES、DES、3DES（速度快，适合大量数据加密，密钥分发难）
- 非对称加密：RSA、ECC（密钥分发安全，适合小数据量加解密和签名）
- 哈希算法：SHA-256、SM3（单向不可逆，用于完整性校验）
- 数字签名：用私钥签名，公钥验签（防否认、防篡改）
- 数字证书：CA机构颁发，绑定公钥与身份（防冒充，构建PKI信任链）
- 国密算法：SM2（非对称）、SM3（哈希）、SM4（对称），国产合规替代

### 4. 可信计算（Trusted Computing）
定义：通过硬件和软件协同，在计算平台上构建可信赖的执行环境，保证系统从启动到运行的完整可信链，实现"被动防御"到"主动免疫"的升级。
关键要点：
- 核心机制：可信度量根RTM、可信平台模块TPM（国际）/TCM（国密）
- 信任链传递：BIOS→BootLoader→OS→APP 逐级完整性度量
- 远程证明：TPM生成的PCR（Platform Configuration Register）值验证平台状态
- 国密TCM：可信密码模块，符合中国密码行业标准
- 应用场景：电子政务、金融支付、国防领域、关键信息基础设施

### 5. 安全架构评估方法（SAAM、ATAM、CBAM）
定义：通过系统化的方法对软件架构的安全性进行评估，识别潜在风险点、安全权衡点与改进方案，为架构安全演进提供决策依据。
关键要点：
- SAAM：基于场景的架构分析方法（早期评估，方法简单）
- ATAM：架构权衡分析法（评估多个质量属性，含安全、性能、可用性）
- CBAM：成本效益分析法（量化安全投入产出比，决策支持）
- 评估步骤：描述架构→识别质量属性→分析权衡点→风险点识别→形成决策
- 与其他方法对比：SAAM简单定性，ATAM全面定性，CBAM定量经济

## 案例分析题

**题目**：某银行计划建设新一代手机银行系统，需要满足以下业务与安全要求：
1. 支持远程办公人员通过互联网访问内部核心业务系统办理业务
2. 确保用户账户、资金交易数据在传输和存储过程中的机密性和完整性
3. 防止SQL注入、XSS跨站脚本、CSRF等常见Web攻击
4. 系统需要支持每月500万笔交易的高并发安全处理
5. 满足《网络安全法》《数据安全法》《个人信息保护法》以及等保2.0三级要求

请根据上述要求，回答以下问题：
（1）针对远程办公场景，应采用何种安全架构？为什么？
（2）针对Web应用常见攻击，应采用哪些纵深防御措施？
（3）为保证国产化合规性，应采用哪些国密算法？分别用于什么场景？

**参考答案**：

（1）针对远程办公场景，应采用零信任架构（Zero Trust Architecture）。
原因分析：
- 传统VPN模式默认内网可信，但远程办公环境下终端类型多样（个人PC、移动设备）、网络环境复杂（家庭WiFi、公共网络），内网边界模糊，传统边界防御失效
- 零信任架构以"永不信任，持续验证"为核心理念，对每次访问请求进行严格的身份认证、动态授权与最小权限控制
- 通过策略引擎PE（决策中心）、策略管理器PA（会话管理）、策略执行点PEP（执行拦截）三大组件协同工作，实现细粒度访问控制
- 支持基于设备状态、用户身份、网络环境、访问上下文的多因素动态授权（如设备健康度检查、行为分析）
- 满足金融行业监管合规要求（《个人金融信息保护试行办法》），降低远程访问导致的数据泄露风险

（2）针对Web应用常见攻击，应采取多层纵深防御措施：
- 网络层：部署Web应用防火墙WAF（含SQL注入、XSS、CSRF规则库）、DDoS防护设备、下一代防火墙NGFW
- 应用层：实施严格输入验证（白名单）、参数化查询（PreparedStatement）防SQL注入、输出编码防XSS、Anti-CSRF Token防跨站请求伪造
- 主机层：操作系统安全加固、最小化安装、及时补丁更新、HIDS主机入侵检测
- 数据层：敏感数据加密存储（密码加盐哈希）、数据库访问审计、SQL注入防护、字段级加密
- 监控层：部署SIEM安全信息与事件管理平台、UEBA用户行为分析、实时监测异常行为
- 业务层：交易限额控制、风险监控模型（反欺诈引擎）、设备指纹、生物识别、行为验证码

（3）为保证国产化合规，应采用以下国密算法：
- SM2：非对称加密算法（基于椭圆曲线ECC），用于密钥协商和数字签名，替代RSA。可用于用户身份认证、交易签名验签
- SM3：哈希算法（输出256位），用于数据完整性校验，替代SHA-256。可用于密码哈希存储、消息摘要
- SM4：对称加密算法（分组长度128位），用于数据加密传输和存储，替代AES。可用于会话密钥加密、敏感字段加密
- SM9：标识密码算法，基于用户身份（手机号、身份证号）生成密钥，替代传统PKI证书体系
- 构建完整国密PKI/CA体系，使用国密SSL证书（SM2_with_SM3）实现HTTPS传输加密，满足等保2.0和密评要求

**踩分要点**：
- 零信任必提"永不信任、持续验证"原则和三大组件PEP/PE/PA
- 纵深防御要点：七层防护、多样性、冗余性，至少答出WAF+输入验证+加密+审计四层
- 国密算法SM2/SM3/SM4职能必须答对（签名/哈希/对称）
- 关注合规性：等保2.0三级、商用密码应用安全性评估（密评）
- 远程办公场景必须否决传统VPN的"内网可信"假设

## 记忆口诀

零信任架构：永不信任持续验，三大组件PE/PA/PEP，最小权限微分段，动态授权多因素。

纵深防御：七层防护多重冗余，数据应用主机网络物理管用，多样叠加攻守兼备。

国密算法：SM2非对称签名，SM3哈希完整性，SM4对称加数据，合规替代RSA/SHA/AES，国产密评等保必备。

可信计算：TPM/TCM度量根，信任链传递逐级验，BIOS到App全度量，远程证明PCR证完整。

架构评估：SAAM场景简单方法，ATAM多属性权衡分析，CBAM成本效益量化，安全决策三步走。

安全合规：等保2.0三级是基础，密评商密应用必评估，数据安全法三同步（同步规划同步建设同步使用）。
