# 信息系统监理师 - 第52次学习（2026-09-08）

## 今日核心概念

### 1. 招投标阶段监理工作要点
定义：招投标阶段监理是监理单位受业主委托，对招标策划、招标文件编制、招标过程、评标、定标、合同签订全过程进行监督管理的工作，是信息系统监理师考试的高频考点。

关键要点：
- 招投标阶段监理四大任务：协助业主编制招标文件、参与评标、定标准备、协助合同谈判签订
- 招标方式三类型：公开招标（公开发布招标公告，不设资格预审）、邀请招标（向3家以上特定供应商发出邀请）、议标（直接谈判，单一来源）
- 招标适用条件：公开招标适用金额大、技术成熟、市场充分竞争项目；邀请招标适用技术复杂或特殊要求项目；议标适用独家生产或紧急项目
- 招标流程九步：招标备案→编制招标文件→发布招标公告/邀请书→资格预审→发售招标文件→踏勘现场→投标答疑→开标评标→定标签订合同
- 招标文件六大组成：投标邀请书、投标人须知、合同条款、投标文件格式、技术规格书、附件与附图
- 评标委员会组成：5人以上单数（一般5-7人），技术经济专家占2/3以上，业主代表不超过1/3，专家随机抽取
- 评标方法两类型：综合评估法（价格+技术+服务综合打分，分值权重公开）、最低评标价法（满足招标文件实质性要求且最低报价，推荐使用经评审的最低投标价法）
- 投标文件有效性检查：投标保证金（一般不超过项目估算价2%，最高80万）、投标文件密封、投标人资质、法定代表人签字盖章
- 监理在招投标阶段的作用：审查招标文件合规性（招标投标法+实施条例）、监督开标评标过程合规性、协助定标、提供专业咨询
- 招投标法核心原则：公开、公平、公正、诚实信用；禁止限制/排斥潜在投标人；禁止串通投标

### 2. 监理合同与合同管理
定义：监理合同是业主与监理单位之间明确监理范围、权利、义务、责任的协议；合同管理是监理对合同签订、履行、变更、终止全过程进行监督管理的工作。

关键要点：
- 监理合同三要素：监理范围（项目边界+监理工作内容）、监理期限（开工至竣工验收+质保期）、监理酬金（人月单价/总价/比例提成三种方式）
- 监理合同五大条款：词语定义、监理工作内容与依据、双方权利义务、违约责任、争议解决
- 监理合同 vs 施工合同区别：监理合同是委托服务合同（监理提供智力服务不产出实体），施工合同是承揽合同（承包商产出工程实体）
- 监理人法定权利：建议权（对工程建设的建议）、审批权（对承包商报审文件的审批）、签认权（对工程款支付凭证签认）、指令权（对施工单位的整改指令）、协调权（组织各方协调会议）
- 监理人核心义务：依法监理、独立公正、保守秘密、勤勉尽责、不得与承包商有利害关系
- 合同类型三族系：总价合同FFP/FP-EPA/FPIF（适用范围明确）、成本补偿合同CPFF/CPIF/CPAF/CPPC（适用范围不明确）、工料合同T&M（适用紧急小项目）
- 合同条款六件套：标的物、价款、履行期限/地点/方式、违约责任、争议解决方法、变更与解除条件
- 合同变更五步法：变更申请→变更评审（影响分析）→变更批准（CCB决策）→变更实施→变更验证（变更后验收）
- 合同违约处理：协商→调解→仲裁→诉讼四步走；诉讼时效3年（自知道或应当知道权利被侵害之日起）
- 合同争议解决四步：协商（首选，零成本）→调解（行业协会或第三方）→仲裁（终局，保密高效）→诉讼（终局，公开但耗时）
- 合同管理两大工具：合同清单（台账）+ 合同档案（原件+附件+变更记录+验收记录）
- 监理合同档案管理：合同原件保存≥10年；变更/补充协议、索赔报告、付款凭证归档可追溯

### 3. 信息系统工程质量控制
定义：质量控制是监理对信息系统工程质量进行监督检查、测试验证、问题整改的全过程管理，是"四控两管一协调"框架中的核心控制目标。

关键要点：
- 质量控制三过程：质量规划（制定质量标准）、质量保证QA（过程审计，监承建方是否按规范实施）、质量控制QC（产品检验，监理对成果物验收）
- QA vs QC 区别：QA是过程导向（关注过程是否合规），QC是产品导向（关注产品是否合格）；QA预防胜于检查，QC检查胜于无
- 质量控制老七工具：因果图（鱼骨图4M1E人机料法环）、流程图、核对单（Checklist）、帕累托图（80/20法则）、直方图、控制图（UCL/LCL=均值±3σ）、散点图
- 新七工具：亲和图、关联图、树状图、矩阵图、PDPC过程决策程序图、活动网络图、箭线图
- 质量控制关键控制点三类：W点（见证，需监理到场见证）、H点（停工待检，必须检验通过才能继续）、S点（旁站，全程监督关键工序）
- WHS三点设置原则：W点（一般工序见证）、H点（关键工序停工待检）、S点（隐蔽工程旁站）；监理规划中明确WHS点清单
- 质量验收四大阶段：分项工程验收（子模块）→分部工程验收（功能模块）→单位工程验收（子系统）→竣工验收（整体系统）
- 软件质量六大特性（ISO/IEC 25010）：功能性、可靠性、易用性、效率、可维护性、可移植性（+安全性）
- 信息系统工程质量验收三步：初步验收（试运行3-6个月）→竣工验收（最终验收）→质保期验收（质量问题整改）
- 软件测试四阶段：单元测试（开发者+白盒）→集成测试（接口测试）→系统测试（端到端）→验收测试（业主+用户）
- 测试覆盖率指标：语句覆盖（最低）、分支覆盖、条件覆盖、路径覆盖（最严）
- 缺陷严重等级：致命（系统崩溃/数据丢失）、严重（主要功能不可用）、一般（次要功能异常）、轻微（UI/文案）
- 缺陷生命周期：New→Assigned→Open→Fixed→Verified→Closed（或Reopen→再处理）
- DoD完成定义：代码评审通过 + 单元测试覆盖率≥70% + 接口测试通过 + UAT用户验收通过 + 部署到预发环境

### 4. 信息系统工程进度控制与投资控制
定义：进度控制是监理对工程实施进度进行计划审查、进度监控、纠偏的管理工作；投资控制是监理对项目资金使用、成本变化进行审核与控制的工作。

关键要点：
- 进度控制六大工具：横道图（甘特图）、里程碑图、网络图、CPM关键路径、PDM前导图法、挣值分析EVM
- 关键路径CPM：网络图中TF=0的活动链为关键路径，决定项目最短工期；可能多条关键路径
- 进度压缩两大方法：赶工Crash（加资源缩短工期，成本↑）、快速跟进Fast Tracking（并行执行，返工风险↑）
- 进度偏差分析：SV=EV-PV（<0滞后）、SPI=EV/PV（<1落后）；当SPI<0.9时需采取纠偏措施
- 进度计划审查：监理审查承建方进度计划合理性（活动定义、资源估算、工期估算、关键路径）
- 进度监控三步：进度数据采集（周报/月报）→进度偏差分析（SV/SPI）→进度纠偏措施（赶工/快速跟进/资源调整）
- 进度变更控制：重大进度变更需CCB评审，重新批准后实施
- 投资控制三阶段：事前控制（投资估算审查、资金计划）、事中控制（进度款审核、设计变更费审核）、事后控制（结算审核、决算审计）
- 投资控制四大工具：投资估算（可研阶段）、概算（初步设计阶段）、预算（施工图阶段）、决算（竣工验收阶段）；后一级控制前一级
- 工程款支付审核：监理审核承建方月度工程量完成情况 → 签认工程款支付凭证 → 业主按合同支付
- 工程款支付五条件：工程量经监理签认、质量验收合格、进度符合计划、变更手续齐全、发票合规
- 投资偏差分析：CV=EV-AC（<0超支）、CPI=EV/AC（<1超支）；当CPI<0.9时需采取纠偏措施
- 投资纠偏措施：价值工程分析（功能/成本优化）、限额设计（限额变更）、合同谈判（调整付款方式）、工程变更控制（避免不必要变更）
- 工程结算审核：合同价款+变更价款-预付款-保留金±索赔=结算价；保留金5%-10%（合同约定）

### 5. 信息系统工程变更控制与组织协调
定义：变更控制是监理对工程变更进行申请受理、影响分析、评审批准、实施监督的管理工作；组织协调是监理组织业主/承包商/监理三方及设备供应商/外协单位协同工作的能力体现。

关键要点：
- 变更控制五步法（CCB五步）：变更申请→影响分析→CCB评审（变更控制委员会集体决策）→变更实施→变更验证
- 变更影响五维度：进度影响（是否影响关键路径）、成本影响（是否超出预算）、范围影响（是否触及范围基准）、质量影响（是否引入技术债务）、风险影响（是否带来新风险）
- CCB变更控制委员会组成：业主代表（决策权）、监理代表（专业建议）、承建方代表（实施方）、设计方代表（设计变更）；必要时外部专家
- 变更分类管理：重大变更（影响范围/进度/成本>10%）、一般变更（影响范围/进度/成本≤10%）、紧急变更（P0/P1故障修复，24h内ECAB）
- 变更申请文件：变更请求CR（变更原因+影响范围+紧急程度+实施方案+预算估算+风险评估）
- 变更文档管理：所有变更记录留痕（CR编号+评审纪要+实施记录+验证报告），保存≥10年
- 监理协调三方关系：业主（建设方）↔ 承建方（承包商）↔ 监理方（第三方）；监理与业主是被委托与委托关系，与承建方是监理与被监理关系
- 三方关系核心：业主是项目所有者、监理是质量与进度监管者、承建方是项目实施者；监理独立于业主和承建方之外
- 监理协调会议三类：第一次工地会议（开工前，业主+承建商+监理三方见面）、工地例会（每周/双周例会）、专题协调会（针对特定问题）
- 第一次工地会议六项议程：宣布监理组织机构、宣布监理工作范围、监理规划交底、承建方施工组织设计审查、明确工作流程、确定会议制度
- 工地例会六要素：会议时间地点、参加人员、议题清单、上次会议纪要落实、本次会议议题、下次会议计划
- 专题协调会五类：技术方案协调会、设计变更协调会、进度纠偏协调会、质量问题协调会、索赔争议协调会
- 协调会议六原则：公正原则、独立原则、证据原则、书面原则、时效原则、边界原则（不超越监理权限）
- 协调工作方法：沟通（口头/书面/会议）、协商（求同存异达成共识）、调解（第三方斡旋）、指令（监理书面指令）
- 监理指令与通知三类：监理通知单（一般问题）、工作联系单（沟通事项）、停工令（严重违规）；停工令需24小时内书面报告业主

## 案例分析题

**题目**：
某省财政厅启动"金财工程"二期信息化建设项目，预算8000万元，工期18个月。业主单位为省财政厅信息中心，通过公开招标方式选择承建方，监理单位通过邀请招标方式确定。

招投标阶段：
1. 监理单位在投标文件中提出"按工程总投资的2.5%收取监理费"，业主接受但未写入合同；
2. 招标文件技术规格书中要求"数据库采用Oracle"，但未明确版本号；
3. 评标委员会7人中，业主代表3人（超1/3上限），技术经济专家4人；
4. 承建方A公司投标报价7200万（含150万"技术创新费"），承建方B公司报价6800万，承建方C公司报价7000万，承建方D公司弃标；
5. 评标委员会推荐B公司中标，业主认为报价过低存在风险，要求B公司提交履约担保1000万；
6. 监理合同约定监理费200万（按工程总投资2.5%），但业主要求监理单位承担"项目经理部分工作"。

施工阶段：
7. 承建方B公司项目经理因病离职3个月，新项目经理到岗后多次对设计方案提出异议，监理多次组织协调未果；
8. 第8个月承建方提出"业务需求变更"需增加投资180万，监理审查发现该变更属"范围蔓延"，未予批准；
9. 第10个月发现Oracle数据库存在性能瓶颈，承建方要求改用MySQL并额外申请120万改造费；
10. 项目延期3个月，超预算200万，最终扣除30%合同款作为违约金。

问题：
(1) 招投标阶段存在哪些违规或不当之处？请按招标投标法及实施条例逐项分析；
(2) 监理合同存在哪些问题？监理单位应如何应对"承担项目经理部分工作"的要求？
(3) 针对变更控制（事件8和9），监理的处理是否得当？请说明监理在变更控制中的权利与义务。

**参考答案**：

问题一：招投标阶段违规与不当分析

一、监理投标报价未写入合同（事件1）：
1. 违规性质：违反招标投标法"实质性条款必须写入合同"原则
2. 问题分析：监理费报价作为投标文件的实质性承诺，必须在合同中明确，否则视为未约定
3. 整改建议：补充签订监理费协议或合同补充协议，明确监理费计算方式、支付时间节点、税费承担；建议监理费2.5%符合行业标准（信息系统工程监理费一般为1.5%-3%）
4. 法律依据：《招标投标法》第46条"招标人和中标人应当自中标通知书发出之日起三十日内，按照招标文件和中标人的投标文件订立书面合同"，实质性条款必须一致

二、招标文件技术规格不明确（事件2）：
1. 违规性质：违反招标投标法实施条例"招标文件应当明确招标项目的技术要求"
2. 问题分析：仅写"Oracle"未明确版本（如Oracle 19c/21c），评标时易产生争议，且影响后续合同执行
3. 整改建议：废标重招或在合同签订前明确技术规格；避免后续纠纷
4. 法律依据：《招标投标法》第19条"招标人应当根据招标项目的特点和需要编制招标文件"，招标文件应当完整、准确

三、评标委员会组成违规（事件3）：
1. 违规性质：违反招标投标法"评标委员会专家不得少于成员总数的三分之二"
2. 问题分析：评标委员会7人中技术经济专家应≥5人（2/3×7=4.67向上取整），实际仅4人，业主代表3人超1/3上限（≤2人）
3. 整改建议：重新组建评标委员会，技术经济专家≥5人，业主代表≤2人；已评标的需作废重评
4. 法律依据：《招标投标法》第37条"评标委员会由招标人的代表和有关技术、经济等方面的专家组成，成员人数为五人以上单数，其中技术、经济等方面的专家不得少于成员总数的三分之二"

四、技术创新费违规（事件4）：
1. 违规性质：违反招标投标法"投标人不得以低于成本的报价竞标"
2. 问题分析："技术创新费"150万无明确技术对应内容，可能被认定为"低于成本竞标"或"虚假投标"
3. 判定原则：评标委员会应审查技术创新费的具体内容与价值合理性；如无法对应实际技术投入，可判定为无效报价
4. 法律依据：《招标投标法实施条例》第51条"有下列情形之一的，评标委员会应当否决其投标：……（五）投标报价低于成本或者高于招标文件设定的最高投标限价"

五、业主强加履约担保（事件5）：
1. 违规性质：违反招标投标法"不得擅自改变中标人"
2. 问题分析：评标委员会已推荐B公司中标，业主"因报价过低"要求B公司提交1000万履约担保属于"变相拒绝中标人"
3. 整改建议：
   - 业主应基于合同实质性条款与B公司谈判
   - 履约担保金额应在招标文件中明确（一般不超过合同价10%），不应在定标后单方变更
   - 若B公司接受且未违反法律规定，可签订补充协议明确
4. 法律依据：《招标投标法实施条例》第57条"招标人和中标人应当依照招标投标法和本条例的规定签订书面合同，合同的标的、价款、质量、履行期限等主要条款应当与招标文件和中标人的投标文件的内容一致"

六、评标方法与定标程序：
1. 本案例采用综合评估法（推荐最低评标价法），未明确评分权重与分值计算
2. 业主认为B公司报价过低存在风险，应在评标阶段由评标委员会评审，而非在定标后要求额外担保
3. 评标报告应包含详细评审理由，业主应尊重评标委员会的专业判断

问题二：监理合同问题与应对

一、监理合同存在问题：
1. 监理费约定不清：
   - 合同约定200万按总投资2.5%，但总投资额可能因工程变更而变化（最终超支200万，总投资变为8200万，监理费应调整为205万）
   - 监理费支付节点与支付条件不明确（按月/按季/按里程碑/按工程进度比例）
2. 监理工作范围扩大：
   - 业主要求监理承担"项目经理部分工作"，实质上将监理职责与项目管理职责混淆
   - 监理是第三方监督角色，不是业主的项目管理执行者
3. 监理期限不明确：
   - 合同未明确质保期监理服务是否包含在监理期内（一般信息系统项目有1-3年质保期）
4. 违约责任不对等：
   - 业主违约责任（拖欠监理费等）与监理违约责任（监理失职等）不对等

二、监理单位应对策略：
1. 拒绝超越监理职责的工作：
   - 书面回复业主，明确监理与项目管理的区别
   - 监理职责：四控两管一协调（质量/进度/投资/变更/合同/信息/协调）
   - 项目经理职责：整合管理、范围/进度/成本/质量/资源/沟通/风险/采购/干系人九大领域
   - 监理可协助但不承担项目经理工作
2. 签订补充协议：
   - 如业主确需监理承担额外工作，必须签订补充协议
   - 补充协议明确额外工作内容、酬金、期限、违约责任
   - 监理酬金按人月单价或工作量另计
3. 监理费调整：
   - 因工程变更导致总投资增加，应按比例调整监理费
   - 签订监理费调整补充协议
4. 合同档案管理：
   - 监理合同原件、补充协议、变更记录统一归档
   - 合同台账动态更新（含金额、节点、状态）
5. 保留书面证据：
   - 业主口头要求应通过书面方式确认
   - 重要事项必须书面沟通（监理通知单、工作联系单）
   - 防止后期纠纷举证困难

三、监理合同争议解决：
1. 协商优先：与业主平等协商，达成补充协议
2. 调解：申请行业协会或第三方调解
3. 仲裁：按合同约定仲裁机构（如约定不明，可事后补充约定）
4. 诉讼：仲裁/诉讼时效3年（自知道或应当知道权利被侵害之日起）

问题三：变更控制分析（事件8和9）

一、事件8（业务需求变更180万）监理处理分析：
1. 监理处理：审查发现属"范围蔓延"，未予批准 → 处理得当
2. 合法性分析：
   - 业务需求变更属"必要性"变更，但承建方未提供充分的变更影响分析
   - 监理审查范围变更是否符合原合同范围，识别是否触及范围基准
   - 监理有权拒绝未经CCB批准的不合理变更
3. 监理应补充动作：
   - 要求承建方补充变更申请文件（CR）：变更原因+影响范围+预算估算+实施方案+风险评估
   - 组织CCB评审（业主代表+监理+承建方+设计方）
   - 评审通过后签订变更协议；评审不通过则书面说明理由
   - 即使CCB批准，监理应督促承建方严格控制变更实施，避免范围蔓延

二、事件9（数据库更换MySQL+120万）监理处理分析：
1. 监理处理：未明确，建议补充分析
2. 合法性分析：
   - Oracle→MySQL属于重大技术变更，需深入评估
   - 变更原因：性能瓶颈（需提供性能测试数据证明Oracle确实存在瓶颈）
   - 变更合理性：MySQL作为开源数据库可能降低成本，但需评估兼容性、性能、功能完整性
   - 变更预算：120万改造费合理性评估（开发改造+测试+部署+数据迁移+培训）
3. 监理应做的全面评估：
   - 技术评估：MySQL与Oracle兼容性（SQL语法、数据类型、事务、存储过程）、性能对比、功能对比（高可用/灾备/安全）
   - 业务影响：业务系统对数据库特性的依赖（高级SQL、触发器、存储过程、并行查询）
   - 成本评估：120万改造费合理性（开发+测试+数据迁移+培训+风险成本）
   - 风险评估：迁移风险（数据丢失、业务中断、性能不达标）
   - CCB评审：技术、财务、业务、法务四方评估
4. 监理建议处理方案：
   - 方案一（推荐）：Oracle优化（升级版本如Oracle 19c/21c + 索引优化 + SQL调优 + 读写分离），可能仅需50万
   - 方案二：MySQL改造（充分评估后实施），120万
   - 方案三：Oracle许可谈判（与Oracle谈判更优惠的许可条款），可能节省成本
   - 监理应建议业主优先选择方案一（成本最低、风险最小），方案二作为备选
5. 监理权利：
   - 审查变更技术合理性
   - 审查变更预算合理性
   - 评估变更风险
   - 提出变更方案建议
   - 签认变更实施记录
6. 监理义务：
   - 公正独立，不偏袒任何一方
   - 严格按变更控制流程办理（CCB五步法）
   - 书面留痕（变更申请/评审纪要/实施记录/验证报告）
   - 重要变更及时报告业主和上级主管部门

三、变更控制中的监理权利与义务总结：
1. 监理在变更控制中的法定权利：
   - 建议权：对变更方案提出专业建议
   - 审查权：审查变更申请、变更预算、变更风险
   - 签认权：签认变更实施记录、工程款支付
   - 报告权：向业主和上级主管部门报告重大变更
   - 协调权：组织CCB评审会议
2. 监理在变更控制中的法定义务：
   - 公正独立（不与承包商有利害关系）
   - 勤勉尽责（及时处理变更申请）
   - 保守秘密（不泄露业主与承建方商业秘密）
   - 严格程序（按CCB五步法办理变更）
   - 书面留痕（所有变更必须书面记录）
3. 监理越权与失职情形：
   - 越权：监理擅自批准变更（应经CCB评审）
   - 失职：监理未及时处理变更申请、隐瞒变更风险、变更后未监督实施

**踩分要点**：
- 问题一必须按招标投标法及实施条例逐项分析6个事件，每项明确：违规性质+法律依据+整改建议；关键法规：第19/37/46条、《实施条例》第51/57条；关键数字：评标专家2/3、履约担保≤10%、监理费1.5%-3%、合同签订30天
