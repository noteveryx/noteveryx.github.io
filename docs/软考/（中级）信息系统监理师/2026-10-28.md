# （中级）信息系统监理师 · 第70次学习（2026-10-28）

**主题**：监理实施阶段的质量、进度与投资控制实务 —— 旁站巡视平行检验、见证与验收、计量支付、工程计量与变更计价

---

## 今日核心概念

### 1. 监理实施阶段的职责定位

定义：监理实施阶段是监理单位依据监理合同与监理规划，对承建单位的建设行为实施质量、进度、投资、合同、信息、安全六大控制的阶段。

关键要点：
- **"六控两管一协调"**：
  - **六控**：质量控制、进度控制、投资控制、合同控制、信息控制、安全控制
  - **两管**：信息管理（文档）与档案管理
  - **一协调**：协调建设、承建、供货等单位的关系
- **监理的三条底线**：
  1. **不代替承建单位实施**——监理是第三方，不是施工方
  2. **不代替建设单位决策**——重大事项由建设单位拍板
  3. **不损害建设单位的合法权益**——这是《信息系统工程监理规范》的核心原则
- **监理的"见证"与"审批"是两种不同性质的行为**：
  - **见证**：监理人员到现场观察关键工序或测试过程，签字确认"我看到了"
  - **审批**：监理单位对承建单位提交的方案、变更、付款申请作出是否同意的书面决定
  - **见证是事实确认，审批是意思表示**。混淆二者会导致责任边界不清
- **总监负责制**：总监是监理单位对外的唯一授权代表，重大事项必须由总监签署，一般监理人员无权对外作出决定

### 2. 质量控制的核心方法

定义：质量控制是监理单位为确保工程质量达到合同与规范要求，所采取的监控、测量、检查、纠正与验证活动。

关键要点：
- **三检制**：自检（承建单位内部）、互检（承建单位班组间）、专检（监理单位独立检验）。**监理的专检不可省略，也不可替代承建单位的自检**
- **三种基本检验方法**：
  1. **旁站（Standing Inspection / On-Site Observation）**：监理人员在关键工序施工或测试**全过程在场观察**。适用于：数据库迁移、数据割接、性能压测、核心功能上线切换、密码配置、权限初始化
     - 旁站记录必须包含：工序名称、部位、时间、实测数据、发现问题、处理意见、旁站人员签字
     - **旁站不等于监理"监工"**，监理不代替承建单位操作
  2. **巡视（Patrol Inspection / Patrol）**：监理人员对现场作业进行**定期或不定期的巡查**，覆盖面广、频次高，属于面上的检查
     - 巡视记录应写明检查部位、检查内容、发现问题、整改要求
     - **巡视发现问题应签发监理通知单**，并跟踪整改闭环
  3. **平行检验（Parallel Inspection / Parallel Test）**：监理单位**独立抽样并检测**，与承建单位的检验结果比对
     - 平行检验常用于：软件代码质量抽检、性能指标测试、配置一致性核查、文档完整性核查
     - **平行检验是监理发现"报喜不报忧"的关键手段**
- **质量控制的三个关键环节**：
  1. **事前控制**——审查承建单位的质量计划、作业指导书、测试方案、人员资质；**审查不通过不得开工**
  2. **事中控制**——旁站、巡视、平行检验、见证取样；**发现问题即时纠正**
  3. **事后控制**——验收、缺陷跟踪、质量统计分析、经验总结
- **软件工程项目的特殊性**：不可返工的部分（已上线的功能）、难以用"检验"发现问题（缺陷常常在运行期才暴露）、缺陷发现成本随阶段指数上升。**因此软件项目的质量控制更依赖过程评审与文档审查，而非末端检验**
- **质量事故与质量缺陷的区分**：
  - **质量缺陷**：不影响正常使用，可局部返修
  - **质量问题**：影响部分功能或性能，需返工并影响进度
  - **质量事故**：造成系统不可用、数据丢失、重大安全风险，需停工整改并追究责任
- **不合格品的处置流程**：标识 → 记录 → 隔离 → 处置决定（返工/返修/让步接收/报废）→ 处置执行 → 验证 → 关闭

### 3. 见证取样与工程计量

定义：见证取样是监理单位对承建单位使用的材料、构配件、设备进行现场见证与抽样的活动；工程计量是监理单位确认承建单位实际完成的工程量，作为支付依据的活动。

关键要点：
- **见证取样的三个环节**：
  1. **见证（Witness）**——监理人员在取样现场观察取样全过程并签字
  2. **取样（Sampling）**——按规范规定的抽样比例与方法取样
  3. **送检（Submission）**——样品送有资质的检测机构检验
- **见证取样的规则**：
  - **取样见证人员不得少于两人**
  - **见证取样必须由承建单位提前（一般 24-48 小时）书面通知监理单位**，监理单位未按时到场，**该次取样无效，可重新取样**
  - 监理人员在见证记录上签字，**注明取样部位、数量、日期、见证情况**
  - **对有争议的样品可要求封样留存**，作为争议时的仲裁依据
- **工程计量的三种类型**：
  1. **按实计量（实测实量）**——实际完成量经测量确定
  2. **按图计量**——按施工图计算
  3. **按工日/台班计量**——适用于服务型、人力型工作
- **计量支付的三条铁律**：
  1. **没有经过验收合格的工作，不能计量支付**
  2. **没有经过监理工程师签认的计量，单方面声明的工程量无效**
  3. **计量必须与合同约定的计量方法和支付节点对应**
- **支付节点的常见设置**：预付款（不超过合同额的 30%）、到货款、进度款、验收款、质保金（一般 3%-5%）
- **进度款支付的前提条件**：
  - 已完成的工程量经监理计量确认
  - 质量验收合格
  - 提交完整的付款申请与证明材料
  - **累计支付不超过已完工程量的一定比例**（避免超付）
- **超付风险控制**：
  - 严格按计量结果支付，**不做"预估支付"**
  - 设置累计支付上限控制
  - 质保金留存
  - 承建单位出现资金链断裂风险时，及时向建设单位预警

### 4. 投资（造价）控制与变更计价

定义：投资控制是指监理单位依据合同约定，对工程造价的形成进行全过程控制，防止投资超支。

关键要点：
- **投资控制的核心是"事前、事中、事后"三道防线**：
  - **事前**：图纸会审、清单核对、单价分析、概算审查——**这一道防线决定 80% 的效果**
  - **事中**：计量支付、变更计价、索赔审核、材料价格审核
  - **事后**：竣工结算审核、决算对比分析
- **工程变更的分类**（不同分类标准）：
  - 按变更内容：设计变更、施工变更、进度变更、条件变更、政策变更
  - 按责任归属：承包方原因变更、发包方原因变更、不可抗力变更、第三人原因变更
  - **投资控制的核心关注点**：**变更的计价原则由责任归属决定**
- **变更价款的确定原则（按顺序）**：
  1. **合同中有适用价格，按合同已有价格**计算
  2. **合同中有类似价格，参照类似价格**计算
  3. **合同中无适用或类似价格，由承包方提出适当的变更价格，经工程师确认后执行**
- **变更估价的原则**：
  - **对已有工程量清单中已有的项目**，按已有单价执行（通常不因变更而调整）
  - **对清单中有类似项目的**，参照类似单价调整
  - **对清单中无此项目的**，按成本加合理利润重新组价，需双方确认
  - **工程量清单漏项或设计变更引起的新增项目**，其单价需按合同约定的组价方法重新确定
- **变更估价的常见争议点**：
  1. **单价是否可调**——合同约定"固定总价"时，非发包方原因的变更一般不予调价（除非合同另有约定）
  2. **工程量增减是否超过约定幅度**——合同常约定清单工程量偏差超过 ±15%（或 ±10%）时超出部分调整单价
  3. **新增项目的组价依据**——是否套用定额、取费标准如何确定
  4. **赶工费用的承担**——发包方要求赶工属"发包方原因"，费用应予补偿；承包方自身延误导致的赶工，费用不予补偿
- **暂列金额与暂估价的处理**：
  - **暂列金额**（Standing Sum）：招标文件中列明但未确定的金额，**由发包人掌握使用**，未使用部分不支付
  - **暂估价**（Provisional Sum / Prime Cost Sum）：招标文件中列明但未确定的单价或金额，**签约后按合同约定的方式确定**，常见的调整方式有按实结算、按总价调整
  - **二者区别**：暂列金额是"钱"（总额），暂估价是"价"（单价）
- **索赔与反索赔**：
  - **索赔的成立条件**：非对方责任、实际损失、因果关系、时效内提出
  - **索赔的时限约定**：工程实践中常约定"索赔通知在事件发生后 28 天内提出，逾期视为放弃"（《建设工程施工合同（示范文本）》的通用约定）
  - **监理对索赔的立场**：**既不偏袒承建单位，也不偏袒建设单位**，以合同为依据、以事实为证据
- **投资控制的常见失效原因**：
  1. **重结算、轻过程**——把投资控制寄托在竣工结算审核上，此时投资已既成事实
  2. **不熟悉合同计价条款**——变更单、暂列金额、索赔的条款没读透
  3. **现场签证管理不严**——签证不及时、不规范，成为结算争议的主要来源
  4. **不掌握材料设备市场价格**——调价时无据可依

### 5. 进度控制的监理视角

定义：进度控制是监理单位依据批准的进度计划，监督承建单位实际进展，并对偏差进行分析与纠偏的活动。

关键要点：
- **进度控制的三个依据**：
  1. **合同约定的工期**（总工期与节点工期）
  2. **经批准的施工组织设计 / 项目进度计划**
  3. **经批准的进度调整计划**
- **进度控制的监理动作**：
  1. **审批进度计划**——审查其合理性与可行性（资源配置、逻辑关系、工期与合同的一致性）
  2. **检查实际进展**——通过例会、周报、监理日志、现场检查掌握实况
  3. **分析偏差**——偏差 = 计划工期 - 实际工期（正为超前，负为滞后）
  4. **签发监理指令**——对严重偏差要求承建单位提交纠偏方案
  5. **跟踪纠偏落实**——闭环验证
- **总工期与节点工期的区分**：
  - 总工期逾期可能构成**违约**，需承担违约责任
  - 节点工期逾期通常不直接构成违约，但可能影响下一阶段并产生连锁影响
  - **监理应分别记录与报告**，不能混为一谈
- **工期索赔与工期延误的处理**：
  - **工期索赔成立的条件**：非承建单位责任、事件确实影响工期、**有因果关系证明**、在索赔时限内提出
  - **"工期延误不等于工期索赔"**：承建单位自身原因导致的延误是违约，应承担违约责任而非索赔
- **进度控制与投资控制的联动**：
  - **赶工通常伴随费用增加**——监理在签发赶工指令前，应提示建设单位评估赶工成本并走变更程序
  - **拖延也会产生费用**——监理应客观记录延误事实与原因，避免建设单位事后主张时缺乏证据
- **监理例会与监理日志**：
  - **监理例会**：定期召开（通常每周一次），承建单位、建设单位、其他相关单位参加，**是进度控制的主战场**
  - **监理日志**：**监理工作的原始记录，是工程索赔与争议处理的关键证据**，须如实、及时、连续记录，不可事后补记或涂改

### 6. 合同管理与监理的证据意识

定义：合同管理是监理单位依据合同文件对履约过程进行监督、控制与协调的活动。证据意识是监理工作的方法论基础。

关键要点：
- **监理工作的成果最终体现为"文件"**。监理的一切结论都必须有书面依据：
  - 监理通知单、监理工作联系单、监理指令、监理报告、旁站记录、巡视记录、平行检验记录、会议纪要、监理日志
- **文件的三个基本要求**：**及时、准确、规范**
  - **及时**——超过合同约定的时限，文件效力大打折扣（如索赔的 28 天时效）
  - **准确**——事实清楚、依据明确、结论明确
  - **规范**——格式统一、签署齐全、用语严谨
- **"监理通知单"的效力与边界**：
  - **可以**要求承建单位整改、限期整改、必要时暂停施工
  - **不可以**直接下达停工令（除非合同另有约定或征得建设单位书面同意）——**监理有"建议权"与"指令权"的分界**
  - **不可以**替代建设单位作出重大决策（如解除合同、大额索赔认定）
  - **不可以**指挥承建单位的具体施工操作
- **监理与"责任"的边界（高频考点）**：
  - 监理对工程质量承担**监理责任**，但**不承担施工单位的质量责任**
  - 监理履行了监理职责而工程仍出现质量问题的，监理一般不承担质量责任
  - 监理**未履行监理职责**（如对明显缺陷未提出、未制止、未报告）的，**应承担相应责任**
  - **监理签认不免除承建单位的责任**——签认"合格"是对当时状态的确认，若后续发现承建单位造假，签认人仍需承担相应责任（这是实务中最易被忽视的一点）
- **"签字"的四种类型及其法律含义**：
  1. **签认（确认）**——确认事实成立
  2. **审批（同意）**——对方案或申请作出是否同意的决定
  3. **签证（确认费用或工期）**——对费用或工期的确认，可能构成放弃权利的效力
  4. **见证（证明过程）**——证明某过程发生
  - **核心区别：签认只证明"事实"，不改变合同责任；签证则可能构成对权利的处分**
  - **"只签事实不签结论"**是监理签认的重要原则：签字栏只写"经现场核查，所签认的工程量与现场情况一致"，不写"同意支付"这类结论性表述（支付与否由建设单位按合同约定决定）

### 7. 缺陷跟踪与验收的闭环管理

定义：缺陷跟踪是对检查中发现的问题进行记录、分派、验证修复与关闭的全过程管理；验收是确认建设成果达到合同要求的最终确认活动。

关键要点：
- **缺陷跟踪的闭环五步**：记录（登记编号、部位、描述、严重级别）→ 分派（明确责任人与整改期限）→ 整改 → 验证（复检或旁站确认）→ 关闭（留痕归档）
- **缺陷的严重级别与处置时限**（示例约定）：
  | 级别 | 定义 | 处置时限 |
  |---|---|---|
  | 致命（A） | 系统不可用、数据丢失或严重错误、安全漏洞 | 立即停工整改，24 小时内闭环 |
  | 严重（B） | 核心功能不可用、重大性能不达标 | 48 小时内闭环 |
  | 一般（C） | 次要功能异常、有替代方案 | 5 个工作日内 |
  | 提示（D） | 体验问题、规范偏差 | 纳入版本计划 |
- **阶段验收与初步验收、最终验收**：
  - **阶段验收（分阶段验收）**：针对可独立使用的阶段成果（如"数据接入模块上线"），**是及时支付进度款和控制风险的关键**
  - **初步验收**：全部系统建成后的初步检验，暴露问题供整改
  - **最终验收（竣工验收）**：整改完成后的最终确认，是支付尾款与启动质保的前提
- **验收的四个层次**：**文档验收、功能验收、性能验收、安全验收**
  - 文档验收常被忽视，但**文档是运维的基础**，缺失文档等于交付不完整
- **验收遗留问题的处理**：
  - **不影响使用的一般问题（C/D 级）**：可先验收通过，列入遗留问题清单，明确整改期限并**从质保金中预留相应金额**
  - **影响主要功能的问题（B 级及以上）**：不得通过验收，须整改后重新验收
- **"带病验收"的风险控制**：
  - 遗留问题必须**形成清单**，逐项明确责任单位、责任人、整改期限、验收确认人
  - **预留质保金**覆盖整改成本（一般不留少于合同价的 3%-5%）
  - **设置整改验收的时限**（如验收后 30 日内完成），逾期由建设单位组织代为处理并从质保金中扣除
  - **质保期与运维服务衔接**——验收通过后进入质保期，质保期与运维合同期需明确衔接

## 三个常考陷阱

### 陷阱一：认为"监理签认合格，就不承担质量责任了"

**错误表述**：监理工程师在验收单上签了"合格"，若工程后来出现质量问题，监理已尽到责任，不应承担责任。

**为什么错**：这是对监理责任边界的典型误解。关键在于**"签认的性质"与"签认时的事实基础"**：
1. **签认是对"当时状态"的确认**——监理签认的是"在验收时点、在监理见证的范围内、依据可核实的证据，该部分符合要求"。它不是对"未来永不发生问题"的担保
2. **签认不能免除承建单位的质量责任**——工程质量的最终责任主体永远是承建单位
3. **但监理也不能绝对免责**——如果存在以下情形，监理仍需承担相应责任：
   - 监理未履行监理职责（如对承建单位的造假行为未察觉、未提出异议、未报告）
   - 监理在明知存在缺陷的情况下仍签认合格
   - 监理的签认本身缺乏依据（如未实际核查即签字、事后补签）
4. **反之，监理履行了职责而工程仍出问题的**（如承建单位偷换材料、伪造记录），监理一般不承担质量责任

**正确表述**：**监理签认不免除承建单位责任，也不当然免除监理责任。**判断监理是否担责，关键看三点：**是否履行了监理职责、签认是否有依据、发现异常是否及时提出并报告**。监理的免责基础是"程序完整、履职到位、记录清晰"，而非"签过字"。

### 陷阱二：把"见证取样"与"平行检验"混为一谈

**错误表述**：监理人员到现场对材料取样进行见证，就是平行检验。

**为什么错**：两者的**独立性、目的、时机、责任后果**完全不同：

| 维度 | 见证取样 | 平行检验 |
|---|---|---|
| 对象 | 材料、构配件、设备 | 已完成的工程实体或作业成果 |
| 目的 | 确认取样过程合规、样品真实 | 独立获取检验数据，与承建单位结果比对 |
| 抽样方 | 承建单位取样，监理见证 | 监理独立抽样（可委托检测机构） |
| 责任后果 | 取样无效会导致检测结果失去效力 | 可发现承建单位检测造假或数据不实 |

典型的混淆表现：监理在材料进场时"见证取样"，认为已完成对该批材料的质量控制，因而在**平行检验环节省掉了对实体的独立检测**。这样一旦承建单位在施工过程中偷换材料、以次充好，监理就完全无从发现。**见证取样管的是"源头"，平行检验管的是"结果"，两者不可互相替代。**

**正确表述**：**见证取样保证"样品是真实的"，平行检验保证"结果是可信的"**。二者应并行开展，构成质量证据链的完整环节。

### 陷阱三：认为"监理可以直接下停工令"

**错误表述**：监理发现有严重质量问题，有权直接签发停工令，承建单位必须执行。

**为什么错**：监理的权限来自**监理合同的授权**，不同合同授权不同，但有基本边界：
1. **在监理合同明确授权的情况下**，监理可以签发工程暂停令。信息系统工程监理合同中通常约定"总监有权签发暂停令"
2. **在未明确授权时**，监理应当**及时向建设单位报告，由建设单位作出决定**，并可采取"先发监理通知单要求立即停止相关作业、限期整改"的过渡措施
3. **无论何种情况**，监理都**无权直接指挥承建单位的施工操作**——那既越权，也可能导致质量责任倒挂
4. **建设单位本身的合同义务也不能被监理替代**——监理签发停工令造成工期延误与费用增加的，相应责任由建设单位承担（对承建单位而言）

**正确表述**：监理对工程进度的控制权是**"建议权"与有限"指令权"的组合**。发现必须立即停工的重大质量问题时，正确做法是：**立即签发监理通知单要求停止相关作业 → 书面报告建设单位 → 由建设单位或按授权由总监签发暂停令 → 同步启动索赔与工期影响的评估**。同时注意：**签发暂停令后必须同时处理由此产生的工期与费用后果**，否则将成为新的争议点。

## 案例分析题

### 案例 1 — 某市政务一体化平台的监理争议

**背景材料**

某市建设"政务服务一体化平台"，建设单位委托某监理单位实施全过程监理。合同工期 14 个月，监理服务费 68 万元，采用固定总价合同。承建单位为某系统集成公司。

**项目实施情况**

**第一阶段（第 1-4 个月）— 设计与开发**

建设单位要求承建单位在第 4 个月底完成核心功能开发并进入内部测试。设计阶段完成后，承建单位提交了详细设计文档与开发计划，监理审查意见为"原则同意，补充完善后实施"。

第 3 个月，承建单位提出：因建设单位新增了"跨部门联合审批"与"电子证照库"两个功能模块，要求调整工期 25 天。监理审查后出具监理意见，认定为**建设单位原因引起的变更**，同意工期顺延 20 天（因承建单位原计划中对该功能有预留，可压缩 5 天）。建设单位在监理报告发出后 5 日内未提出异议。

**问题一（内部测试阶段）**：承建单位进行核心功能压力测试，测试报告中性能指标全部达标。监理人员**未到测试现场进行平行检验**，仅审阅了测试报告与截图。承建单位测试报告的原始数据由承建单位自行生成，测试工具为承建单位自行开发。

**问题二（测试阶段）**：承建单位在测试环境部署的数据库版本与生产环境不一致，且**未在方案中说明该差异**。测试通过后部署到生产环境时，出现数据字段长度不兼容，导致数据迁移失败，回退耗时 6 小时。

**问题三（上线阶段）**：上线前，承建单位报送了《数据库迁移旁站记录》，记录显示监理人员到场见证。建设单位在检查时发现：
- 旁站记录上监理人员签字为**打印体签名**，非手写
- 旁站记录填写的迁移时间为 **22:40 至 23:55**，但旁站记录表的备注栏注明"**旁站人员当日 18:00 已下班**"
- 旁站记录表编号为 **JS-2026-038**，但监理单位同期旁站记录编号为 **JS-2026-031 至 JS-2026-037**，**038 号编号不存在**

**问题四（进度）**：第 9 个月，承建单位报送 8 月度进度报表显示完成 85%。监理核对发现，核心功能模块实际仅完成 60%，但**非核心功能（统计分析、报表导出）反而超额完成至 120%**。监理指出后，承建单位项目经理解释："核心功能遇到技术难点，统计分析是顺手做的，先把能做的做了。"

**问题五（变更与签证）**：施工过程中，建设单位要求新增"一件事一次办"跨部门协同模块，承建单位提交变更报价 86 万元。合同约定该部分"按实结算"。监理审查发现：
- 承建单位报价中包含 12 万元"接口联调费"，但合同中接口联调工作已包含在原接口开发范围内，**不应重复计取**
- 承建单位提出的新增模块工期为 30 天，监理测算按其实际投入应为 22 天
- 承建单位要求**先行开工再补办变更手续**，理由是"建设单位着急用"

**问题六（付款）**：建设单位按承建单位的付款申请，已累计支付合同价的 88%。监理核查发现，其中第 7 个月的进度款支付**对应的计量工程量未在系统中实际完成**；此外，承建单位在第 6 个月提出的**材料设备涨价索赔**（涉及 32 万元），监理尚未完成审核即由建设单位支付了 60%。

**问题七（验收与文档）**：初步验收前，监理检查交付文档，发现缺少：数据库设计说明书、接口联调测试报告、运维手册、源代码交付清单。承建单位称"这些文档在内部有，验收后可以补"。

**建设单位与监理单位的争议焦点**

建设单位项目负责人提出四点意见：
1. "压力测试监理没到场，说明监理没尽到职责，压测报告不可信"
2. "旁站记录签字造假，监理单位涉嫌造假，必须严肃处理"
3. "承建单位把核心功能拖到最后，影响整体上线，要求监理认定工期违约"
4. "合同才 68 万监理费，监理单位连旁站记录都编不出来，这 68 万花得值吗？"

---

### 问题 1 — 分析该项目中反映出的监理工作缺陷

**参考答案：**

**一、针对"问题一：平行检验缺位"**

**缺陷定性**：监理对核心功能压力测试**未实施平行检验**，这是质量控制环节的实质性缺失。

**具体表现与后果**：
1. 监理仅"审阅报告与截图"，未获取第一手检验数据
2. **测试数据由承建单位自行生成、测试工具由承建单位自行开发**——这意味着测试结果缺乏独立性与可验证性，承建单位存在修改数据以通过测试的动机与空间
3. 对核心系统的性能指标（并发量、响应时间、吞吐量、错误率）而言，**压测是唯一有效的验证手段**，因为这些指标无法通过静态审查得出

**违反的规范要求**：
- 信息系统工程监理规范要求监理单位对关键工序、关键测试实施旁站或平行检验
- 软件工程的质量特性中，**性能是非功能属性，只能通过实测获得**，不存在"审阅报告即可确认"的情形

**正确做法**：
- 对核心功能压测实施**平行检验**：监理独立组织或委托第三方测试机构，使用**监理方认可的测试工具与测试数据集**，独立出具测试结论
- 重点验证：并发用户数下的 P95/P99 响应时间、吞吐量、错误率曲线、长时间稳定性（是否内存泄漏、连接池耗尽）
- 测试环境与生产环境的配置差异需**书面核对**（对应问题二，这正是平行检验能提前发现的问题）
- 承建单位自测报告只能作为**参考材料**，不能作为验收依据

**建设单位的意见评价**：意见一**成立**。监理未实施平行检验，是"该做的没做"，属职责缺失。

---

**二、针对"问题三：旁站记录签字造假"**

**这是本案最严重的缺陷，必须分四个层次定性。**

**第一层：事实认定**

三处矛盾形成完整的证据链：
1. **打印体签名**——正常手写签名笔迹有书写特征，打印体签名属于事后代签
2. **时间矛盾**——记录填 22:40 至 23:55，但备注栏注明旁站人员当日 18:00 已下班，**旁站人员根本不在场**
3. **编号断裂**——JS-2026-038 在监理同期记录中不存在（只有 031 至 037），**该记录是凭空编造的**

**第二层：性质认定**

三项事实相互印证，构成"**伪造监理记录**"，而非简单的记录填写不实：
- 时间矛盾证明**人未到现场**
- 编号不存在证明**记录未真实发生**
- 打印签名证明**非现场签署**

**核心判断**：这不是"记录没写好"，而是**记录本身是编造的**，即根本没有旁站这件事。

**第三层：法律与职业后果**
1. 监理单位涉嫌**伪造资料、虚假监理**，违反《建设工程质量管理条例》《信息系统工程监理规范》
2. 监理人员个人可能面临**职业资格处理**，严重的可能承担法律责任
3. 建设单位据此支付的**进度款、验收款可能存在被追回的风险**（因监理签认是其付款依据之一）
4. 若因此导致工程质量问题或事故，监理单位**免责事由消灭**

**第四层：根本原因分析（这才是整改的关键）**

旁站记录造假的成因通常不是单个监理人员的主观恶意，而是**监理管理机制失效**：
1. **旁站计划缺失**——未编制旁站方案明确哪些工序需要旁站、由谁旁站、提前多久通知
2. **旁站记录事后补签**——未要求旁站记录**现场即时手写、即时签字**，给事后编造留下空间
3. **监理单位内部无人复核**——监理日志、旁站记录、通知单之间无交叉校验（编号连续性、时间合理性、与施工日志的可比对性均未校验）
4. **旁站工作量与监理人员配置不匹配**——若旁站频次超出实际人力，就会自然催生"编造记录"的应对方式。**这是资源配置问题被掩盖为廉洁问题，必须一并查清**

**正确做法**：
1. **立即核查全部旁站记录**——不限于 JS-2026-038 一条，应由建设单位组织对全部旁站记录做**编号连续性核查、时间交叉比对、签字笔迹核验、与施工日志及门禁记录交叉验证**，形成核查结论
2. **暂停相关人员的监理工作**，由监理单位内部调查并向建设单位报告调查结果
3. **追回基于虚假记录支付的款项**，并视情追究违约责任与索赔
4. **建立记录真实性管控机制**：
   - 旁站记录、隐蔽工程记录**必须现场手写、即时签字**，禁止补签
   - 记录编号统一连续编号、**作废编号也须保留并注明作废原因**（断号必须能解释）
   - 旁站人员与记录签字人**应为同一人**，且旁站时间应与**监理日志、门禁记录、施工日志三方时间吻合**
   - 建设单位派员或聘请第三方对关键旁站进行**抽查复核**
5. **把记录真实性纳入监理单位考核**——虚假记录一票否决

**建设单位的意见评价**：意见二**成立且应严肃处理**。但需注意处理边界：**监理单位的记录造假责任与承建单位的工程责任是两条线**，不能因监理造假就推定承建单位的成果合格，也不能因监理造假就把工程问题一并归咎于监理。两条线应分别查清、分别追责。

---

**三、针对"问题四：进度报表失真"**

**缺陷定性**：监理**未识别并有效处理进度报表与实际进度的严重背离**，且对"以非核心功能超额掩盖核心功能滞后"的进度管理手法缺乏敏感度。

**具体分析**：
1. **数据本身已暴露异常**——核心 60% vs 统计报表 120%，这一组数字的背离程度极大，**任何有经验的监理都应立即追问**
2. **"核心功能拖到最后、统计功能顺手做"是典型的"计划谬误"与"进度造假"**——本质是用低风险任务的高完成率，掩盖高风险任务的大幅滞后
3. 监理"核对发现"后仅"指出"，**未要求承建单位提交纠偏计划**，也未采取任何控制措施（监理指令、工期预警、书面报告建设单位）

**进度控制环节的缺失**：
- **未审批承建单位的月度进度计划及其资源投入计划**——若承建单位一开始就计划把核心功能排在最后，监理应在计划审批阶段就提出异议
- **未建立进度偏差的量化分析与纠偏机制**——发现问题后未做偏差分析（关键路径是否已变、是否影响总工期）
- **未就核心功能滞后的工期风险向建设单位发出书面预警**——这是监理的勤勉义务，缺失将导致建设单位在无预警状态下被动接受延期后果

**正确做法**：
1. **立即要求承建单位重新报送真实进度**，并要求说明此前报表失实的原因与责任
2. **重做进度分析**：重新计算关键路径（核心功能延后很可能已改变关键路径），量化偏差对总工期的影响
3. **要求提交纠偏方案**，内容包括：追赶措施、资源投入调整、可能的工期影响，报监理审批后执行
4. **建立进度预警制度**：核心模块进度落后计划超过阈值（如 15%），监理必须书面预警建设单位并抄告承建单位
5. **加强对进度数据的核验**：不依赖承建单位自报数据，通过**代码提交记录、测试执行记录、实际部署内容**交叉验证

**建设单位的意见评价**：意见三**方向成立，但结论要修正**。核心功能滞后确实影响整体上线，但**工期责任不能简单认定**：
- 若滞后源于建设单位需求变更、接口条件不具备、第三方配合不到位，属**建设单位原因**，应顺延工期
- 若源于承建单位技术能力不足、资源投入不足、计划编制不合理，属**承建单位原因**，构成**工期违约**
- 监理的职责是**查清原因并据实认定**，而非直接"认定违约"。**认定工期违约必须基于事实归因，且须有承建单位的申辩与证据**

---

**四、针对"问题五：变更报价"**

**监理在变更审核中的具体缺陷**：

1. **未识别重复计取**——接口联调费 12 万元与合同原范围重复，属**重复计取**，应予剔除
2. **未审核工期报价**——已测算应为 22 天而非 30 天，但未见监理的核减意见，说明**工期与造价未联动审核**
3. **未阻止"先开工后补手续"**——这是变更控制的红线。变更未批准即施工，导致：
   - 工作量难以核实（先干后算，主动权在承建单位）
   - 计价失去谈判基础（沉没成本已成事实）
   - 质量责任边界模糊
   - **构成承建单位的违规，应在报告中明确记载**

4. **审核深度不足**——对 86 万元的变更报价，仅需剔除 12 万元即可看出审核粗糙，未对组价依据、取费标准、工作量计算方法做系统核查

**正确做法**：
1. **退回变更报价**，要求承建单位按合同约定的计价原则重新组价，并提供组价依据（定额、取费标准、人工与材料价格来源）
2. **明确剔除重复计取项**，对工期报价出具核减意见（30 天 → 22 天），并将工期与造价一并纳入变更审批
3. **立即制止"先开工后补手续"**，要求承建单位立即停止该模块施工，并就"未经批准擅自施工"作出书面说明
4. **建立变更前置管控**：变更未获建设单位书面批准，**监理不得签署计量与支付**，并在监理日志中逐次记录
5. **变更的审批主体明确**：监理只对变更的**技术合理性与计价合规性**出具意见，**是否批准变更由建设单位决定**，且建设单位批准应在监理意见基础上作出

**五、针对"问题六：付款失控"**

**这是投资控制环节最严重的缺陷，必须逐项指出。**

**缺陷一：计量与支付脱钩**

第 7 个月进度款的计量工程量未实际完成，**说明监理未履行"计量确认"职责即由建设单位付款**。监理的付款签认是建设单位付款的**前置依据**——监理不签认，建设单位本不应支付。**监理在此处要么签了字（失职），要么未签字（建设单位和监理共同失职）**。

**缺陷二：索赔未审核即支付**

32 万元材料涨价索赔，监理尚未完成审核，建设单位即支付 60%。这暴露：
1. **建设单位绕过监理的付款前置条件**——监理未完成审核，无签认资格，建设单位却直接付款
2. **监理未履职的连带后果**——监理若未明确告知"该笔款项不具备支付条件"，等同于默许
3. **支付比例异常**——未审核即付 60%，本身违反支付控制原则

**缺陷三：累计支付比例失控**

已累计支付 88%，而：
- 核心功能仅完成 60%
- 存在未完成的计量
- 存在未审核的索赔
- **变更（86 万元）尚未获批即施工**

综合上述，**累计支付比例已明显超出实际完成比例对应的应付额度**，超付风险已经形成。

**正确做法**：
1. **立即开展投资专项核查**：逐项核对已付款项对应的计量依据、验收记录、发票与合同条款，出具核查报告，明确应付、已付、应退金额
2. **暂停后续进度款支付**，直至计量与索赔审核机制恢复
3. **建立付款的刚性前置条件**（写入监理合同与工作程序）：未经监理计量确认并签认、未经监理索赔审核意见的付款申请，建设单位不予支付；建设单位如需绕过，属建设单位自身违约责任
4. **强化索赔审核**：材料涨价索赔须审查合同是否有调价条款、涨价的客观依据与幅度、是否为承建单位风险范围内；**若合同为固定总价且约定风险不调价，则不予支持**
5. **设置累计支付上限**（如不超过合同价的 80%），保留足够尾款以约束履约

**六、针对"问题七：文档缺失"**

**缺陷定性**：监理在初步验收前的文档核查中已发现问题，但**未采取任何措施**（未签发监理通知单、未设定整改期限、未报告建设单位、未暂缓验收），属于"发现了不管"。

**文档缺失的实质危害**：
- **数据库设计说明书**缺失 → 后续运维无法理解数据结构，变更风险极高
- **接口联调测试报告**缺失 → 接口质量无证据，问题一（平行检验缺位）与文档缺失叠加，使接口质量完全无法追溯
- **运维手册**缺失 → 系统交付后运维无从接手，必须依赖原开发人员，形成长期人员依赖
- **源代码交付清单**缺失 → **知识产权归属不清**，若合同约定交付源代码，缺失将直接影响建设单位权益，也影响后续安全加固与自主可控

**正确做法**：
1. **立即签发监理通知单**，明确四项文档的整改要求、责任人、期限
2. **文档整改作为验收的前置条件**——**核心文档缺失不得通过初步验收**
3. **若合同约定源代码交付**，须按合同核查交付物清单，未交付构成承建单位违约
4. **建立交付物清单核查表**：合同签订后即由监理编制"交付物清单"并经建设单位与承建单位确认，验收时逐项核对，避免"验收时才发现少东西"

**七、总体评价：监理工作的四个系统性问题**

把上述六个具体问题归纳起来，反映出该监理单位存在四个层面的系统性缺陷：

| 层面 | 具体表现 | 根本原因 |
|---|---|---|
| **程序性** | 平行检验缺位、旁站记录造假、变更先开工后补手续、付款未经计量审核 | 无可执行的监理工作程序，标准化作业文件缺失 |
| **实质性** | 进度报表失真未识别、文档缺失未处置、变更报价审核粗糙 | 监理工作停留在"审阅材料"，未做现场验证与实质核查 |
| **独立性** | 未阻止建设单位绕过程序直接付款；未对建设单位的不当要求提出书面异议 | 监理单位对建设单位的依附性过强 |
| **资源配置** | 旁站频次与人力不匹配（推测） | 监理合同价格与工作量不匹配，68 万难以支撑 14 个月的旁站强度 |

**最后一点特别值得建设单位注意**：建设单位负责人在质疑"68 万花得值吗"时，**把矛头指向了监理单位，但真正的问题是监理服务采购与工作量不匹配**。监理服务费定价过低导致监理单位无法配置足够人力，反而可能诱发记录造假等更严重问题。**这是采购环节的责任，不是监理单位单方面的道德问题。**正确的应对不是简单更换监理单位，而是**重新测算监理服务的工作量与合理报价，并在下一期合同中明确旁站频次、平行检验项、监理人员配置与驻场要求**。

### 问题 2 — 针对建设单位的四点意见，逐条回应

**参考答案：**

**一、针对意见一："压力测试监理没到场，说明监理没尽到职责，压测报告不可信"**

**结论：意见成立，但应补充两点。**

**成立的理由**：
- 核心功能的性能指标是**非功能属性**，只能通过实测获得，审阅报告无法替代验证
- **测试数据由承建单位自行生成、工具由承建单位自行开发**，缺乏独立性与可验证性
- 监理规范明确要求对关键测试实施旁站或平行检验，**这是"该做未做"的职责缺失**

**需要补充的两点**：

**第一，"压测报告不可信"的结论要转化为可执行动作。**不能停留在否定报告，而应：
- 要求承建单位**重新开展压测**，监理实施平行检验（独立工具、独立数据集、独立结论）
- 在重新测试前，**该核心功能不得进入下一阶段**（如用户测试、试运行）
- 重新压测后若指标不达标，按缺陷流程处理并评估对总工期的影响

**第二，责任要查到底——资源配置问题是根因。**监理未做平行检验，除了监理单位自身失职，**建设单位在监理合同中是否明确了平行检验的项数与频次，也是必须核查的**：
- 若监理合同对此无约定，建设单位在合同管理上同样有漏洞
- 若合同有约定而监理未执行，监理单位承担主要责任
- **同时要核查监理服务费与工作量的匹配性**（见后文意见四）

**建议动作**：
1. 书面要求监理单位就压测未旁站一事作出书面说明
2. 委托第三方或监理单位实施平行检验，出具独立压测结论
3. 将"核心功能压测未平行检验"列为重大监理履职缺陷，纳入监理单位履约评价
4. 在后续监理合同或补充协议中**明确列出必须实施平行检验的测试项清单**

---

**二、针对意见二："旁站记录签字造假，监理单位涉嫌造假，必须严肃处理"**

**结论：意见完全成立，且必须严肃处理，但处理方式需分类，避免简单化。**

**第一步：立即固定证据（最紧急）**
- 封存监理单位全部旁站记录、监理日志、会议纪要、通知单原件
- 提取监理单位办公系统的记录修改日志、文件创建时间戳
- 调取监理人员考勤记录、门禁记录（可与旁站记录时间交叉比对）
- **在证据固定前不得让监理单位自行整理归档材料**——否则存在二次污染风险

**第二步：扩大核查范围（不能只查这一条）**
建设单位的意见指向单条记录，但监理单位如果存在系统性造假，问题远不止一条。**必须全面核查**：
- **编号连续性核查**：全部旁站记录编号是否连续，断号是否有作废说明
- **时间合理性核查**：旁站时间是否在监理日志有对应记录、是否在人员考勤与门禁记录范围内
- **交叉比对**：旁站时间与施工日志、承建单位报验记录、设备进场记录是否吻合
- **笔迹与签名核验**：委托专业机构做笔迹检验
- **逻辑一致性核查**：同一监理人员同一天是否出现在多个不同地点的旁站记录上

**第三步：分类处理**

| 情形 | 认定 | 处理 |
|---|---|---|
| 个别记录填写不规范，事实存在 | 记录失实 | 责令整改，人员处理 |
| 编造未发生的旁站记录（本案情形） | **伪造监理资料** | 监理单位承担违约责任，人员停职并按行业规定处理，建设单位可索赔并解除合同 |
| 涉及收受承建单位好处 | 商业贿赂 | 移交纪检监察与司法机关 |
| 甲方授意或默许 | 双方共同违规 | 建设单位相关责任人一并追责 |

**第四步：追回已付款项**
因监理签认是进度款支付的前置依据，虚假签认所支持的付款存在被追回的风险。应**逐笔核查**基于虚假记录支付的款项并追回。

**第五步：制度性补救（最重要的部分）**
- **旁站记录必须现场手写即时签字**，明确"事后补签的旁站记录一律无效"并写入监理合同
- **记录编号统一连续管理**，作废编号须注明作废原因与批准人，**断号必须可解释**
- **建立交叉校验机制**：监理单位内部设专人做编号连续性、时间合理性、记录间逻辑一致性的日常复核；建设单位每月抽查不低于 10% 的记录
- **引入建设单位见证或第三方复核**：对关键工序旁站，建设单位派员或聘请第三方同步见证
- **监理人员配备与工作量匹配核查**：核查旁站频次要求与实际到场人数、到场时长的对应关系，从资源配置上消除造假的动因

**特别提示建设单位**：处理监理单位时，**不要把监理的造假定性为"掩盖承建单位的问题"**。监理确实失职，但承建单位是否因此获得了不应获得的利益（如虚报工程量骗取进度款），需要**独立开展核查**。两条线并行、分别定性，不能因为监理造假就把承建单位的所有问题一并"洗掉"。

**三、针对意见三："承建单位把核心功能拖到最后，影响整体上线，要求监理认定工期违约"**

**结论：意见的方向有合理性，但"直接认定工期违约"的处理方式不正确，且必须先查清责任归因。**

**理由一：核心功能滞后与工期违约之间不能直接划等号**

需要依次查清三个问题，缺一不可：
1. **核心功能滞后的原因是什么**——是承建单位技术能力不足、资源投入不足、计划编制不合理（承建单位原因），还是建设单位需求变更、接口条件不具备、第三方数据未到位、机房环境未就绪（建设单位或第三方原因）？
2. **滞后期是否导致总工期逾期**——这是关键。核心功能滞后可能已被非关键路径上的赶工吸收，**总工期未必受影响**。必须重新计算关键路径，量化偏差对总工期的影响
3. **承建单位是否有过补救**——发现滞后后是否提交了纠偏方案、是否投入了追赶资源、是否尽到"及时减损"义务

**理由二：认定工期违约属于监理的专业判断，且需要完整程序**
- 监理应出具**工期偏差分析报告与责任归因意见**，而非直接"认定违约"
- 归因必须基于事实与证据（会议纪要、监理指令、承建单位的计划与实际对比、往来的确认函件）
- 责任认定后，**违约责任的承担方式（顺延、扣减违约金、赔偿损失）由建设单位按合同约定决定**，监理在合同中一般仅承担"提出意见"的义务，除非合同明确授权监理做出违约认定
- **必须给予承建单位申辩与举证的机会**——监理单方面认定，程序上站不住

**理由三：监理自身的失职在此事件中同样存在，监理的认定意见需要中立性支撑**

监理在本项目已存在平行检验缺位、旁站记录造假、变更审核粗糙、付款失控、文档缺失未处置等多重问题。**在这种状态下，监理就工期问题作出的认定，其公信力本身是有争议的。**

**建议动作**：
1. 监理在 10 个工作日内提交《工期偏差分析与责任归因专项报告》，含：实际进度与计划的逐项对比、关键路径重算、偏差原因分析、承建单位的责任认定意见及依据、建议的处理方式
2. 建设单位组织承建单位**书面申辩**，监理复核后出具最终意见
3. **同步核查监理方的责任**：监理是否在发现进度异常后及时预警、是否要求承建单位提交纠偏计划、是否采取了控制措施。若监理未预警、未要求纠偏，**监理对工期延误的扩大也应承担相应责任**——这在争议解决中往往会被承建单位作为抗辩理由提出
4. 强化后续管理：**月度进度计划由监理审批后方可执行**，核心里程碑进度偏差超阈值即触发监理预警

**结论表述**：核心功能滞后是客观事实，必须查明原因、量化影响、据实归因。**若确属承建单位原因且造成总工期逾期，监理应出具违约认定意见；若属建设单位原因，则应按合同顺延；若属双方原因，则应按影响程度分担。**但"直接认定违约"这一处理方式，程序上不规范，实务中难以站住。

---

**四、针对意见四："合同才 68 万监理费，监理单位连旁站记录都编不出来，这 68 万花得值吗？"**

**结论：这个质疑指对了方向，但归因错了对象，且提出的解决方案会重复上一轮的失败。**

**方向对的部分**：
- 监理服务费与服务质量之间存在**合理的对应关系**，低价监理服务确实难以保证投入强度
- 本案暴露的问题中，**资源配置不足很可能是造假行为的诱因之一**——若旁站频次远超 68 万所能支撑的人力投入，编造记录就成了"最省事的解法"
- 建设单位有权对监理服务质与价进行评价

**归因错的部分：**

**第一，问题不只是钱，更是"工作量没有定义"。**

监理服务费高低本身不是核心，**真正的问题是监理合同没有明确界定监理服务的工作内容与频次**。检查本案的合同约定会发现：
- 是否约定**旁站项清单**（哪些工序必须旁站）？
- 是否约定**旁站频次**（关键工序全程旁站，还是抽检）？
- 是否约定**平行检验的项目与比例**？
- 是否约定**监理人员配置与驻场要求**（总监、专业监理工程师人数、驻场时间）？
- 是否约定**进度预警的触发阈值与报告时限**？

**若合同有约定而监理未执行，监理担责，与 68 万无关；若合同无约定，建设单位的采购管理同样有责。**在没有查清合同条款的情况下，把问题归结为"钱少"，是**归因错了**。

**第二，"换一个监理单位"不会解决问题。**

若不先解决"合同未定义工作量 + 采购价格与工作量不匹配"这两个根因，换一家监理单位、压一个更低的价格，只会得到：
- 更少的人力投入 → 更多编造记录的诱因 → 下一轮同样的问题
- **这是典型的"低价中标—质量下降—换供应商—继续低价"的循环**

**第三，68 万对应 14 个月的监理服务，约合每月 4.9 万。**对照本项目的 30 余个业务系统规模、6 小时数据库迁移旁站、核心功能压测旁站、变更审核、进度控制、验收组织等工作量，**这笔费用是否与工作量匹配，答案是可质疑的**。但正确的结论是"**价格与工作量需要重新测算**"，而不是"**价格高、没花值**"。

**建议动作（分三层）**：

**第一层：立即核查合同与履约**
- 调取监理合同、监理规划、监理实施细则，核对上述工作内容与频次条款
- 核查监理单位实际派驻人员数、到场记录，核对其是否具备履行合同的能力
- 核查是否存在"监理单位以不具备资质或能力的人员充数"的情形

**第二层：形成评价结论并追责**
- 出具《监理单位履约评价报告》：逐项对照合同条款评价履约情况（旁站是否按约定实施、平行检验是否实施、记录是否真实、变更审核是否到位、进度控制是否有效、文档是否核查）
- **区分两类问题**：能力与投入不足（可通过补充人员、要求整改解决）→ 要求限期整改并核验；诚信问题（记录造假）→ 按合同约定追究违约责任直至解除合同
- 按合同约定处理服务费支付：存在重大履约缺陷的，**按合同扣减服务费或不予支付尾款**；合同有约定的按约定执行

**第三层：下一期监理服务重新采购（这才是解决问题的真正落点）**
- **重新测算工作量**：按系统数量、旁站项数与频次、平行检验项、驻场人数与时长、报告频次逐项测算，形成**工作量清单**
- **以工作量清单为基础重新定价**，使监理服务费与实际投入匹配。**这一条应写入招标需求与技术要求**
- **招标文件中明确硬性要求**：旁站记录须现场手写签字、编号连续可追溯、监理人员配置与驻场时间、平行检验项清单、违约责任条款
- **加强履约过程监督**：建设单位派驻甲方代表或聘请第三方监理，对监理单位的工作记录实施抽查
- **建立监理服务评价结果的应用机制**：评价结果与后续监理服务的投标资格、评分挂钩，形成**用评价结果约束下一轮采购**的闭环

**给建设单位的一句话建议**：**当前要做的是"查合同、查人员、算工作量、定责任"，而不是"换一家更便宜或同样便宜的监理单位"。**监理服务的质量不是靠价格买来的，是靠**用明确的工作量定义去采购、用过程监督去保证**。

---

**五、四点意见的汇总回应**

| 意见 | 结论 | 核心动作 |
|---|---|---|
| 一、压测未旁站 | 成立 | 重新压测 + 监理平行检验 + 核查合同是否约定平行检验项 |
| 二、旁站记录造假 | 完全成立 | 固证 → 全面核查 → 分类追责 → 追回付款 → 制度补救（含工作量匹配） |
| 三、认定工期违约 | 方向合理、方式不当 | 专项偏差分析 + 责任归因 + 申辩程序 + 同步核查监理预警失职 |
| 四、68 万值不值 | 方向对、归因错 | 查合同条款 + 查人员投入 + 重新测算工作量 + 下期按工作量采购 |

**贯穿四点意见的核心建议**：本案的教训是**监理工作必须"程序化、留痕化、可核查"**。上述四个问题（压测未验证、旁站造假、进度失控、变更失管）**本质上是同一个问题——监理工作缺少标准化的程序与可核查的证据链**。因此整改的最高优先级不是处理个案，而是**为监理单位建立可执行的标准作业程序，并建立建设单位的抽查核验机制**。个案追责解决不了程序缺失。
