# 信息系统监理师 - 第53次学习（2026-09-09）

## 今日核心概念

### 1. 信息系统工程监理法律基础与监理依据
定义：信息系统工程监理法律基础是监理工作合法性的根本保障，包括国家法律、行政法规、部门规章、技术标准与规范、合同文件五大层级；监理依据是监理工作开展的法律基础和工作准绳。

关键要点：
- 监理依据五大层级（按法律效力从高到低）：
   1. 法律：《招标投标法》《合同法》《民法典》《政府采购法》《网络安全法》《数据安全法》《个人信息保护法》《保守国家秘密法》
   2. 行政法规：《招标投标法实施条例》《政府采购法实施条例》《关键信息基础设施安全保护条例》《计算机软件保护条例》
   3. 部门规章：《信息系统工程监理资质管理办法》《信息系统集成资质管理办法》（已废止转CS）《信息技术服务标准（ITSS）》
   4. 地方性法规：《XX省信息工程建设管理条例》《XX市政务信息化项目管理办法》
   5. 技术标准：GB/T 25000.51（软件产品质量要求与测试）、GB/T 22239（等保2.0）、GB/T 28827（ITSS运维服务）、ISO 20000、ISO 27001、CMMI、ITIL 4
- 监理合同五大依据：
   1. 法律法规（强制约束）
   2. 工程建设文件（业主需求说明书、技术规格书）
   3. 承建合同（业主与承包商合同）
   4. 监理委托合同（业主与监理合同）
   5. 项目前期文件（可研报告、概预算、设计文件）
- 监理工作"四不原则"：不直接参与承建方工作（不替代施工）+不擅自决策（不越权）+不与承建方有利益关系（保持独立）+不泄露业主与承建方商业秘密（保密义务）
- 监理独立公正性三要素：组织独立（独立法人资格）+经济独立（监理费独立核算）+技术独立（专业技术人员配备）
- 监理人员资质：信息系统监理师（国家软考中级，本科+4年工作经验或硕士+2年）+信息系统工程监理岗位证书（行业证书）
- 监理法律责任：行政责任（警告/罚款/吊销证书）+民事责任（赔偿损失）+刑事责任（重大责任事故罪/工程重大安全事故罪）
- 监理人员违规处罚：警告→暂停执业→吊销证书（情节严重）
- 监理行业监管：工信部（行业主管部门）+中国电子信息行业联合会（行业协会）+地方信息化主管部门

### 2. 信息系统工程监理规划与监理细则
定义：监理规划是监理单位根据项目特点编制的指导监理工作开展的纲领性文件；监理细则是针对具体专业工程或分部分项工程编制的操作性文件。

关键要点：
- 监理规划编制依据：监理委托合同+法律法规+项目特点+业主需求+承建合同+技术标准
- 监理规划编制主体：项目总监理工程师主持，专业监理工程师参与，监理单位技术负责人审批
- 监理规划九大内容：
   1. 工程概况（项目背景/规模/工期/目标）
   2. 监理工作范围（监理边界与责任）
   3. 监理工作目标（质量/进度/投资/安全/合规目标）
   4. 监理工作依据（法律法规+技术标准+合同文件）
   5. 监理组织机构（监理部组成+人员分工+岗位职责）
   6. 监理工作内容（四控两管一协调）
   7. 监理工作程序（流程与时序）
   8. 监理工作方法（旁站/巡视/平行检验/见证取样）
   9. 监理工作制度（会议制度/报告制度/文档管理制度）
- 监理规划审批程序：监理单位内部审批→报业主备案
- 监理细则编制要求：针对专业工程/分部分项工程；具体可操作；技术指标明确；质量控制点（WHS点）详细
- 监理细则主要内容：专业工程概况+监理工作流程+监理工作要点+质量控制点+验收标准+常见问题及处理
- 监理交底：开工前由总监理工程师主持，对承建方进行监理规划与监理细则交底，明确监理要求与工作流程
- 监理实施细则动态管理：根据工程进展调整完善；重大变更需重新审批
- 监理规划 vs 监理细则区别：监理规划（纲领性，全局指导）+监理细则（操作性，专业细化）
- 监理工作方法：旁站（关键工序全过程监督）+巡视（定期或不定期检查）+平行检验（独立于承建方的检验）+见证取样（关键材料/工序现场见证）
- 监理规划与监理大纲关系：监理大纲（投标阶段编制，投标文件附件）+监理规划（中标后编制，实施阶段指导）

### 3. 信息系统工程质量控制与WHS控制点
定义：质量控制是监理对信息系统工程质量进行监督检查、测试验证、问题整改的全过程管理；WHS控制点是监理对关键工序进行监督的见证点设置。

关键要点：
- 质量控制三过程：质量规划（制定质量标准）+质量保证QA（过程审计，监承建方是否按规范实施）+质量控制QC（产品检验，监理对成果物验收）
- QA vs QC 区别：QA过程导向（关注过程合规）+QC产品导向（关注产品合格）
- 质量控制老七工具：因果图（鱼骨图4M1E人机料法环）+流程图+核对单+帕累托图+直方图+控制图（UCL/LCL=均值±3σ）+散点图
- 质量控制新七工具：亲和图+关联图+树状图+矩阵图+PDPC过程决策程序图+活动网络图+箭线图
- WHS三点设置原则：W点（Witness，见证，监理到场见证并签认）+H点（Hold，停工待检，必须检验通过才能继续）+S点（Standby，旁站，全过程监督关键工序）
- WHS三点设置方法：
   * W点（一般工序见证）：单元测试报告、设备到货验收、分部分项工程验收
   * H点（关键工序停工待检）：隐蔽工程覆盖前、关键模块上线前、核心代码合入主干前、安全测评结果确认
   * S点（关键工序旁站）：系统集成调试、数据库迁移、网络割接、机房设备上架、安全漏洞修复
- WHS点清单编制：监理规划阶段明确，列入监理细则；根据工程进展动态调整
- WHS点签认流程：承建方提前24小时通知监理→监理到场见证→检查合格签认→进入下一道工序
- 软件质量六大特性（ISO/IEC 25010）：功能性+可靠性+易用性+效率+可维护性+可移植性
- 软件测试四阶段：单元测试→集成测试→系统测试→验收测试；监理重点审查系统测试与验收测试
- 缺陷严重等级：致命（系统崩溃/数据丢失/安全漏洞）+严重（主要功能不可用/性能严重不达标）+一般（次要功能异常）+轻微（UI/文案/小Bug）
- 缺陷生命周期：New→Assigned→Open→Fixed→Verified→Closed（Reopen→再处理）
- DoD完成定义（Definition of Done）：代码评审通过+单元测试覆盖率≥70%+接口测试通过+UAT用户验收通过+部署预发环境+文档完整
- 质量门禁：重大里程碑前的质量审查，未通过门禁禁止进入下一阶段

### 4. 信息系统工程进度控制与投资控制
定义：进度控制是监理对工程实施进度进行计划审查、进度监控、纠偏的管理工作；投资控制是监理对项目资金使用、成本变化进行审核与控制的工作。

关键要点：
- 进度控制七大工具：横道图（甘特图）+里程碑图+网络图+CPM关键路径+PDM前导图法+挣值分析EVM+Project/P6软件
- 监理进度控制三大任务：
   1. 进度计划审查（开工前审查承建方进度计划合理性）
   2. 进度计划执行（按计划跟踪实际进度）
   3. 进度纠偏（偏差分析与纠偏措施）
- 进度计划审查要点：活动分解完整性+活动排序合理性+资源估算准确性+工期估算合理性+关键路径识别+里程碑设置合理性+风险预留
- 进度监控三步：进度数据采集（周报/月报+Project更新）→进度偏差分析（SV/SPI）→进度纠偏措施
- 进度偏差判断：SPI<0.9 进度严重滞后（必须纠偏）；SPI 0.9-1.0 进度轻微滞后（关注）；SPI=1.0 进度符合计划；SPI>1.0 进度提前
- 进度纠偏措施：赶工（加资源缩短工期）+快速跟进（并行执行，返工风险）+资源平衡（关键路径资源倾斜）+范围调整（与业主沟通削减非核心功能）
- 进度变更控制：重大进度变更需CCB评审，重新批准后实施
- 投资控制三阶段：事前控制（投资估算审查、资金计划）+事中控制（进度款审核、设计变更费审核）+事后控制（结算审核、决算审计）
- 投资控制四大工具：投资估算（可研阶段）+概算（初步设计阶段）+预算（施工图阶段）+决算（竣工验收阶段）；后一级控制前一级
- 监理投资控制五大任务：
   1. 工程款支付审核（按工程量+质量+进度）
   2. 设计变更费用审核（必要性+经济性+合规性）
   3. 索赔费用审核（合规性+合理性+证据链）
   4. 材料设备采购价格审核（市场行情+合同约定）
   5. 竣工结算审核（合同+变更+索赔+保留金）
- 工程款支付审核五条件：工程量经监理签认+质量验收合格+进度符合计划+变更手续齐全+发票合规
- 工程款支付审核流程：承建方申报→监理审核（工程量+质量+合规）→业主审批→财务支付
- 工程款支付方式：按月支付+按里程碑支付+按阶段支付+竣工一次支付
- 投资偏差分析：CV = EV - AC（成本偏差）+CPI = EV/AC（成本绩效）；CPI<0.9 投资严重超支
- 投资纠偏措施：价值工程分析（功能/成本优化）+限额设计（限额变更）+合同谈判（调整付款方式）+工程变更控制
- 工程结算审核：合同价款+变更价款-预付款-保留金±索赔=结算价
- 保留金：一般为合同价款的5%-10%，质保期满无质量问题无息退还

### 5. 信息系统工程变更控制与文档管理
定义：变更控制是监理对工程变更进行申请受理、影响分析、评审批准、实施监督的管理工作；文档管理是监理对工程全过程文档进行收集、整理、归档、移交的管理活动。

关键要点：
- 变更控制五步法（CCB五步）：变更申请→影响分析→CCB评审→变更实施→变更验证
- 变更影响五维度：进度影响（是否影响关键路径）+成本影响（是否超出预算）+范围影响（是否触及范围基准）+质量影响（是否引入技术债务）+风险影响（是否带来新风险）
- 变更控制委员会CCB组成：业主代表（决策权）+监理代表（专业建议）+承建方代表（实施方）+设计方代表（设计变更）；必要时外部专家
- 变更分类管理：重大变更（影响范围/进度/成本>10%）+一般变更（影响≤10%）+紧急变更（P0/P1故障修复，24h内ECAB）
- 变更申请文件CR：变更原因+影响范围+紧急程度+实施方案+预算估算+风险评估
- 监理在变更控制中的角色：受理变更申请→组织变更评审→出具监理意见→监督变更实施→验证变更效果
- 监理变更审查要点：变更必要性论证（必须性）+变更方案合理性（可行性）+变更费用合理性（经济性）+变更影响分析（完整性）+变更合规性（程序合规）
- 监理否决权场景：变更未经CCB评审+变更影响分析不充分+变更方案不可行+变更费用明显不合理+变更违反法律法规
- 文档管理重要性：工程档案是项目竣工验收与运维的重要依据；是追溯责任的重要凭证；是经验教训总结的重要来源
- 工程文档五大类型：合同文档（招投标+合同文件）+技术文档（需求+设计+代码+测试）+管理文档（计划+报告+会议纪要）+验收文档（验收报告+签字）+运维文档（运维手册+培训资料）
- 监理文档管理范围：监理规划+监理细则+监理日志+监理通知单+监理工作联系单+监理月报+监理专题报告+监理会议纪要+监理工作总结+工程质量评估报告
- 监理日志主要内容：日期+天气+施工内容+人员动态+材料使用+设备运行+质量检查+安全问题+监理工作+其他事项
- 监理通知单类型：质量不合格通知+进度滞后通知+违规操作通知+安全隐患通知；必须书面发出
- 监理工作联系单：用于一般沟通事项、协商事项、会议通知；不构成强制指令
- 监理月报主要内容：工程进度+质量状况+投资完成+合同执行+变更情况+安全问题+监理工作+下月计划+存在问题+建议
- 工程档案归档要求：完整（不缺项）+准确（不失真）+系统（不混乱）+及时（不延误）；分类立卷；保存期限≥10年
- 工程档案移交：项目竣工验收后30日内监理单位将监理档案移交业主；监理档案一式三份（监理+业主+档案管理部门）
- 电子档案管理：电子签名（数字证书）+电子归档（区块链存证）+长期保存（云存储+异地容灾）

## 案例分析题

**题目**：
某省政务服务中心启动"一网通办"政务平台二期建设项目，将原有一期平台升级为统一的政务服务门户。合同金额1500万元，工期15个月。项目由业主单位省政务服务中心通过公开招标选择总包A公司，并另行通过邀请招标选择监理单位B公司（监理费按工程总投资的2.0%计算）。

项目执行过程：
1. 监理单位进场后第2个月，总监发现承建方未提交开工报告、监理规划未报业主审批、分部分项工程划分未经监理确认；
2. 承建方将硬件采购分包给C公司（业主书面同意），但C公司供货的服务器型号与投标承诺不一致（CPU型号降低），监理要求整改但承建方推诿；
3. 第6个月监理签认工程款200万元，但业主以"项目进度滞后"为由拒付，监理陷入两难；
4. 第8个月承建方提出业务需求变更"增加移动端办事大厅"（合同外），监理审查发现未走变更流程；
5. 第10个月发生重大数据泄露事件，承建方开发的电子证照共享模块SQL注入漏洞被攻击，500万群众身份证信息泄露；
6. 第12个月进行挣值分析：PV=900万、EV=780万、AC=850万；
7. 工程档案管理混乱，监理日志不全，监理月报连续3个月未提交业主；
8. 第13个月承建方主张按原合同条款追加"政策变化导致需求变更"费用200万，但监理发现合同中无政策变更条款。

问题：
(1) 请分析该项目中监理工作的主要问题（按四控两管一协调维度）；
(2) 监理在事件2（硬件降配）和事件5（数据泄露）中应承担什么责任？应如何处理？
(3) 针对事件4（业务需求变更），监理应如何按变更控制五步法处理？

**参考答案**：

问题一：监理工作主要问题

一、质量控制维度：
1. 监理进场后发现承建方未提交开工报告、未提交施工组织设计、未报审监理规划，监理未督促整改
2. WHS点设置不清：承建方关键工序（数据库迁移、系统集成调试）未通知监理见证
3. C公司供货服务器硬件降配（CPU型号降低），监理发现后要求整改但承建方推诿，监理未强力跟进
4. 质量管理失职：电子证照共享模块存在SQL注入漏洞（OWASP Top 10 A03），导致500万群众身份证泄露，反映监理对承建方代码审计与安全测试监督不到位
5. 测试监督缺位：承建方系统测试不充分，重大漏洞未在测试阶段发现
6. DoD完成定义执行不严：缺陷未修复即上线，未达DoD标准仍发布

二、进度控制维度：
1. 项目进度滞后（SPI=0.867<0.9），监理未及时发现与纠偏
2. 监理未督促承建方提交详细进度计划与进度保障措施
3. 关键路径未识别与监控，里程碑节点缺失
4. 进度协调机制失效，承建方与业主就进度问题沟通不畅
5. 进度纠偏措施缺失：未组织进度专题会议，未提出赶工或快速跟进方案

三、投资控制维度：
1. 业主拒付监理签认的工程款，监理陷入两难（既需维护业主权益又需公正独立）

问题二：监理在事件2和事件5中的责任与处理

一、事件2（硬件降配）监理责任与处理：
1. 监理责任分析：
   - 主要责任：监理在设备到货验收时未严格按投标文件核验设备配置，导致降配设备通过验收
   - 次要责任：监理发现降配后要求整改但跟踪不力（承建方推诿未升级处理）
   - 监理违约责任：未履行"四控两管"中的质量控制与合同管理职责
2. 监理处理措施：
   - 第一步：立即下发监理通知单，要求承建方3日内整改（更换符合投标承诺的设备）
   - 第二步：暂停该批次设备验收签认，暂不签认相关工程款支付
   - 第三步：组织专题会议（业主+承建方+监理三方），明确整改要求与时间节点
   - 第四步：若承建方拒不整改，向业主书面报告并建议业主按合同违约条款处理
   - 第五步：协助业主追究承建方违约责任（更换设备+赔偿损失）
   - 第六步：建立设备到货验收制度，所有设备必须严格按投标文件+合同核验配置
3. 监理工作改进：
   - 强化设备验收：对照投标文件+合同技术规格书逐项验收
   - 关键设备100%验收，关键参数100%核验
   - 验收记录详细留痕（设备型号+序列号+配置参数+验收结论）
   - 验收不合格设备严禁用于工程

二、事件5（数据泄露）监理责任与处理：
1. 监理责任分析：
   - 主要责任：监理未督促承建方在系统上线前进行安全测评，未审核SQL注入等高风险漏洞，违反"质量控制"与"安全监理"职责
   - 重大责任：500万群众身份证泄露属于重大安全事件，监理未提前识别与预警
   - 监理违约责任：未履行"协助业主进行安全监督"职责，可能承担违约责任
2. 监理处理措施：
   - 第一步：立即下发工程暂停令，要求承建方停服整改
   - 第二步：48小时内书面报告业主（含事件描述+影响评估+初步原因+整改建议）
   - 第三步：协助业主启动应急响应预案：通知网信办+公安部门+网安部门
   - 第四步：组织安全专项会议，要求承建方立即修复漏洞（72小时内）
   - 第五步：要求承建方进行全面的安全测评与渗透测试，发现并修复所有高风险漏洞
   - 第六步：协助业主评估损失，配合调查取证与责任追究
   - 第七步：要求承建方完善安全开发规范（SDL）+DevSecOps安全融入CI/CD
   - 第八步：协助业主完善数据安全防护体系（数据加密+脱敏+访问控制+审计日志+应急预案）
3. 监理安全监督改进：
   - 强化安全监理：系统上线前必须安全测评（OWASP Top 10）+渗透测试
   - 安全测评纳入监理规划与监理细则
   - WHS点增加安全验证节点
   - 安全合规检查清单（等保三级+数据安全法+个人信息保护法）

三、监理责任边界：
1. 监理责任范围：监理是受业主委托的第三方监督者，不直接承担承建方的开发责任，但应履行监督责任
2. 免责情形：监理已按规范履行监督职责，但承建方刻意隐瞒或违规操作导致事故
3. 追责情形：监理失职（未监督、未审核、未报告）应承担违约责任；情节严重涉及犯罪追究刑事责任

问题三：业务需求变更处理（变更控制五步法）

第一步：变更申请
1. 承建方提交变更申请书CR（含变更原因+影响范围+紧急程度+实施方案+预算估算+风险评估）
2. 申请书必须由承建方项目经理签字+承建方公司盖章
3. 监理审查申请书完整性，要求承建方补充缺失内容

第二步：影响分析（监理组织）
1. 进度影响分析：
   - 增加移动端办事大厅涉及前端开发+后端API+接口测试+性能测试+安全测评
   - 估算工期：约2-3个月（含开发+测试+部署+上线）
   - 关键路径影响：可能影响关键路径，导致总工期延期2个月
2. 成本影响分析：
   - 增加预算：前端开发+后端API+UI设计+测试+部署，约150-250万
   - 监理费按总投资2.0%计算可能增加3-5万
3. 范围影响分析：
   - 增加移动端属于范围扩展（原有合同为PC端+门户网站）
   - 触及范围基准（范围说明书+WBS+WBS字典）
4. 质量影响分析：
   - 移动端代码质量要求与PC端一致
   - 需考虑移动端特有性能+兼容性+适配性
5. 风险影响分析：
   - 新功能可能引入新漏洞（移动端安全需重点关注）
   - 多端协同可能影响系统性能
6. 监理出具影响分析报告（5维度详细分析）

第三步：CCB评审
1. 监理组织变更控制委员会CCB评审会议
2. CCB组成：业主代表+监理代表+承建方代表+设计方代表+外部专家
3. 评审要点：变更必要性（业务必需）+方案可行性+预算合理性+影响可控性+合规性
4. 评审决议：批准/拒绝/延期；批准需明确实施时间+预算+验收标准
5. 监理出具监理评审意见（专业建议）
6. CCB三方签字（业主+承建方+监理）
7. 签订变更协议（业主与承建方）

第四步：变更实施
1. 监理监督变更实施全过程（旁站+巡视+见证）
2. 关键里程碑监理见证（需求评审+设计评审+代码评审+测试用例评审+上线验收）
3. WHS点更新：增加移动端相关控制点
4. 文档更新：WBS+范围说明书+进度计划+成本预算 同步更新
5. 定期报告变更实施进展（周报/月报）

第五步：变更验证
1. 监理组织变更验收（功能验收+性能验收+安全验收+文档验收）
2. 对照变更申请书与变更协议逐项核验
3. 测试报告审查（单元测试+集成测试+系统测试+UAT）
4. 安全测评（OWASP Mobile Top 10+渗透测试）
5. 性能压测（P95/P99响应时间+并发能力）
6. 监理出具变更验收报告
7. 验收合格签认，纳入项目正式范围；验收不合格要求整改后重新验收

六、变更控制注意事项：
1. 变更未通过CCB评审不得实施（严禁先实施后审批）
2. 监理发现承建方擅自实施变更的，应下发工程暂停令并报告业主
3. 紧急变更走ECAB快速通道（24小时内决策），但仍需五步流程
4. 变更文档必须完整留痕（申请书+影响分析+评审纪要+协议+实施记录+验收报告）
5. 变更累计影响超原合同10%须重新招标（避免化整为零规避招标）

**踩分要点**：
- 问题一必须按四控两管一协调七大维度分析（质量+进度+投资+变更+合同+信息+协调），每维度至少3-4个具体问题；同时可补充监理规划、监理细则、监理组织等综合问题
- 问题二硬件降配必须给出监理五步处理（通知单+暂停签认+专题会议+升级报告+追究违约）+验收制度改进；数据泄露必须给出八步处理（暂停令+48小时报告+应急响应+安全会议+漏洞修复+全面测评+协助调查+完善体系）+监理安全监督改进
- 问题三变更控制五步法必须详细展开：申请（CR表格完整性）+分析（进度/成本/范围/质量/风险五维）+CCB评审（三方签字+变更协议）+实施（旁站+见证+文档更新）+验证（功能/性能/安全/文档四项验收）
- 关键数字：1500万合同、15月工期、2.0%监理费、500万群众数据泄露、C公司分包、CPU型号降低、PV=900/EV=780/AC=850、SV=-120/CV=-70/SPI=0.867/CPI=0.918、200万政策变更、追加费用150-250万、变更超10%须重新招标
- 必须体现监理独立性（不偏袒业主或承建方）、程序合规（CCB五步+ECAB 24h）、书面留痕（监理通知单+工作联系单+会议纪要+监理月报）三大原则
- 法规引用：《招标投标法》《合同法》《民法典》《数据安全法》《个人信息保护法》《网络安全法》；技术标准：GB/T 22239（等保2.0）、GB/T 25000.51、OWASP Top 10
