## 今日核心概念

### 1. 大模型推理服务架构

定义：大模型推理服务架构是把训练完成的大参数模型部署为可对外提供低延迟、高吞吐服务的工程体系，解决"算得动、跑得快、扛得住、成本可控"四个问题。
关键要点：
- 显存三件套：权重（参数量×精度字节，如 7B 模型 FP16 约 14GB、INT8 约 7GB、INT4 约 3.5GB）、KV Cache（随上下文长度与并发线性膨胀，是长文本场景显存爆炸主因）、激活值与临时缓冲。显存估算公式：显存 ≈ 参数量×精度/8×1.2 + KV Cache 占用 + 激活开销。
- 推理性能三瓶颈：显存带宽（访存墙，解码阶段为显存密集型）、算力（预填充 Prefill 阶段为算力密集型）、通信与调度开销。因此必须"预填充与解码分离"（PD 分离，Prefill 池 + Decode 池独立部署异构扩容）。
- 关键优化手段：连续批处理（Continuous Batching，替代静态批，请求级动态入批，提升吞吐）、PagedAttention（分页注意力，按块管理 KV Cache 显存碎片）、投机解码（Speculative Decoding，小模型草稿+大模型验证，单请求延迟降 2~3 倍）、张量并行/流水线并行（多卡切分模型）、量化（FP16→INT8/INT4，精度换吞吐）。
- 服务编排三件套：限流与排队（令牌桶、按模型长度分级队列）、多级缓存（提示缓存 Prefix Cache 命中复用前缀、语义缓存 Semantic Cache 命中相似问答）、流式输出（SSE/WebSocket）与取消机制。
- 弹性与降级：GPU 资源池化（K8S+Volcano/Slurm）、按 QPS 与 Token 吞吐双维度 HPA、超时熔断、大小模型路由（小模型先行、置信度不足再升级大模型）。
- 考核指标：TTFT（首 Token 延迟）、TPOT（每 Token 延迟）、端到端 P95 延迟、吞吐（tokens/s）、并发数、GPU 利用率、单 Token 成本。
- 记忆口诀：「权重KV两座山，批页投猜四把刀；预填解码分家走，TTFT与吞吐同时保」

### 2. RAG 检索增强生成架构

定义：RAG（检索增强生成）是在生成前先从外部知识库检索相关片段并注入提示词，以解决大模型知识过期、私有数据不可用与幻觉问题的架构范式。
关键要点：
- 标准链路七步：文档接入与解析（PDF/OCR/表格结构还原）→ 清洗与切分（Chunking，按语义边界/标题层级切分）→ 文档向量化（Embedding，bge-large-zh、text2vec 等中文优化模型）→ 向量入库（FAISS/Milvus/PgVector/Elasticsearch）→ 查询改写与混合检索（BM25 关键词 + 向量语义）→ 重排序 Rerank（BGE-Reranker、Cross-Encoder 精排）→ 上下文组装与生成。
- 切分三要素：粒度（512~1024 Token 均衡）、重叠（10%~20% 防止语义截断）、结构保留（表格转"一记录一段落"而非碎片化单元格）。
- 检索质量四杠杆：Embedding 模型选型、混合检索（关键词保精确、向量保召回）、Top-K 与相似度阈值、查询改写（多路召回、HyDE、问题拆解）。
- 进阶范式：GraphRAG（实体关系图谱全局检索，解决跨文档多跳推理）、RAPTOR（递归摘要树，长文层次化检索）、Self-RAG（模型自评是否需要检索）、Late Chunking（长文本先编码后切分）。
- 生成侧控制三招：引用溯源（返回片段编号与原文链接，防幻觉可溯源）、引用完整性校验（回答必须落在检索片段内）、拒答机制（检索相似度低于阈值时明确回答"知识库未收录"）。
- 关键指标：召回率 Recall@K、精确率、MRR、上下文利用率、答案忠实度 Faithfulness、答案相关度、幻觉率。
- 记忆口诀：「切分嵌入检重排，混合召回保精准；引用拒答双护栏，忠实幻觉可度量」

### 3. Agent 智能体架构

定义：Agent 智能体是具备感知、规划、工具调用与记忆能力，能自主分解任务并执行到底的大模型应用形态，核心是"大模型 + 工具 + 记忆 + 循环"。
关键要点：
- 核心循环：感知（输入）→ 思考推理（ReAct 的 Thought-Act 交替）→ 行动（工具调用 Tool Call）→ 观察结果（Observation）→ 直至任务完成或触发终止条件。
- 任务编排模式：ReAct（边想边做，通用）、Plan-and-Execute（先出完整计划再逐步执行，适合长任务）、Router（分类路由到不同专家 Agent）、Parallel（并行子任务后聚合）、Swarm/Supervisor（多智能体协同与交接）。
- 能力三组件：工具调用（Function Calling / MCP 协议统一工具接入，工具描述即提示词）、记忆（短期对话上下文 + 长期向量记忆 + 情节记忆）、规划与反思（Reflexion 自省重试、Plan-ReAct 迭代修订计划）。
- 工具层工程要点：工具粒度适中、返回结果 Token 裁剪、危险操作人工确认（Human-in-the-loop）、工具失败重试与降级、幂等与权限最小化。
- 多智能体协作模式：Supervisor 中心调度、Debate 多智能体辩论求真、Blackboard 黑板共享、Pipeline 顺序流水线。
- 风险控制：循环失控与 Token 爆炸（设置最大步数与预算上限）、幻觉式工具参数（JSON Schema 强约束 + 参数校验）、提示注入（工具返回内容视为不可信数据）、权限越权（每个工具独立鉴权）。
- 记忆口诀：「感知思考再行动，观察回流成闭环；计划执行治长程，Supervisor 管多兵」

### 4. AI 平台工程化与 MLOps

定义：MLOps 是将机器学习模型从实验到生产全生命周期（数据、训练、评估、部署、监控、迭代）工程化、自动化、可复现的实践体系，解决"模型能算出来但上不了线、管不住"。
关键要点：
- 核心四闭环：数据闭环（采集、标注、版本、漂移检测）、模型闭环（训练、超参搜索、实验追踪、模型仓库与版本管理）、部署闭环（灰度、金丝雀、A/B 切流、影子流量）、运维闭环（在线/离线指标监控、告警、模型回滚、影子验证）。
- 数据与特征工程：训练特征与线上特征必须同源（训练/服务偏斜是模型线上效果崩塌的首要原因），特征存储（Feature Store）统一特征定义与离线在线一致性。
- 数据质量三关：样本覆盖度（长尾样本不足导致分布外失效）、标签质量（标注一致性、标注漂移）、时效性（概念漂移导致模型随时间衰减）。
- 评估体系：离线指标（准确率/召回/F1/AUC、生成任务的忠实度与相关度）+ 在线指标（业务转化、采纳率、人工干预率、成本与延迟）+ 人工评估（专家盲评）。离线好不等于线上好。
- GPU 资源治理：容器化与算力虚拟化、任务队列与优先级（在线推理优先于离线训练）、抢占式调度（Spot 实例训练）、分布式训练（数据并行/模型并行/流水线并行）、显存与算力配额管理。
- 成本优化：模型分级路由（70% 请求小模型、30% 大模型）、蒸馏与量化、Prompt 缓存、批处理合并（动态批）、超时降级。
- 可复现三要素：数据版本、代码版本、随机种子与环境镜像版本，须随模型一并登记。
- 记忆口诀：「数模部运四闭环，特征离线在线同；灰度影子可回滚，采标训评上线全」

### 5. AI 系统安全与可信治理

定义：AI 系统安全与可信治理是对大模型应用全生命周期实施的安全管控与质量治理体系，目标是"内容合规、数据不泄、结果可信、责任可溯"。
关键要点：
- 四类核心风险：内容风险（虚假信息、歧视性内容、违法违规生成）、数据风险（训练数据投毒、个人信息泄露、越权检索）、模型风险（幻觉、越狱绕过、后门与恶意微调）、使用风险（自动化决策歧视、责任不清、依赖过度）。
- 输入侧防护：提示注入识别与隔离、用户输入清洗、越狱检测、敏感词与风险分类前置。
- 输出侧防护：内容安全审核（涉政涉黄涉暴、广告、虚假信息四类过滤）、敏感信息脱敏（手机号、身份证、地址、银行卡正则+模型双通道）、事实一致性校验、拒答与人工转接策略。
- 数据隐私：训练数据脱敏与匿名化、检索内容按用户权限过滤（知识库 ACL 防越权检索）、私有化部署与不出域、向量库分租户隔离、日志不落敏感原文。
- 模型安全：对齐训练（RLAIF/RLHF）、红队对抗测试、模型指纹与水印、敏感能力降级、供应链安全（基础模型来源审查、开源许可证合规 SBOM）。
- 可解释与可审计：生成溯源（引用来源片段）、决策留痕（提示词、检索记录、模型版本、输出全链路日志）、可解释性报告、人工复核机制。
- 治理制度：算法备案与生成式AI服务管理暂行办法、模型分级分类管理、数据出境安全评估、伦理审查委员会、AI 生成内容标识（显式+隐式水印）。
- 记忆口诀：「入防注入出防毒，检索分权数据不出；对齐水印全留痕，备案标识合规路」

## 案例分析题

**题目**：
某市政务服务管理部门建设"政务问答大模型知识库平台"，采用 RAG 架构，为市民和窗口人员提供政策咨询、材料清单指引与办事流程问答。平台上线三个月后出现以下问题：

1. 市民咨询"小微企业创业补贴"时，机器人给出的金额、申请条件和材料清单中有多处与市政府最新政策文件不一致，运营人员核查后发现，模型回答的答案主要来自两年前的一篇已被废止的旧政策解读网页，但该网页仍留在知识库中且向量检索时被召回；同时部分关键内容被切分得支离破碎，答案只说了一半。
2. 部分业务骨干在未授权的情况下，通过系统检索到了内部敏感文件内容（如内部审核要点、未公开的审批时限约定），存在越权访问风险。
3. 平台高峰期（上午 9:00-11:00）大量市民同时访问，页面长时间转圈，监控显示首字响应时间从 1.2 秒升至 9 秒，部分请求超时失败；运维为扩容直接增购 GPU 服务器，但发现扩容后仍不稳定。
4. 业务部门反馈：平台回答"看起来很专业但不确定对不对"，窗口人员不敢直接采信，仍需人工查阅文件，工作台使用率不高，测算发现每千次问答的人工咨询量仅下降 5%。

**问题**（请逐项作答）：
1. 针对问题 1，从知识库治理与检索生成两个层面，指出至少 4 条改进措施，并说明为什么"仅靠更换更大的模型"无法解决问题。
2. 针对问题 2，说明应从哪些层面实施防护，重点说明检索阶段如何实现越权控制，并解释"数据不出域"与"检索权限过滤"的关系。
3. 针对问题 3，列出导致高峰期响应慢的可能原因（至少 4 条），并给出推理服务层面的优化方案。
4. 针对问题 4，说明如何建立该平台的效果度量与闭环优化体系，请提出至少 5 项度量指标及一项提升采纳率的具体机制。

**参考答案**：

**第 1 问：知识库治理与 RAG 链路改进**

（1）知识库治理层面：
- 建立知识全生命周期治理机制：为每份文档打上"来源、发布机构、发布日期、有效期、废止状态、密级、适用区域"等元数据，废止政策必须物理下线或标记失效并从向量库删除，防止过期内容被召回。
- 建立内容准入与审核流程：新增文档须经业务归口部门审核签字后方可入库，明确"谁发布谁负责、谁废止谁下架"的责任链。
- 优化文档切分策略：按标题层级与语义边界切分，粒度控制在 512~1024 Token 并保留 10%~20% 重叠；表格类文档必须先重组为"一记录一段落"的结构化文本，避免单元格碎片化导致上下文断裂。
- 建立文档新鲜度与冲突检测机制：定期比对新旧版本，对同一事项的冲突条款自动告警；对强时效性内容（金额、时限、补贴标准）采用结构化存储与模板化答案优先，避免依赖大模型自由生成。

（2）检索生成层面：
- 提升检索精度：引入混合检索（BM25 关键词检索 + 向量语义检索）并用 RRF 融合，解决"废止旧文件与新政策语义高度相似"导致的召回错误。
- 引入重排序 Rerank：用 Cross-Encoder 类模型对 Top-K 候选文档精排，把最相关的片段压入上下文顶部，缓解"正确答案在第 20 位"的问题。
- 查询改写与多路召回：对市民口语化提问做意图识别与查询改写，必要时拆解为多个子查询并行召回。
- 引入时效性与权威性权重：召回后按文档有效期、发布层级加权重排序，过期文档降权或直接过滤。
- 强化生成约束：强制答案必须在检索片段内生成并附引用出处（可点击跳转原文），无有效片段时明确拒答"知识库暂未收录，请咨询窗口"，禁止模型自由发挥。
- 提升可信度：对金额、日期、时限等关键要素增加规则校验与一致性比对，校验不通过则拦截不输出。

（3）为什么仅换更大模型不能解决：
- 大模型的幻觉源于"基于概率生成文本"而非"基于事实检索"，参数规模无法解决知识时效性与领域私有性；模型参数越大反而越容易把似然而非正确的内容流畅地表达出来。
- 旧政策内容确实存在于知识库中并被召回，大模型忠实于被检索到的错误上下文，属于"垃圾进、垃圾出"，与模型能力无关。
- 切分破碎导致上下文缺失，模型无法推断缺失事实；增大模型不能补回未被检索到的信息。
- 政务场景要求可溯源、可审计，模型再大也无法给出"依据某文件某条款第几项"的确定性引用。

**第 2 问：越权防护的层面与检索权限过滤**

（1）分层防护：
- 身份层：统一身份认证与单点登录，实名办理人、窗口人员、管理员分级；人脸或电子证照结合高风险操作二次认证。
- 授权层：基于 RBAC/ABAC 的细粒度权限模型，属性维度包含角色、单位、部门、事项、密级、时间、终端 IP 等。
- 资源层：文档入库即打密级标签（公开/内部/秘密），敏感文件独立索引库或独立向量集合，与公开库物理隔离。
- 检索层：向量库记录与元数据强绑定，检索请求携带用户身份上下文，服务端在召回后、返回前执行权限过滤（Post-Filtering），命中无权限片段一律剔除并记录审计日志；对高敏库可先做库级路由（Pre-Filtering）再检索。
- 上下文层：生成环节仅接收过滤后的片段，防止通过"多轮诱导提问"或"拼凑式提问"间接套取敏感内容。
- 输出层：敏感信息识别与脱敏（手机号、身份证、内部条款编号），命中则脱敏或转人工。
- 审计层：全量留存"谁、何时、检索了什么、返回了什么"日志，可回溯、可告警、异常检索行为实时风控拦截。

（2）"数据不出域"与"检索权限过滤"的关系：
- 二者目标一致，服务于"最小必要、按需可见"的政务数据安全要求，但手段与层次不同：检索权限过滤解决"同域内谁能看哪部分"（纵向权限隔离），数据不出域解决"数据是否离开可控环境"（边界隔离）。
- 数据不出域是基础前提：模型、知识库、向量库全部部署在政务云内网，数据不经外部公网传输，为权限过滤提供可信的边界。
- 检索权限过滤是不出域条件下的精细化管控：如果模型和索引部署在域外，权限过滤将失去可信边界，不出域也就无从谈起。
- 二者不可互相替代：即使全部不出域，若缺权限过滤仍会横向泄露；即使做了权限过滤，若数据出域仍存在整体失控风险，必须叠加实施。

**第 3 问：高峰期响应慢的原因与推理优化**

（1）可能原因：
- 显存不足导致 KV Cache 争抢，请求排队等待，长上下文请求挤占显存使并发数骤降。
- 采用静态批处理，请求需等待凑满批次，空闲资源浪费且尾延迟高。
- 预填充与解码混部部署：Prefill 阶段算力密集的长输入"大请求"阻塞其他请求的解码，造成队头阻塞（Head-of-Line Blocking）。
- 缺乏限流与分级调度，超出承载能力的请求直接压垮服务，最终大量超时重试形成雪崩效应。
- 语义缓存命中率低或提示前缀缓存未复用，长系统提示每次重复计算。
- 应用侧每次会话都携带完整历史消息，输入 Token 膨胀加剧预填充开销。
- 扩容只增 GPU 数量但未解决调度与缓存问题；也可能存在多模型重复加载导致显存浪费。
- 网关限流缺失、日志同步写阻塞、健康检查探针过密等工程因素。

（2）推理服务层优化：
- 部署架构升级：预填充与解码分离（PD 分离），Prefill 实例（重算力）与 Decode 实例（重显存）按各自瓶颈独立扩缩容。
- 推理引擎优化：采用 vLLM 等 PagedAttention 引擎，配合连续批处理（Continuous Batching）替代静态批；开启 Prefix Cache 复用多轮会话的系统提示前缀。
- 量化与并行：模型 INT8/INT4 量化降低显存与带宽压力；单卡不足时采用张量并行，跨节点采用流水线并行。
- 批处理与调度：按输入输出 Token 长度分级队列，交互式请求优先；设置单请求最大 Token 与最大步数上限。
- 缓存体系：建设语义缓存（相似问题命中历史答案，节省 30% 以上重复计算），并对政务高频标准问答建立 FAQ 兜底直答。
- 弹性扩缩容：基于 QPS 与 Token 吞吐双维度自动扩缩容，结合 K8S 配额管理；扩容必须配套调度与缓存优化，否则边际收益递减。
- 流量治理：网关层限流、排队、熔断与降级（高峰期降级为检索式直答或转人工），配置请求超时与指数退避重试，避免重试风暴。
- 模型路由：引入大小模型路由，简单咨询由小模型或规则引擎直答，复杂问题升级大模型，控制单位成本。
- 客户端改造：启用流式输出降低感知延迟；历史消息做摘要压缩，避免上下文无限膨胀。

**第 4 问：效果度量与闭环优化体系**

（1）度量指标（建议构建四层指标体系）：
- 检索层指标：Recall@K（目标召回率）、MRR、Top-K 命中位置、过期文档召回率、检索耗时。
- 生成层指标：答案忠实度（Faithfulness，答案是否完全有依据）、答案相关度、引用准确率（引用片段是否真正支撑结论）、幻觉率、拒答率与拒答正确率。
- 效果层指标：问答采纳率、窗口人员采信率、人工介入率、每千次问答人工咨询量下降幅度、首次解决率（FCR）、用户满意度。
- 系统层指标：首字响应时间 TTFT、端到端 P95 延迟、并发数、可用性（99.9%）、单次问答成本、知识库文档覆盖率与新鲜度。
- 安全层指标：越权拦截次数、敏感内容拦截率、提示注入拦截率、审计日志完整率。

（2）闭环优化机制：
- 建立"三库一标"基线：黄金评测集（人工标注的高频问题标准答案集，2000~5000 条，覆盖简单/复杂/边界/越权四类）、对抗测试集、回归测试集，配合统一的评测脚本与评分标准，保证每次迭代可量化对比。
- 建立反馈闭环：窗口人员对每次回答进行"有用/无用"一键评分并可填写纠错意见；低分与纠错数据自动进入待优化队列，驱动知识库补录、切分策略调整、Prompt 优化与 Rerank 训练，形成"采集—分析—优化—回归验证—上线"闭环。
- 设立内容运营岗负责知识库日常治理：政策更新 T+1 同步入库、废止文件 24 小时内下线、每周核对高频问题答案准确性。
- 建立灰度与回归机制：每次优化以小流量灰度发布，用黄金集回归验证不劣化后再全量，避免"修一坏三"。
- 建立人机协同机制：涉及金额、资格认定、审批条件等高风险答案强制"AI 草稿 + 人工确认"双轨，窗口人员确认后的修订沉淀为知识库条目。
- 定期开展专题评估（如每月一次盲评与红队对抗测试），并依据度量结果动态调整模型路由策略与知识库投入优先级。

**踩分要点**：

- 第 1 问（知识治理 + RAG + 为何换大模型无效）：必须分层作答，"知识库治理"与"检索生成"两块分开写，避免混为一谈；换大模型无效的原因要答出"幻觉源于概率生成、知识时效性靠外接、旧文档属垃圾进垃圾出、切分破碎导致上下文缺失、可溯源要求与模型规模无关"中的任意 3~4 条，这是本题区分度最高的得分点。
- 第 2 问（越权防护）：分层防护写满身份、授权、资源、检索、上下文、输出、审计七层中至少五层；"检索权限过滤"要答出"元数据强绑定 + 召回后返回前过滤 Post-Filtering + 高敏库库级路由 Pre-Filtering + 审计日志"；最后关系题必须点明"不出域是边界前提、权限过滤是域内精细管控，二者不可替代"，只答一层要扣分。
- 第 3 问（性能）：原因分析要区分"模型侧、引擎侧、架构侧、工程侧"，至少覆盖显存/KV Cache、批处理策略、预填充解码队头阻塞、限流缺失、重试雪崩、缓存未命中中的四条；优化方案务必包含 PD 分离、连续批处理 + PagedAttention、量化与并行、分级队列与限流、缓存体系、流式输出、大小模型路由，其中"PD 分离"与"连续批处理"是拉开差距的关键词。
- 第 4 问（度量闭环）：指标必须分层（检索、生成、效果、系统、安全），不少于 5 项且写明目标值或口径；闭环机制要点名"黄金评测集 + 回归测试 + 灰度发布 + 人工反馈纠错 + 高风险答案人工确认"五件套，缺少回归与灰度会扣完整性分。
- 全题通用踩分：所有改进措施须落到"机制 + 责任主体 + 度量指标"，只写技术名词不给落地抓手最多得一半分；涉及金额、时限、资格等高风险内容，一律要写"规则校验 + 人工确认 + 全程留痕"。
