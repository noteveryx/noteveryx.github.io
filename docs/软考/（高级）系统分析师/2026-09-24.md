## 今日核心概念

### 1. 面向对象分析（OOA）三大模型
定义：面向对象分析是以"对象"为中心的需求分析方法，通过标识问题域的对象、类及其结构、行为来构建系统逻辑模型，Coad/Yourdon方法将OOA产物归纳为三大模型：对象模型（静态结构）、动态模型（交互行为）、功能模型（数据变换），是面向对象软件工程"做什么"的核心建模技术。
关键要点：
- 对象模型：描述系统的"是什么"，是OOA的核心，使用类图（UML Class Diagram）表达，包含类、属性、操作、关联、泛化、聚合/组合等关系
- 动态模型：描述系统的"何时做什么"，使用状态图（单个对象生命周期）和交互图（对象间协作），关注事件触发的对象状态变迁
- 功能模型：描述系统的"做什么功能"，使用用例图（Use Case）+数据流图补充，表达系统功能分解和数据变换
- 三模型关系：对象模型为基础—分三表（动态模型描述对象的状态变迁，功能模型描述对象的操作语义），功能模型中的用例对应对象模型中的类操作
- 建模步骤：①标识对象/类（候选清单筛选：删除冗余、模糊、属性、动词）②标识结构（关联、聚合）③标识主题（包）④标识属性（5个筛选规则）⑤标识方法（动态+功能模型共同推导）
- 与SA的对比：映射关系：SA-DDFD功能模型≈OOA对象模型+动态模型+功能模型（SA分解功能，OOA抽象对象）

### 2. UML用例图（Use Case Diagram）
定义：UML用例图是从用户视角描述系统功能需求的图形化工具，由参与者（Actor）、用例（Use Case）、系统边界、关联关系组成，是需求阶段"系统范围+用户目标"建模的标准工具，也是面向对象分析OOA的入口。
关键要点：
- 四要素：参与者（人形，外部实体）、用例（椭圆，系统功能）、系统边界（矩形框定系统范围）、关系（参与关系—关联线、用例间关系—包含/扩展/泛化）
- 三种用例关系：包含（<<include>>，必选公共子用例，被基础用例强制依赖）、扩展（<<extend>>，可选增强用例，在特定扩展点触发）、泛化（子用例继承父用例行为）
- 参与者类型：主参与者（主动发起）、支持参与者（被动配合，如支付网关）、幕后参与者（时间/硬件触发）
- 用例粒度：业务用例（用户级，高层目标） vs 系统用例（系统级，可实现的最小功能单元）
- 用例描述模板：编号、名称、参与者、前置条件、基本流、扩展流、后置条件、业务规则
- 易错点：不要把用例当成"增删改查"细分步骤（如"打开QQ""输入密码"不是用例），用例是参与者的业务目标

### 3. UML类图与六大关系
定义：UML类图是面向对象系统静态结构的核心视图，展示系统中的类、接口、协作以及它们之间的静态关系，是OOD阶段类设计、模式识别、架构可视化的主要表达方式。
关键要点：
- 类的三大组成：类名、属性（可见性 名称：类型[多重性]=初值）、操作（可见性 名称(参数表)：返回类型）
- 六大关系（由弱到强）：①依赖（uses-a，虚线箭头，临时使用）②关联（has-a，实线，可双向/单向/自关联，多重性1..*）③聚合（弱has-a，空心菱形，整体-部分可分离）④组合（强has-a，实心菱形，整体-部分同生命周期）⑤泛化（is-a，实线空心三角，子类继承父类）⑥实现（虚线空心三角，类实现接口）
- 关键区别：关联 vs 依赖（关联是类属性级长期持有，依赖是方法参数临时使用）；聚合 vs 组合（菱形空心vs实心，整体销毁时部分是否存活）
- 关联的多重性：1（一个）、0..1（零或一个）、*（零或多）、1..*（一到多）、n..m（指定范围）
- 派生属性/关联：用斜杠前缀表示（/年龄=当前日期-出生日期）
- 与ER图区别：类图面向对象（含行为操作、继承多态），ER图面向数据（仅实体属性）；类图关联有导航性，ER图仅表示关系

### 4. UML交互图（顺序图与协作图）
定义：UML交互图是动态模型中描述对象间消息传递与协作顺序的视图，分顺序图（强调时间顺序）和协作图（强调对象结构关系）两种形式，两者语义相同可相互转换。
关键要点：
- 顺序图四要素：对象（生命线顶端的方框）、生命线（虚线垂直向下）、激活条（细矩形，表示对象处于活跃期）、消息（带标签的实线箭头，synchCall=实心三角，asyncCall=开箭头，返回消息=虚线箭头）
- 消息类型：同步消息（实心三角，实线）、异步消息（开箭头，实线）、返回消息（虚线开箭头）、自调用消息（自循环）
- 控制结构：分支（alt，多选一）、循环（loop，循环条件）、并行（par，并发执行）、可选（opt，可有可无）、异常（break）
- 协作图特点：对象+消息编号（1, 1.1, 1.1.1表示嵌套顺序）+对象间连线，弱化时间轴，强调对象协作网络
- 与活动图区别：交互图关注"对象间消息流"，活动图关注"业务流程节点与控制流"；交互图面向对象协作，活动图面向算法/流程
- 时序图变体：UML 2.x新增时间图（Timing Diagram，状态vs时间维度）和交互概览图（Interaction Overview Diagram）

### 5. 4+1架构视图模型
定义：4+1视图模型是Philippe Kruchten提出的软件架构多视图描述框架，用5个互补的视图从不同利益相关者角度描述系统架构，是软件架构师考试和系统分析师考试"架构文档"部分的核心方法论。
关键要点：
- 五个视图：①逻辑视图（Logical，面向对象设计师/系统分析师，描述系统的功能需求分解，对应UML类图/包图）②开发视图（Development，面向程序员，描述模块组织与依赖，对应UML构件图/包图）③进程视图（Process，面向集成商，描述并发与进程通信，对应UML活动图/进程图）④物理视图（Physical，面向运维，描述硬件拓扑与部署，对应UML部署图）⑤场景/4+1中的+1（Scenarios，用例驱动，串联4个视图的"黏合剂"）
- 视图对应关系：逻辑视图+场景→功能性需求；开发视图→代码组织；进程视图→非功能性需求（性能/可用性）；物理视图→系统部署
- 4+1 vs TOGAF ADM区别：4+1是视图框架（What描述），TOGAF ADM是过程框架（How过程）；4+1面向架构师文档，TOGAF面向企业架构治理
- UML图对应：类图/对象图→逻辑视图；构件图/包图→开发视图；活动图（进程泳道）/状态机→进程视图；部署图→物理视图；用例图+场景脚本→+1场景
- 落地工具：4+1视图通常以arc42架构文档模板（轻量级）、RUP的架构骨架（重型）方式落地

## 案例分析题

**题目**：某在线教育平台拟开发"学员在线学习系统"，支持学员注册登录、选课学习、在线考试、成绩查询等功能。项目组采用面向对象方法（OOA/OOD/UML）进行系统分析与设计。请回答下列问题：
1. 请用OOA方法构建该系统的对象模型，请列出至少4个核心类并给出其属性和操作，并说明该系统应识别哪些对象？
2. 在学员选课用例中，包含"验证学员资格"和"扣减学员积分"两个公共子用例，请画出学员选课用例与子用例的关系，并说明包含与扩展的区别。
4. 系统中"订单"类与"订单明细"类是哪种关系？请用UML类图符号（文字描述）表示这种关系，并说明该关系强于普通关联的原因。
3. 描述学员参加考试时，监考系统、考试服务器、考生三者之间的消息顺序（请用顺序图文字描述）。
5. 请用4+1架构视图模型说明该系统应从哪5个角度描述架构？并指出进程视图对应的UML图是什么？

**参考答案**：
1. 核心类（至少4个）：①学员类（属性：学员编号、姓名、手机号、积分余额；操作：注册、登录、选课、参加考试、查询成绩）②课程类（属性：课程编号、课程名称、学时、学分、授课教师；操作：发布课程、查询课程、添加章节）③选课记录类（属性：选课编号、学员编号、课程编号、选课时间、学习进度；操作：记录进度、完成课程）④考试类（属性：考试编号、课程编号、考试时长、总分；操作：生成试卷、自动判卷）⑤成绩类（属性：成绩编号、学员编号、考试编号、分数、考试时间）。识别对象方法：从名词候选清单（学员、课程、考试、成绩、订单、章节、试卷、章节视频等），筛选出可独立存在、有属性有行为的实体。
2. 学员选课用例与两个子用例的关系：学员选课用例---<<include>>---→验证学员资格；学员选课用例---<<include>>---→扣减学员积分。包含（include）与扩展（extend）的关键区别：①方向相反：include箭头从基础用例指向子用例（基础依赖子用例），extend箭头从子用例指向基础用例（子用例扩展基础用例）②强制性：include子用例是基础用例必执行的公共部分（不执行基础用例无法完成），extend子用例是可选行为（仅在特定条件触发）③扩展点：extend需在基础用例指定扩展点（Extension Point），include不需要。
3. 订单与订单明细的关系是组合（Composition，整体-部分同生命周期），UML类图表示：订单◆———订单明细（实心菱形在订单端，实线连接订单明细，订单明细多重性1..*）。强于普通关联的原因：组合关系中整体对象（订单）销毁，部分对象（订单明细）必然随之销毁；订单明细不能脱离订单独立存在；整体拥有部分的生命周期所有权。普通关联仅表示对象间长期持有关系，部分可独立存在。
4. 顺序图描述（学员参加考试）：①学员→监考对象：synchCall"提交考试申请"（消息1）②监考对象→学员：return"验证学员身份"（消息1.1返回）③监考对象→考试服务器：synchCall"请求考试试卷"（消息2）④考试服务器→监考对象：return"返回试卷"（消息2.1）⑤监考对象→学员：asyncCall"下发试卷"（消息3）⑥学员→学员：自调用"答题"（消息4）⑦学员→监考对象：synchCall"提交答卷"（消息5）⑧监考对象→考试服务器：synchCall"提交答卷判分"（消息6）⑨考试服务器→监考对象：return"判分结果"（消息6.1）⑩监考对象→学员：asyncCall"显示成绩"（消息7）。关键：消息编号1→1.1→2→2.1...表示时间顺序。
5. 4+1架构视图：①逻辑视图（类图+包图，面向对象设计师）②开发视图（构件图+包图，面向程序员）③进程视图（活动图/状态机图，面向集成商）④物理视图（部署图，面向运维）⑤场景/4+1的+1（用例图+场景脚本，黏合剂）。进程视图对应的UML图是活动图（含进程泳道Swimlane的并发控制视图）或UML 2.x的交互概览图。

**踩分要点**：
- 第1题：识别对象必须用OOA筛选方法（从名词候选清单出发，删除冗余/属性/动词/边界外对象），每个核心类必须有属性+操作，不能只列类名。
- 第2题：include vs extend是高频考点，三点区别（方向、强制性、扩展点）必须答全，箭头方向不能画反（include从基础→子，extend从子→基础）。
- 第3题：组合 vs 聚合区别是必考点，判断依据是"整体销毁，部分是否随之销毁"，组合用实心菱形，聚合用空心菱形，多重性必须标对。
- 第4题：顺序图必须有对象+生命线+消息+消息编号，synchCall/asyncCall要分清，自调用消息是细节加分项。
- 第5题：4+1的5个视图全名+对应UML图+对应利益相关者角色是必答三件套，缺一扣分。

## 记忆口诀

**OOA三大模型口诀**：对象动态功能（对象模型—静态—类图，动态模型—交互—顺序/状态图，功能模型—用例—用例图），对象模型为基础

**UML用例图四要素**：参与者+用例+系统边界+关系（参与关系+用例关系：包含include/扩展extend/泛化generalization）

**include vs extend区别口诀**：包扩反（include箭头从基础→子，extend箭头从子→基础），包强制选可有，扩需扩展点包不要

**UML六大关系由弱到强**：依关聚组合泛实（依赖→关联→聚合→组合→泛化→实现），菱形空心聚实心合

**UML用例图关系符号**：实线实心三角=泛化（is-a），虚线空心三角=实现（接口实现），实线箭头=关联（参与），虚线箭头+<<include>>=包含，虚线箭头+<<extend>>=扩展

**类图vs顺序图vs用例图**：类图静态结构看"是什么"，顺序图消息交互看"何时发消息"，用例图用户视角看"做什么功能"

**4+1视图口诀**：逻开进程物+场景（逻辑视图+开发视图+进程视图+物理视图+场景视图=4+1），对应角色：分析/开发/集成/运维/全体

**4+1视图-UML图对应**：类包→逻（逻辑视图），构件包→开（开发视图），活动状态→进（进程视图），部署→物（物理视图），用例脚本→场（场景视图）

**UML2.x14种图分四类**：结构图（类/对象/构件/部署/包/组合结构图），行为图（活动/状态机/用例图），交互图（顺序/通信/时序/交互概览图），其他（剖面图）

**对象识别筛选五删**：删属性（颜色、年龄）、删方法（移动）、删事件（点击）、删冗余（同义不同名）、删边界外（与系统无关）
