## 今日核心概念

### 1. 复杂度分析的精细化：摊还分析与主定理

定义：算法复杂度分析不只给出"最坏情况的大 O 界"，还需区分三类界——最坏界（单次操作的保证上界，用于容量规划与服务等级承诺）、期望界（随机算法的平均代价，须同时给出发生概率）、摊还界（数据结构在一串连续操作上的均摊代价上界，是独立于最坏与期望的第三类）。主定理用于直接求解递归式 `T(n) = a·T(n/b) + f(n)` 的渐近上下界。

关键要点：

1. **摊还分析三法**：
   - 记账法：为每个操作预先"充值"势能，操作时消耗，总充值量即上界；
   - 势能法：定义势函数 Φ(s)，单次摊还代价 = 实际代价 + Φ(s_i) − Φ(s_{i−1})，需证明总势能增量非负以保证界成立；
   - 聚合（总和）法：先求整个操作序列总代价，再除以操作数 n。
2. **经典摊还结论**：动态数组追加为均摊 O(1)（按倍数扩容，扩容代价被摊到后续 n 次插入上，摊还代价上界约 3）；哈希表查找期望 O(1) 但最坏 O(n)（冲突链退化）；平衡树与跳跃表为 O(log n)；队列在摊还模型下插入 O(1)。
3. **主定理三种情形**（设 `f(n) = Θ(n^{log_b a} · log^k n)`）：
   - 情形一：`f(n) = O(n^{log_b a − ε})`（ε>0）→ `T(n) = Θ(n^{log_b a})`；
   - 情形二：`f(n) = Θ(n^{log_b a} · log^k n)` → `T(n) = Θ(n^{log_b a} · log^{k+1} n)`；
   - 情形三：`f(n) = Ω(n^{log_b a + ε})` 且满足正则性条件 `a·f(n/b) = O(f(n))` → `T(n) = Θ(f(n))`。
4. **工程含义**：数据规模从百万级跨到十亿级时，O(n) 与 O(n log n) 是数量级差距而非百分比差距；容量估算应用"单次代价 × 调用总量"，不能只看单点复杂度；隐蔽的 O(n) 陷阱——列表中间删除、循环内字符串拼接、日志全表扫描、循环内查库、逐条拉取接口、每次重算全量派生数据。
5. **摊还界不是"平均成本"**：摊还分析给出的是**任意操作序列**上的保证，不是"最可能情形"，因此可以直接用于 SLA 与容量承诺；而期望界依赖概率分布，不可用于硬承诺。

### 2. 计算复杂性理论与 NP 完全性：为什么"最优解"常常不可得

定义：P 是多项式时间可解问题集；NP 是解可在多项式时间内**验证**的问题集；NP 完全问题是既属于 NP、又能把任意 NP 问题多项式时间归约到它的问题；NP 难问题至少与 NP 完全问题一样难。归约（Reduction）是判定 NP 完全性的标准技术。

关键要点：

1. **NP 完全性的两条证明义务**：① 问题属于 NP（给出候选解的多项式验证过程）；② 任意 NP 问题可多项式时间归约到本问题，即 `B ≤p A`，归约方向不能写反。
2. **经典 NP 完全问题**：3-SAT、顶点覆盖、图着色、团问题、哈密顿回路、旅行商问题（TSP）、划分问题、0-1 背包、子集和；Cook-Levin 定理确立 SAT 为首个 NP 完全问题。
3. **近似算法与近似比**：定义式必须写清方向——最大化问题的比值近似为 `OPT/ALG ≤ ρ`，最小化问题为 `ALG/OPT ≤ ρ`。经典保证：顶点覆盖 2-近似；度量 TSP 2-近似、Christofidos 算法 3/2-近似；最大割 1/2-近似；装箱 3/2-近似；集合覆盖 ln n 近似；在 P≠NP 假设下，不存在无多项式时间常数近似比保证的精确多项式算法。
4. **贪心与近似的边界**：贪心策略若能证明"贪心选择性质 + 最优子结构"成立，则直接得最优解（最小生成树、哈夫曼编码、区间调度）；无法证明时，贪心只是一种**无保证的启发式**，其结果只能表述为近似解。
5. **启发式与元启发式工程选型**：局部搜索（邻域定义是关键）、模拟退火（温度-退火调度决定跳出局部最优能力）、遗传算法（编码-选择-交叉-变异）、蚁群算法（信息素正反馈）、禁忌搜索（禁忌表防止回退）；工程上需明确"可接受损失"与"求解时间上限"两个参数。
6. **混合策略范式**：精确算法只用于小规模子问题（如分治中的小规模块、区间 DP 的小区间），大规模用近似/启发式，并以局部修复（如破坏-重建、大邻域搜索）提升解质量。

### 3. 图论算法族与网络优化建模

定义：将系统要素抽象为顶点、要素间关系抽象为边与边权，用图算法求解最优配置、最短路径、资源分配与故障影响面问题。图论是系统分析师最常用的建模语言之一。

关键要点：

1. **最短路谱系**：Dijkstra（非负权单源，堆优化 O(E log V)）；Bellman-Ford（允许负权，可检测负环，O(VE)）；Floyd（全对最短路 O(V³)，用于小规模全网分析）；A*（启发式搜索，`h` 需满足可采纳性与一致性，否则不保证最优）；0-1 BFS 与 Dial 算法处理小整数边权。
2. **最小生成树**：Prim 从顶点扩展（稠密图 O(V²)）、Kruskal 按边排序 + 并查集（稀疏图 O(E log E)）；性质——割性质保证任意横跨割的最小权边必在 MST 中；环性质说明最大权边可不在 MST 中；权值相等时 MST 可能不唯一。
3. **最大流最小割定理**：Ford-Fulkerson 增广路（依赖容量整数性保证终止）、Edmonds-Karp O(VE²)、Dinic 强多项式；应用面广——二分图最大匹配、任务分配、可靠度与最小割集、带宽分配、交通流量分配、容量规划。
4. **匹配与指派问题**：匈牙利算法求二分图最大权匹配（对应指派问题），可用最小费用流建模；图着色对应资源冲突排班，团问题对应多元资源冲突判定。
5. **拓扑序与有向无环图上的最长路**：拓扑排序用于判定环路与求关键路径（项目管理网络与调度约束共用同一模型）；强连通分量、割点、桥用于故障影响面与可靠性分析。
6. **建模要点**：边权语义必须写明（时间/费用/容量/惩罚）；含时序约束的场景用"时间展开图"分层建模；超大规模图先做区域缩点、层级图、预计算与热点剪枝，避免直接跑全量算法。

### 4. 动态规划建模方法论：状态定义决定成败

定义：动态规划用于多阶段决策的最优解求解，本质是用"空间换时间"的表格化方法把组合爆炸的搜索空间压缩为状态空间上的递推。

关键要点：

1. **五要素**：阶段、状态定义、决策、状态转移方程、初始与终止条件——口诀"阶段、状态、决策、方程、边界"，缺一不可。
2. **三个成立条件**：最优子结构、无后效性（某阶段的状态只由前面阶段决定，与之后如何决策无关）、子问题重叠（这是 DP 相对分治提效的根本原因）。
3. **经典模型谱系**：0-1 背包 / 完全背包 / 多重背包；最长公共子序列与编辑距离；区间 DP（矩阵链乘、括号匹配、最长回文子序列）；数位 DP（计数与范围统计）；状压 DP（旅行商、任务排程）；概率与期望 DP。
4. **空间优化**：滚动数组按依赖方向压维（0-1 背包一维化时物品必须**倒序**遍历，顺序遍历会导致同一物品被重复使用）；记忆化搜索与递推二选一；内存不足时改用"路径回溯 + 哈希缓存"或按阶段分块落盘。
5. **高频错误**：状态定义缺维（漏掉剩余容量/剩余时间等约束维度，导致方案非法或答案偏大）；转移方程漏分支（未处理"不选"或"不装"）；边界初始化错误（不可达状态应为负无穷而非 0）；遍历方向错导致重复取用；把"后效性"破坏的输入（顺序敏感问题）硬套 DP。
6. **与贪心的判别**：能证明贪心选择性质用贪心（更快），否则用 DP（更优）；DP 状态数过大时退化为搜索 + 剪枝（分支限界）或直接用启发式。

### 5. 并行与分布式算法及算法工程化落地

定义：并行算法通过多核/多机协同加速求解；算法工程化是把理论复杂度转化为可交付工程性能的一整套手段（预处理、索引、缓存、增量、向量化、近似、离线在线分离）。

关键要点：

1. **加速比与并行度**：`S(p) = T(1) / T(p)`；Amdhal 定律——串行占比 s 时 `S(p) ≤ 1/s`，存在硬上限；Gustafson 定律——若问题规模随核数 p 同步增长，则 `S(p) → p`，扩展性依赖"弱扩展"与"强扩展"的区分。
2. **并行代价**：通信开销、同步等待、负载不均（长尾任务）、共享内存竞争与伪共享；两类并行——数据并行（批处理、特征工程、报表统计这类各算各的、易于并行）与任务并行（分支限界、图遍历、参数搜索）。
3. **分布式算法特有约束**：幂等设计（至少一次投递 + 去重）、最终一致性而非强一致（避免全局锁与跨库事务）、数据倾斜与热点键（分片再平衡、加盐/二段散列、热点拆分）、分区裁剪避免全表扫描。
4. **算法工程化九招**：预处理与批量计算；索引与倒排；多级缓存（本地—进程—分布式）；空间换时间（预计算表、位图、布隆过滤器）；增量与事件化计算；原地算法与流式处理；向量化/位运算/图形处理器加速；采样与近似（可交换随机抽样、蓄水池抽样）；离线计算与在线查询分离。
5. **必须写明的权衡**：精确 vs 近似、延迟 vs 成本、实时 vs 离线、通用 vs 特化、模型复杂 vs 可解释。
6. **验证与治理闭环**：单元测试 + 属性测试（对不变量随机生成验证）、基准测试与压测（含最坏输入与拐点）、影子流量对比、灰度与回滚、算法版本化与效果度量（准确率/召回率、P99 延迟、单次成本、覆盖率），并把"算法效果"纳入监控告警。

## 案例分析题

**题目**：某市建设"城市交通信号协同优化与应急运力调度平台"，覆盖全市 2.6 万个信号路口、约 48 万条路段，实时接入车辆轨迹、公交刷卡、120 急救呼叫三类数据。

平台上线一年后出现四类问题：

（1）**信号配时效果不升反降**：原方案采用"逐路口独立贪心配时"，单路口通行时间下降 8%，但全市路网平均延误由 62 秒升至 71 秒，早晚高峰潮汐路段排队溢出至上游路口，形成"一处优化、处处恶化"。运维反映，把全网路口一起联立求解属于 NP 难问题，等待数十分钟仍算不出可行解。

（2）**计算时延不可接受**：全量协同优化一轮需 3.5 小时，调度屏只能显示 6 小时前的策略；平台要求分钟级刷新，运维尝试将单路口数从 2.6 万降到 3000 个做"抽样优化"，结果策略下发到未抽中的路口后整体效果回退。

（3）**应急运力调度依赖人工**：120 急救平均出车 8 分钟、跨区支援频繁绕行。调度员依据经验手工派车，车辆路径规划依赖"逐单最近点贪心"，在多车辆、时限窗、载重不同条件下频繁产生不可行派单，现场改派频繁。

（4）**性能与稳定性退化**：平台一次全量重算期间，在线查询接口 P99 响应时间从 400 毫秒升至 3.2 秒；运维临时把在线链路降级为"只读缓存"后被市民投诉；同时发现某区实时轨迹数据量是其他区的 60 倍，导致该区分区任务积压 40 分钟，而其他区早已算完，空转等待。

现请你作为系统分析师，提出算法与体系层面的改造方案。

**参考答案**：

**问题一：局部贪心导致全局次优的根因与算法族选择**

1. 根因是**目标函数错配与局部最优陷阱**：逐路口贪心优化的是单路口延误总和，而全市延误是一个**全局耦合**目标（相邻路口的放行决策相互影响，下游溢出成本必须计入上游决策）。经典反例即可解释：两个相邻路口分别贪心，都选择"本路口绿灯延长"，二者叠加导致队列在两者之间来回振荡，全网延误上升。
2. 论证计算复杂性：把路网抽象为图、路口放行方案抽象为决策变量后，单路口配时是背包/多约束优化，路口之间存在容量耦合，整体落入 NP 难类。**结论：不可寄望于多项式时间精确全局最优**。
3. 正确算法族选择：
   - **图论建模 + 网络流/最短路**负责结构性问题：路段通行时间、上下游溢出、路径选择；
   - **动态规划**负责单条路径/单条走廊（绿波带）的时序最优，状态可含"相位与到达时刻"，具备最优子结构；
   - **启发式/元启发式**（局部搜索 + 大邻域搜索、模拟退火、蚁群）负责多路口联合的大规模联合寻优；
   - **分解策略**负责规模：区域分解 + 走廊级子问题 + 区域间用网络流/拉格朗日松弛交换边界流量。
4. 贪心的正确用法：仅在**可证明贪心选择性质**的单点小问题上保留（例如"相位差最小化"的绿波带配时在单向走廊模型下有最优性保证），并在文档中写明"局部贪心不保证全局最优"的适用边界。

**问题二：3.5 小时全量重算与分钟级刷新的矛盾（复杂度工程化解法）**

1. **先做复杂度与耗时归因**：`T(n) = a·T(n/b) + f(n)` 型递归用主定理定阶；重算慢的典型根因是 f(n) 中含"对每个路口 × 每条邻接路段 × 每个时段"的重复全量计算（O(V·E·T)），以及数据倾斜导致的等待，而非算法本身指数级。
2. **摊还视角的优化**：把重复代价前置——拓扑排序后的"影响传播"只沿受影响子图扩散，代价由 O(V·E·T) 降到与受影响节点数成正比的均摊代价；动态数组式扩容只适用于局部缓存扩容的摊还结论，不可直接套用于全局重算。
3. **增量 + 事件化**：由"全量定时重算"改为"拓扑与流量驱动的事件触发重算"——检测到流量突变、上游溢出、信号配时变更、公交优先触发等事件时，仅对受影响走廊及下游子图重算，典型代价从 O(全网) 降为 O(受影响子图)。
4. **采样/分层/近似**：离线层做全量精确或高精度求解（小时级、异步、可回溯），在线层用分钟级轻量模型（参数化绿波/区域均衡）下发；在线模型必须标注"由离线模型产出、由在线模型裁剪"，并定期用离线全量结果回灌校正，防止类似"抽样优化下发到未抽样路口"造成的整体回退。采样下发的覆盖面必须全量（每条路至少被某次抽样覆盖或被规则兜底覆盖）。
5. **分解并行**：区域级子问题间弱耦合（仅边界流量耦合），可按区域并行；采用数据并行（矩阵/图批量计算向量化）+ 任务并行（区域任务分配），用 Amdhal 定律评估加速比上限：若串行占比 s=0.15，理论加速比上限约 6.7，扩到 16 核收益递减，因此并行度应按实测拐点设定（通常不超过串行占比倒数）。

**问题三：应急运力调度——从贪心到可行解工程**

1. 问题建模：多车辆、异构载重、时限窗、起讫点固定的**带时间窗车辆路径问题**，属 NP 难。贪心"最近点"只保证单次局部最短，不保证总成本与时限可行。
2. 分层求解：
   - 第一层**可行解生成**：先按急救等级/时窗紧度/距离构造初始派车顺序，保证"每单有车且不超时"（可行性优先于最优性）；
   - 第二层**大邻域搜索/局部搜索**：以"破坏（移除一区段订单）—重建（按插入代价最小重排）"迭代，压降总里程与总等待；
   - 第三层**精确求解兜底**：对规模缩小的子区域/小车队用精确算法（整数规划 + 分支定界 / 网络流）求最优或近优解；
   - 第四层**跨区支援**：用网络流或最小费用流解决"哪一区借车、借多少、借多久"的分配问题，保证全局可行且不违反各区保底车辆数。
3. **时限窗与不可行处理**：软约束（超窗惩罚）转为目标函数中的惩罚项，硬约束（急救黄金时间）不可违反；对确实不可行的订单输出"最近可行替代方案 + 升级建议"，而不是硬派导致违规。
4. 现实约束补齐：跨区支援需要**人员/资质/车辆类型匹配**，在模型中加可行性过滤（先过滤再优化），避免生成不可执行方案。

**问题四：P99 恶化、数据倾斜与降级误用**

1. **P99 从 400 毫秒升到 3.2 秒的归因**：重算任务与在线查询共用同一批计算资源与同一队列，造成资源争抢；重算过程持有大对象与内存缓存，触发 GC 停顿；在线链路与批处理链路缺乏资源隔离。
2. **治理措施**：
   - **资源隔离**：在线查询链路与离线重算链路分队列、分线程池、分机器组；在线链路设置优先级与配额（如 CPU 配额 20%、独立内存池）；
   - **削峰与错峰**：重算任务安排在低峰或按优先级排队，避免与查询峰值重叠；
   - **重试与背压**：查询侧加熔断、限流与降级，防止重算受阻引发级联；
   - **减少全量对象**：重算改用增量/流式与列式存储，避免全量物化导致的 GC 压力。
3. **降级误用的纠正**：降级为"只读缓存"必须明确缓存数据的**最大可接受时延**与**过期数据对业务的危害**——对应急调度这种强时效场景，过期数据不可用，应降级为"展示最近一次成功解 + 标注时间 + 转人工兜底"，而不是把过期策略当作现行策略下发；降级方案必须写明适用场景、触发阈值、恢复条件与责任人。
4. **数据倾斜治理**：某区数据量 60 倍导致积压，采用——
   - 按**区域 + 时间窗**重新分区，把倾斜键再切分为二级子键；
   - 热点分区单独拆出独立任务组并提高其并行度；
   - 避免"全局等待最慢分区"的同步屏障，改为按区域完成即发布（流式发布 + 区域级一致性），并以"各区域版本号 + 发布时间"向调度端声明数据新鲜度；
   - 上游做数据抽样与降采样（轨迹按 5 秒粒度聚合），保留峰值特征的抽稀算法。

**问题五：算法治理与落地路线**

1. **算法资产化**：每个算法登记"输入/输出契约、复杂度等级、精度特征、超时上限、失败降级策略、版本号、责任人"，纳入配置与版本管理，避免算法以脚本形式散落在业务代码中。
2. **效果度量体系**：把"算法有效"拆为四层——业务效果（全市延误、排队溢出次数、急救出车时长）、模型效果（最优性差距/近似比、覆盖率）、系统效果（P99 延迟、任务积压时长、资源成本）、工程效果（可复现性、回滚时长、缺陷率）。每层都要有基线与目标值。
3. **正确性验证**：属性测试验证不变量（如"总延误不高于基线""派单不违反时间窗""结果对输入顺序不敏感"）；影子流量与人工调度结果对比；关键场景回归集与最坏输入压测；上线采用影子运行 → 灰度 → 分区放量 → 全量的四阶段，任一阶段指标劣化自动回滚。
4. **分阶段路线**：
   - 第一阶段（1 个月）：归因与隔离——在线/离线链路隔离、数据倾斜分区与降级规范修正，把 P99 拉回基线；
   - 第二阶段（2 个月）：算法重构——事件触发增量重算 + 区域分解并行上线影子模式，全量结果作为在线策略的基准与兜底；
   - 第三阶段（2 个月）：算法升级——引入大邻域搜索与元启发式改善联合优化与应急调度质量，建立近似比与业务效果对照表；
   - 第四阶段（持续）：算法治理——算法资产台账、效果度量看板、季度回溯评审与策略迭代机制。
5. **风险与约束**：短期内不得承诺"全局最优"；所有对外公布的策略效果口径必须注明是"离线最优解"还是"在线近优解"及其相对基线的差距；跨部门协调（交通、卫健、公交）数据标准与考核口径需在项目章程中锁定。

**踩分要点**：

1. **必须指出贪心失效的本质是目标函数错配**：局部优化目标是"单路口/单次派车成本"，而真实目标是"全网总延误/总里程最小且可行"，须写出"耦合目标 + 局部最优陷阱"两个关键词，只答"贪心不好"不得分。
2. **必须点明复杂性与可解性结论**：明确写出该类问题属 NP 难、精确最优不可期，给出"图论 + 动态规划 + 启发式 + 分解"的算法族选型。只说"用启发式"不给算法族依据不完整。
3. **必须写出近似算法保证与归约方向正确**：近似比定义方向不能写反（最大化 OPT/ALG ≤ ρ，最小化 ALG/OPT ≤ ρ）；NP 完备性证明须含"属于 NP"与"归约到本问题"两条义务；归约方向不能颠倒。
4. **复杂度分析要落到数量级与陷阱**：必须写出 O(n) 与 O(n log n) 在十亿级数据下的差距，并点名至少两个隐蔽 O(n) 陷阱（循环内查库、列表中间删除、字符串拼接、全表扫描等），这是区分"背概念"与"会分析"的关键。
5. **主定理与摊还分析要各有落点**：至少正确写出主定理三种情形之一并用于给定递归式；摊还分析需点明"任意操作序列上的保证、可用于 SLA"，与期望界区分开。
6. **图论模型必须写清图要素语义**：顶点、边、边权各代表什么，边权是时间/费用/容量；须写明最小生成树与最大流最小割在本场景的对应关系，不能只写算法名。
7. **"3.5 小时 → 分钟级"的方案必须给出可落地机制**：事件触发增量重算、影响子图传播、离线全量 + 在线轻量模型、采样必须全覆盖（并明确指出"抽样下发到未抽样路口"这一错误），只写"优化算法"不得分。
8. **并行度与加速比必须用 Amdahl 定律给上限论证**，并指出串行占比决定加速比天花板，扩核不等于线性提速；须说明并行带来通信、同步、长尾负载开销。
9. **应急调度必须给"先可行后最优"的分层求解路径**：初始可行解 → 大邻域/局部搜索 → 小规模精确兜底 → 跨区支援用网络流/最小费用流；且必须写明时间窗硬约束不可违反、超时用惩罚项转软约束。
10. **数据倾斜治理答案要落在工程手段而非"加机器"**：再分区/二级子键、热点分区独立任务组与并行度提升、去除全局同步屏障改流式发布、抽稀降采样；须说明"其他区空转等待"是同步屏障问题。
11. **性能退化必须区分"资源争抢"与"算法退化"**：答出在线/离线链路隔离（分队列、分线程池、分机器组、配额）、错峰、GC 与大对象压力、熔断限流背压；只答"扩容"不得分。
12. **降级误用必须被明确纠正**：指出"把过期缓存策略当作现行策略下发"是错误做法，应为"标注时间 + 转人工兜底 + 适用条件 + 触发阈值 + 恢复条件"，并点出应急强时效场景不接受过期数据。
13. **必须给出算法治理闭环**：算法资产台账（契约/复杂度/精度/超时/降级/版本/责任人）、四层效果度量（业务/模型/系统/工程）、属性测试与影子流量验证、四阶段发布（影子→灰度→分区→全量）+ 指标劣化自动回滚。
14. **必须给分阶段路线与时间表**，且阶段划分体现"先隔离止血、再算法重构、后质量提升、终持续治理"的递进逻辑，每阶段有明确交付物。
15. **评分标准的"开放性"处理**：需声明短期内对外口径为"近优解"而非"全局最优"，并说明与基线的差距须可度量、可回溯，这是系统分析师视角的责任边界意识。

## 记忆口诀

**一、复杂度三界（最坏/期望/摊还）**

1. 最坏保底、期望看概率、摊还保序列——三者别混。
2. 摊还不是平均：任意序列都成立，才敢写进 SLA。
3. 记账势能聚合法，三法通用摊还法。
4. 动态数组摊还常数一，扩容代价摊后头。
5. 哈希期望常一最坏全，链化退化记心间。
6. 主定理三情形：小于取平、齐次多对数、大于取 f。
7. 数量级差距非百分比，百万到十亿是断层。
8. 隐蔽 O(n) 四兄弟：循环查库、中删元素、串拼、日扫表。
9. 容量估算看总量，单次再快也怕乘。

**二、复杂性理论与 NP 难**

10. P 是能做，NP 是能验；NP 完全是能做验还最难。
11. 证明两义务：属 NP 加归约；归约方向莫写反。
12. 3-SAT 领头，团、覆盖、着色、旅行商跟。
13. 近似比方向记牢：小的除 OPT，大的被 OPT 除。
14. 顶点覆盖二近似，度量旅行商二，Christofidos 一半。
15. 贪心有证才最优，无证便是启发式。
16. 局部最优陷阱：相邻路口互让，反成全网更堵。
17. 精确只做小子问题，混合框架是大势。
18. NP 难不怕，怕的是没有基线与近似比。

**三、图论算法族**

19. 最短路：正权 Dijkstra，负权 Bellman-Ford 检测环。
20. 全对用 Floyd 三方次，小规模网络最省心。
21. A* 启发要可采纳，不一致就不保证最优。
22. 生成树：Prim 顶点扩，Kruskal 边排序加并查。
23. 割性质最小边必入树，环性质最大边可舍。
24. 权相等树不唯一，选法须写清不写错。
25. 流量问题统一用流：最大流等于最小割。
26. 增广路 Ford-Fulkerson，容量整数才保终止。
27. 二分匹配即指派，匈牙利法出最优配。
28. 图着色排冲突，团判多元冲突。
29. 拓扑序查环排关键路径，割点桥定故障面。
30. 建模三件套：顶点、边、边权语义写清。

**四、动态规划五要素**

31. 阶段、状态、决策、方程、边界——缺一不可。
32. 三条件：最优子结构、无后效、子问题重叠。
33. 子问题重叠是 DP 快过分治的根由。
34. 背包三型：01 完全多重，遍历方向记心头。
35. 0-1 背包倒序走，顺序走就重复拿。
36. 区间 DP 括号与矩阵链，状压 DP 排任务。
37. 状态漏维则答案偏大，边界错则方案非法。
38. 不可达状态负无穷，别拿 0 充数。
39. DP 状态爆炸退搜索，剪枝是命门。
40. 贪心能证就用贪心，快且最优。

**五、并行与算法工程化**

41. 加速比 T1 比 Tp，Amdahl 卡在串行占比。
42. 串行占一成，上限十倍速。
43. 弱扩展规模随核长，强扩展规模不变难。
44. 并行四开销：通信、同步、长尾、竞争。
45. 数据并行 embarrassingly，任务并行要切分。
46. 幂等加去重，最终一致免全局锁。
47. 分片再平衡治倾斜，热点键二段散列拆。
48. 工程九招：预处理、索引、缓存、空间换时间。
49. 增量流式、原地化、向量化，三招压时延。
50. 采样近似须说明误差，蓄水池抽样保均匀。
51. 离线算在线查，节奏分离两边清。
52. 精确与近似、延迟与成本，总要写明取舍。
53. 属性测试验不变量，影子流量比结果。
54. 影子、灰度、分区、全量，劣化自动回滚。
55. 算法资产要台账：契约、复杂度、版本、责任人。
56. 度量四层：业务、模型、系统、工程。
57. 效果要有基线与目标，没有基线免谈提升。

**六、案例实战要点**

58. 局部贪心失效先查目标函数错配，再谈算法优劣。
59. 全网耦合目标必须把下游溢出算进上游决策。
60. 抽样下发必须全覆盖，未抽样路口要有兜底规则。
61. 在线轻量模型须由离线全量回灌校正，防整体回退。
62. 影响传播只走受影响子图，摊还代价降一数量级。
63. 在线离线必须资源隔离，共用队列必被打穿。
64. 降级不是过期数据照用，要标注时间转人工。
65. 强时效场景不接受过期策略，降级须写触发恢复条件。
66. 倾斜治理靠再分区与去屏障，不是靠加机器。
67. 其他区空转等待 = 全局同步屏障问题。
68. 应急调度先可行后最优，超窗用惩罚不用违反。
69. 跨区支援用网络流，人员资质先过滤再优化。
70. 短期限只承诺近优解，效果口径必须与基线对照。
