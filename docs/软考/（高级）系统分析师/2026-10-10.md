## 今日核心概念

### 1. 遗留系统演化策略
定义：遗留系统演化策略是分析遗留系统在业务价值、技术质量、风险与成本四维度上的现状，识别可改造、可继承、可淘汰、可替换的子系统，并选择渐进式、整体式或并行式改造路径的方法体系。
关键要点：
- 业务价值与技术评估采用四象限矩阵划分为改造、继承、淘汰、集成四类，避免一刀切。
- 演化策略分淘汰、继承、改造、集成四类，分别对应业务终结、封装复用、重新开发、接口桥接。
- 改造路径包括抽象分支、绞杀者模式、修缮者模式，并按业务优先级分阶段推进。
- 演化过程必须保留数据迁移、回退机制和并行运行验证，避免单点失败。
- 治理层面应明确产品经理、架构师、运维、业务四方职责，建立持续演进机制。

### 2. 抽象分支与绞杀者模式
定义：抽象分支是通过在遗留系统前构建代理层、抽象接口和防腐层，使新旧系统并行运行并逐步迁移；绞杀者模式是通过门面、网关、消息路由逐步把遗留系统功能替换为新系统，直至遗留系统被完全绞杀。
关键要点：
- 抽象分支的核心是接口先行，实现可替换，常用六边形架构、依赖倒置和适配器模式落地。
- 绞杀者模式通过 Facade 门面接收请求，按路由规则逐步将流量迁移到新系统。
- 二者均需并行运行并做双写对账，避免数据漂移和业务断点。
- 迁移过程中必须保留遗留系统的可观测性和回退能力。
- 适合大型单体到微服务、单机到分布式的渐进式演进。

### 3. 修缮者模式与并行运行
定义：修缮者模式是在保留遗留系统整体结构的前提下，对关键模块、性能瓶颈、安全风险和可维护性问题逐步进行局部替换和优化；并行运行是新旧系统同时对外提供服务，按业务、地域、租户或流量比例逐步切流。
关键要点：
- 修缮者适合无法一次性替换、价值仍高但局部问题突出的遗留系统。
- 修缮顺序应按风险、价值、依赖关系排序，从高收益低风险模块开始。
- 并行运行需要统一身份、统一数据视图、统一监控、统一告警。
- 双写对账机制是并行运行的核心，包括写入双写、读取双轨、差异比对和补偿修复。
- 切流策略支持灰度、蓝绿、按租户切流和按地域切流，每种策略均需独立演练。

### 4. 数据迁移与一致性治理
定义：数据迁移是将遗留系统的存量数据按新系统模型和业务规则进行抽取、转换、加载和校验的过程；一致性治理是在迁移过程中保障新旧系统数据一致、不丢失、不漂移、不重复的方法集合。
关键要点：
- 数据迁移应遵循评估、清洗、映射、转换、加载、校验、对账七个阶段。
- 迁移策略分为一次性切换、分批切换、增量同步和双写渐进四类。
- 数据校验包括总数校验、关键字段校验、抽样校验和对账校验。
- 数据漂移常由时区、空值、主键冲突、外键缺失和编码差异引起。
- 迁移过程应保留原始数据快照、回滚预案和差异修补脚本，确保可回退。

### 5. 架构治理与持续演进
定义：架构治理是对系统架构决策、组件依赖、技术债务和演化路径进行制度化、流程化管理的体系；持续演进是建立在反馈、度量、复盘和变更机制上的渐进式架构优化活动。
关键要点：
- 架构治理通过架构评审委员会、架构原则、技术雷达、参考架构和编码规范实现。
- 技术债务要量化、可视化，按影响、修复成本和业务风险分级管理。
- 持续演进依赖度量、监控、用户反馈、事件复盘和趋势分析形成闭环。
- 治理过程应区分强制项、推荐项和禁止项，平衡标准与团队自主权。
- 持续演进应纳入项目集管理和产品路线图，避免被单一项目割裂。

## 案例分析题

**题目**：某省人社厅"社保核心业务系统"运行已 12 年，采用单体架构、J2EE/Struts + Oracle 11g，覆盖养老、失业、工伤、医疗和参保征缴五大业务，日均交易 800 万笔。近三年系统逐步出现以下问题：
1. 系统响应慢，年度结算期业务办理从 1.2 秒退化至 4.5 秒，并发用户峰值达到 6000 后频繁超时。
2. 核心 jar 包已 EOL，框架升级窗口小，任何一次升级均需停机 6 小时以上。
3. 业务部门要求新增电子凭证、电子签章、跨省通办和个人养老金四大新业务，但现有架构无法支撑快速上线。
4. 数据中心仅有一个主数据中心，发生过两次因存储控制器故障导致业务中断 4 小时和 2 小时的故障。
5. 数据库大表超 8 亿行，缺少有效分区和归档机制，索引维护和统计信息更新耗时过长。
6. 系统中包含 200 多个历史模块，源码注释不全，文档缺失，关键业务逻辑分散在 15 个不同代码片段中。
7. 已发生两次外部接口联调失败事件，由于接口协议不统一、数据规范不清晰导致联调延期。
8. 项目组希望一次性将系统重构成微服务架构，但业务部门担心切换风险且要求业务连续。

请回答：
1. 对该遗留系统进行业务价值与技术四象限评估，并给出子系统分类结果。
2. 设计整体演化策略，包括淘汰、继承、改造、集成四类策略的具体应用。
3. 给出渐进式架构演进方案，说明抽象分支、绞杀者模式、修缮者模式和并行运行的组合使用。
4. 制定数据迁移与一致性治理方案，包括迁移策略、双写对账、回退机制和数据校验。
5. 提出架构治理与持续演进机制，包括治理组织、技术债务管理、变更流程和度量体系。

**参考答案**：

1. 业务价值与技术评估结果：
- 养老、失业、工伤、医保核心结算：业务价值高、技术质量中等、风险中等，归为改造类。
- 个人参保征缴、缴费基数年结：业务价值高、技术质量低、风险高，归为改造或重建类。
- 历史报表、纸质档案扫描等模块：业务价值低、技术质量低，归为淘汰或封装继承。
- 跨省通办、电子签章、电子凭证：业务价值高、技术缺失，归为新建集成。
- 老旧工作流引擎、消息中间件、报表引擎：业务价值中等、技术债务高，归为继承+替换。
- 单数据中心、Oracle 11g、Struts 框架：技术支撑高风险，归为基础设施改造。
- 治理结果：四类策略覆盖范围明确，避免一次性大爆炸式改造。

2. 整体演化策略：
- 改造类：对养老、工伤、医保等核心业务，采用绞杀者模式逐步替换为微服务。
- 继承类：对报表引擎、消息中间件、权限组件进行封装抽象，保留资产并对外提供 API。
- 集成类：对电子签章、电子凭证、跨省通办等新业务，新建微服务并通过 API 网关集成。
- 淘汰类：对长期不用的纸质档案扫描模块、历史报表和老旧工作流，按计划下线归档。
- 策略组合强调渐进、分批、可回退，避免业务连续性风险。

3. 渐进式架构演进方案：
- 第一阶段搭建 API 网关、注册中心、配置中心、监控中心和统一认证，形成新架构底座。
- 第二阶段按业务域拆分，对电子凭证、电子签章、个人养老金等新业务新建微服务。
- 第三阶段对核心业务采用绞杀者模式，将 Facade 部署在旧系统前，按租户、地区和业务逐步切流。
- 第四阶段对老旧核心模块采用修缮者模式，逐步拆分性能瓶颈、安全风险和高耦合模块。
- 第五阶段逐步关停旧模块、压缩旧数据库、迁移数据到新平台。
- 全过程配合灰度发布、蓝绿部署、流量回放和金丝雀验证。
- 关键切换需采用双写、对账、补偿、回退和验证五件套。

4. 数据迁移与一致性治理方案：
- 迁移策略采用分批切换+增量同步，先迁移低风险模块，再迁移高并发核心。
- 数据库切换采用 Oracle 12c/19c 升级、逻辑迁移、GoldenGate 实时同步、binlog 增量同步组合。
- 迁移前进行数据评估、清洗、字段映射、主外键重建、编码统一和空值治理。
- 双写机制：新旧库并行写入，按业务对账、字段对账和总数对账。
- 对账机制：T+1 全量对账+小时级增量对账+异常告警+补偿修复。
- 校验机制：迁移前快照、迁移中校验、迁移后抽样、业务验证。
- 回退机制：保留旧系统只读访问、原始数据备份、应急回切脚本。
- 风险防控：迁移演练、关键切换双人复核、灰度验证和 7×24 小时观察窗口。

5. 架构治理与持续演进机制：
- 治理组织：成立架构评审委员会，涵盖首席架构师、技术负责人、安全负责人、业务负责人和运维负责人。
- 治理制度：制定架构原则、技术雷达、参考架构、编码规范、API 规范、数据规范。
- 技术债务：建立技术债务登记册，按影响、修复成本、风险三维度排序，制定分期偿还计划。
- 变更流程：变更分级、变更评审、变更窗口、变更窗口演练、回退方案和双人复核。
- 度量体系：监控响应时间、错误率、并发数、可用度、技术债务指数、缺陷密度和发布频率。
- 复盘机制：每次重大事件、变更和故障均形成复盘报告，更新知识库和度量指标。
- 持续演进：纳入项目集管理、年度架构评估、半年度技术雷达刷新、月度度量评审。

**踩分要点**：
- 第1问必须按业务价值、技术质量、风险、依赖四维评估，并明确四类策略覆盖范围。
- 第2问应包含淘汰、继承、改造、集成四类策略的具体应用，避免空泛描述。
- 第3问应说明抽象分支、绞杀者模式、修缮者模式、并行运行的组合使用，并强调灰度与回退。
- 第4问必须写明双写、对账、补偿、回退、校验、风险防控六要素。
- 第5问应包含架构评审委员会、技术债务登记、变更流程、度量体系、复盘机制五项内容。

## 记忆口诀

**四象限评估口诀**：价值高低与技术强，四象限里定方向；改造继承集成淘汰，分类施策不乱忙。

**四类策略口诀**：淘汰下线封存好，继承封装加抽象；改造重做要渐进，集成新建接通道。

**绞杀者模式口诀**：Facade 门面接流量，路由逐步切新堂；并行运行双写对账，业务不中断，迁移不慌张。

**修缮者模式口诀**：整体保留局部修，性能安全优先修；按序推进分批上，回归验证不遗漏。

**数据迁移口诀**：评估清洗到转换，加载校验再对账；双写补偿和回退，迁移数据稳如山。

**架构治理口诀**：评审委员会立规，技术雷达指方向；技术债务量化管，度量复盘持续长。
