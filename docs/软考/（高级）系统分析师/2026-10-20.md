## 今日核心概念

### 1. 企业架构与 TOGAF ADM

定义：企业架构（EA）是描述企业"长什么样、怎么运转"的整体蓝图，由业务架构、数据架构、应用架构、技术架构四层组成；TOGAF（开放集团架构框架）的 ADM（架构开发方法）是用九步循环把业务与 IT 统一到同一架构规划中的方法论。
关键要点：
- 四层架构自上而下：业务架构（能力、流程、组织、价值主张）→ 数据架构（数据模型、主数据、生命周期）→ 应用架构（应用分解、复用、集成）→ 技术架构（中间件、基础设施、技术标准）
- ADM 九步：Architecture Vision → Business Vision & Principles → Capability Baseline → Target Architecture（数据/应用/技术三视图）→ Application & Technology Vision → Technology Architecture & Requirements → Architecture Principles → Transition Architecture（Work Packages 过渡架构）→ Architecture Governance & Requirements
- 三种核心视图：组件视图（与业务主题对应）、标准视图（信息标准、数据标准、技术标准）、矩阵视图（功能—数据—技术对应矩阵，做整合与裁剪）
- 四种架构类型：业务架构、信息架构（数据+技术合并）、解决方案架构、变更架构（Transition）
- TOGAF 与 ADM 之外还有：架构能力成熟度（ACM 成熟度 L1-L5）、架构原则（Principle 句子化可仲裁）、SOA 连续性谱（SOA-参考架构—服务—SOA-实现）
- 记忆口诀：「业务数据应用技，ADM 九步建体系；过渡架构管落地，治理标准定规矩」

### 2. 系统集成与互连技术

定义：系统集成是把分散异构的软硬件系统按业务目标连接为一个整体的技术体系，包含数据集成、控制集成、应用集成与业务集成四个层次。
关键要点：
- 集成层次：基础设施集成→数据集成（ETL、数据联邦、主数据管理）→应用集成→业务流程集成→门户集成→业务智能集成
- 通信方式：文件传输（FTP/SFTP，适用于批量、弱实时）、消息中间件（MQ、AMQP，异步解耦、削峰）、远程过程调用（REST/SOAP/RPC）、数据共享数据库
- 企业服务总线 ESB：路由、协议转换、消息转换、服务编排、企业级安全策略，SOA 核心组件
- API 网关：统一入口、鉴权认证、限流熔断、协议转换、灰度路由、日志审计，是微服务架构的"前端守门员"
- 单点登录 SSO：CAS（票据）、OAuth 2.0 / OpenID Connect（令牌）、SAML（联邦身份），核心目标是"一次登录、处处通行"
- 服务网格 Sidecar：应用无侵入实现 mTLS、流量治理、可观测，Istio/Envoy 是代表
- 集成模式：ESB 中心化 vs API 网关轻量 vs 消息异步 vs 事件驱动；遗留对接首选防腐层（ACL）隔离
- 记忆口诀：「文件批量消息异步，网关统一鉴权限流；ESB 编排协议转，服务网格无侵入」

### 3. 分布式系统与通信机制

定义：分布式系统是由多台独立计算机通过网络互联、共同提供单一系统视图的系统；核心困难是部分故障（partial failure）与无全局时钟。
关键要点：
- 核心问题：异构性、开放性、可伸缩性、连通性、部分故障、并发性——Capistrano 问题（部分故障、并发、无全局时钟、不可预知故障）
- 远程通信模型：同步阻塞（RPC 请求-响应，简单但耦合）、异步消息（队列，削峰解耦）、流式通信（Sparkle/Spark Streaming 类长连接）
- 远程过程调用 RPC 三要素：存根 Stub、协议规范、底层传输；同步与异步 RPC 之分
- 分布式协调原语：心跳检测、故障检测（超时未达 + 不可靠检测 phi 累加器）、Gossip 协议（Merkle 树收敛）
- 选主算法：Paxos（多数派法定人数 3、5、7 最佳性能 5）、Raft（领导者选举 + 日志复制 + 任期号）、ZAB（Paxos 在 ZooKeeper 上的实现）
- 一致性哈希与虚拟节点（解决扩容重分布）、分布式锁（Redlock 争议：应基于 etcd/ZooKeeper 强一致实现，而非 Redis 单节点）、幂等与去重
- CAP → BASE，落地最终一致的五种手段（可靠消息最终一致、CDC binlog、定时对账、分布式补偿 Saga、幂等写入去重）
- 记忆口诀：「三两五七 Paxos 法定，Raft 选leader 任期管日志；一致哈希带虚节点，强一致锁用 etcd ZooKeeper 别用 Redlock」

### 4. 嵌入式与实时系统

定义：嵌入式系统是嵌入到其他系统内部、面向专用场景的计算机系统；实时系统要求在规定时间内给出确定性响应，分为硬实时与软实时。
关键要点：
- 组成三要素：硬件（MCU/DSP/SoC、外设总线 SPI/I2C/CAN）、软件（BSP→驱动→RTOS→中间件→应用）、嵌入式 OS
- 裸机 vs RTOS：无操作系统顺序轮转 vs 任务调度+中断管理；RTOS 内核服务：任务管理、任务同步（信号量/互斥量/事件标志）、定时管理、中断管理、内存管理、通信管理
- 实时性：硬实时（超时即失效，如飞控、汽车制动）、软实时（超时降低服务质量，如视频播放、监控大屏）
- 调度算法：抢占优先级调度（RM 上限 69%、速率单调 RM 可调度条件 ΣCᵢ/Tᵢ ≤ 1）、最早截止期优先 EDF、非抢占式 FCFS/FPS
- 关键约束：响应时间 T = 中断延迟 + 处理延迟 + 排队延迟；WCET（最坏执行时间）分析是硬实时可调度性判定依据
- 轻量协议：MQTT（发布订阅，物联网事实标准）、CoAP（受限设备）、Modbus（工业现场）、CAN 总线（CSMA/CR 多主仲裁）
- 存储与低功耗：Flash 磨损均衡、掉电保护、Watchdog 看门狗、电源管理（休眠/唤醒）
- 记忆口诀：「硬实时误一次就废，软实时超时降质量；实时四要素中断、排队、处理、响应；调度抢占 RM 69%，EDF 用得最广」

### 5. 标准化与信息化法律法规

定义：标准化是国家对信息技术产品、系统、服务的基础要求与统一规范，信息化领域标准体系由国际标准（ISO/IEC）、国家标准（GB/GB/T）、行业标准（MM/T、WS）、地方标准（DB）构成。
关键要点：
- GB/T 22239 等保 2.0：安全通用要求 + 扩展要求（云计算、移动互联、物联网、工业控制）；五个等级（一级自主保护→五级专控）；一个中心三重防护（安全管理中心 + 安全计算环境、安全区域边界、安全通信网络）；技术要求五部分：安全物理环境、安全通信网络、安全区域边界、安全计算环境、安全管理中心 + 管理要求五部分
- GB/T 20984 信息安全风险评估：资产识别→威胁识别→脆弱性识别→风险分析→风险等级判定→风险处置，六步法
- GB/T 35273 个人信息安全规范：告知同意、最小必要、明示目的、境外传输规则
- GB/T 22239.2 关键信息基础设施：定级备案、年度测评、三年一次（密评）、采购安全审查
- 软件著作权与知识产权：著作权+专利权+商业秘密+商标权；职务作品与开源合规（SBOM、许可证传染性 GPL/AGPL）
- 电子政务与数据共享规范：GB/T 21063 政务信息资源目录体系、GB/T 2260 行政区划代码、GB/T 13745 主题词表、统一社会信用代码（GB 32100）
- 记忆口诀：「国标 GB/T、行业 MM/T；等保 2.0 一个中心三重防护五级；风险评估六步：资产、威胁、脆弱、分析、定级、处置」

## 案例分析题

**题目**：

某省政务服务管理局拟建设"一网通办"综合服务平台，实现 50 个省级部门、2000 余项政务事项统一受理、统一办理、统一监管。现状问题如下：

1. 各部门业务系统为不同时期建设、厂商各异、数据标准不统一，事项名称、审批流程、材料清单各不相同，无法横向比对；局方需要先形成覆盖全局的整体规划，明确哪些能力要统一建设、哪些保留部门自建，以及标准如何统一。
2. 已建成"统一身份认证平台"，但各部门系统仍需二次登录，用户体验差；部分系统对外接口文档不完整、对接意愿低，采用方式也不一致（有的网页抓取、有的数据库直连、有的文件交换）。
3. 用户高峰期办件量达日常的 12 倍，平台任务分发接口出现请求堆积；部分批处理类事项处理超过 5 分钟，用户端长时间无反馈后重复提交，产生多笔重复办件。
4. 大厅配置 800 台政务自助一体机（含身份证读取、证照打印、活体检测、人脸比对），需要 7×24 小时不间断运行；某次打印机卡纸故障未被发现，直到第二天巡检才发现当日办件积压 400 余件。
5. 按等保 2.0 三级要求，系统已上线两年，局方拟开展一次风险评估并对不符合项进行整改。

**问题**：

1. 该局应采用什么架构规划方法？请简述其基本流程与产出。
2. 针对上述第 2 点，设计一个统一集成方案，并说明为什么不能继续采用数据库直连与网页抓取。
3. 针对第 3 点的性能与重复提交问题，提出技术改进措施。
4. 针对第 4 点的自助机可靠性问题，说明嵌入式系统层面的设计要点。
5. 说明该系统等保 2.0 三级定级后的测评与整改要点。

**参考答案**：

**第 1 问：企业架构规划方法**

采用 TOGAF 的 ADM（架构开发方法）进行企业架构规划。

基本流程：
- 架构愿景：明确建设目标、范围与关键干系人，形成 Architecture Vision；
- 业务架构：梳理统一受理、统一办理、统一监管三大业务能力，形成能力基线（Capability Baseline），识别重复建设与能力缺口；
- 数据架构：建立事项、审批、材料、办件、证照等主题域模型，统一标准（如事项编码、事项名称、材料清单、办理时限、事项分类编码），建立主数据管理与元数据管理机制；
- 应用架构：对 50 个部门系统按"复用/整合/新建/替换"四类处置，明确应用集成关系与集成方式（API 网关、消息、ETL）；
- 技术架构：统一技术栈、部署形态、终端与自助机技术标准；
- 过渡架构：把目标架构分解为若干过渡态 Work Packages，制定分阶段迁移路线与投资计划；
- 架构治理：设立架构委员会，制定架构原则（如"接口一律走 API，禁止直连数据库"）、技术标准与例外审批流程。

产出：架构愿景、业务能力基线、四层目标架构（业务/数据/应用/技术）、过渡架构与实施路线图、架构原则与技术标准清单、架构评估与治理办法。

**第 2 问：统一集成方案**

方案：在统一身份认证平台与各业务系统之间建设统一集成层，形态为"API 网关 + 消息中间件 + ESB/集成平台"的组合。

- 统一身份入口：采用 OAuth 2.0 / OpenID Connect 令牌机制，以统一身份认证平台为认证中心，业务系统为资源服务器，令牌携带用户标识与权限声明，访问令牌采用短时效 + 刷新令牌；对接入方实施 TLS 双向认证与签名验签；
- API 网关作为唯一对外入口：负责路由、协议转换（REST 与 SOAP 互转）、请求校验、限流、熔断降级、灰度发布与全量日志审计；
- 内部业务系统之间通过消息中间件异步解耦，办理状态变更、办件流转、材料预审结果等以事件消息广播，削峰填谷；
- 对存量、无接口的老系统，采用防腐层（ACL）加适配器封装为标准服务，形成"新系统走 API、老系统包适配"的过渡策略；
- 建立服务目录与接口注册审批机制，接口文档、版本、变更纳入配置管理，接口变更须走变更评审。

不能继续采用数据库直连与网页抓取的原因：
- 数据库直连：绕过业务系统的数据契约与校验逻辑，破坏数据完整性；直连使调用方与库表结构强耦合，表结构一变所有对接方全部受影响；无法做统一鉴权、权限、限流与审计；存在严重安全隐患，直连账号一旦泄露可越权读写全量数据，违反等保 2.0 最小权限与审计要求；无法纳入统一事务、补偿与一致性保障。
- 网页抓取：页面结构随前端改版频繁变化，稳定性极差，接口不可维护；拿不到结构化的业务状态与错误码，只能解析展示文本；性能差、易被限流封禁、存在法律与合规风险；无法保证幂等与事务一致性，重复提交或超时无法判定结果。

**第 3 问：性能与重复提交改进**

- 异步化削峰：办件受理、任务分发、状态回写由同步调用改为消息队列异步处理，入口只做受理与返回受理单号；队列分区保证有序，消费者横向扩展消化峰值 12 倍流量。
- 幂等设计：客户端请求携带唯一请求号（令牌 + 业务键），服务端以 Redis/数据库唯一索引保证幂等；短时间窗口内相同请求直接返回原受理单，不重复创建办件。
- 防重提交：前端按钮提交后置灰 + 倒计时；后端对同一身份证 + 同一事项 + 规定时间窗口内的重复申请做去重校验。
- 结果反馈：将长耗时批处理事项改为"受理—处理中—完成"异步结果模型，通过站内消息、短信、微信公众号推送结果，或提供结果查询接口，前端轮询/WebSocket 推送状态。
- 削峰与保护：令牌桶/漏桶限流保护下游；超时设置合理上限，避免线程长时间占用；熔断降级保证核心事项优先受理；引入任务优先级队列，紧急事项与普通事项分级。
- 性能基线：建立全链路链路追踪与 APM 监控，采集分段耗时与慢 SQL，重点优化数据库索引、连接池与热点数据缓存（本地缓存 + 分布式缓存）。

**第 4 问：嵌入式与实时系统设计要点**

- 实时性判定：打印失败告警属软实时（超时后影响服务质量，可人工补偿），核心办件链路若涉及人脸比对超时判定则需保证可界定的响应时间，不宜按硬实时设计，但需设定最坏执行时间上界与超时降级策略。
- 任务调度：采用 RTOS 调度（抢占优先级 + 定时任务），把身份读取、证照打印、活体检测、页面响应等拆分为独立任务，打印任务优先级高于 UI 刷新与日志上报；严格响应时间 R = 中断延迟 + 处理延迟 + 排队延迟，并对关键任务做最坏执行时间分析。
- 高可用与故障检测：启用硬件 Watchdog 看门狗，看门狗超时自动复位并记录复位原因；关键任务（打印机状态、通信、心跳）采用超时监控与心跳机制，失败自动重试 N 次并上报运维平台。
- 可靠性设计：打印机移动机构、纸路等机械件做寿命与异常统计，提前预警更换；打印失败进入重试队列，重试仍失败则自动转为"后台打印 + 短信通知取件"或人工干预工单。
- 抗干扰与稳定性：电源做稳压与掉电保护（超级电容/掉电保存已完成事务），存储做 Flash 磨损均衡；外设走工业级总线并做电气隔离；系统镜像做 A/B 分区，升级失败自动回滚。
- 7×24 运维：设备统一接入物联网平台做远程监控与批量下发配置，远程心跳与远程日志采集；配置冗余设备与耗材预警，保留一定比例备用机。
- 现场验收：以真实场景压力测试 + 连续 72 小时稳定性测试为验收依据，统计平均响应时间、最大响应时间、故障次数、平均修复时间。

**第 5 问：等保 2.0 三级测评与整改要点**

测评流程：定级备案（专家评审定三级，向公安机关备案）→ 建设整改 → 等级测评（委托测评机构开展等级测评）→ 整改复测 → 监督检查。

按"一个中心、三重防护"检查整改：
- 安全管理中心：建立统一的安全运营/审计中心，账号统一身份认证与权限管理，落实运维审计（谁、什么时间、对哪台设备、执行了什么命令），日志留存不少于 6 个月并具备防篡改与审计追溯能力。
- 安全通信网络：传输加密（TLS/国密算法），内部网络按业务分区做访问控制，重要数据传输完整性与保密性保障。
- 安全区域边界：部署防火墙、入侵防御、边界访问控制，划分不同安全区域并按最小化原则开放端口与白名单；严禁互联网直连业务系统。
- 安全计算环境：主机加固与最小化安装、漏洞修补、恶意代码防护、数据库审计；应用层补充输入校验、会话管理、敏感数据加密与脱敏；关闭不必要的默认账号与调试接口；禁止明文存储密码口令，口令采用加盐哈希。
- 安全管理：安全管理制度、人员培训与考核（安全意识培训）、供应链管理（第三方开发运维管控）、数据分类分级与备份恢复（异地备份、恢复演练）。
- 整改闭环：对照差距分析表逐项整改，形成"发现问题—整改措施—复测证据"闭环文档；对短期无法整改项采取风险补偿措施并制定整改计划。
- 密码应用同步：若系统涉及关键信息基础设施或达到密评要求，需同步开展商用密码应用安全性评估（密评），确保国密算法落地。

**踩分要点**：

- 第 1 问踩分点：答出"TOGAF + ADM"（核心得分）、业务/数据/应用/技术四层架构、四类架构、过渡架构与 Work Packages、架构治理与技术标准、架构原则可仲裁。只答"做架构设计""分层设计"不得分。
- 第 2 问踩分点：写出具体技术组件（统一身份认证 + OAuth/OIDC + API 网关 + 消息中间件 + 防腐层 ACL）；数据库直连理由必须答"破坏数据契约/强耦合/无法审计鉴权/安全与权限越权"，网页抓取理由必须答"页面不稳定/拿不到结构化状态/无事务与幂等保证"，只写"不安全"得分低。
- 第 3 问踩分点：必须同时命中四个关键词——异步削峰、幂等（唯一请求号 + 唯一索引）、长耗时改为异步反馈（消息通知/轮询/推送）、限流熔断与横向扩展。只答"加机器""优化数据库"属低分答案。
- 第 4 问踩分点：先判断软实时/硬实时性质（这是区分度最高的采分点），再答 RTOS 任务划分与优先级、Watchdog 看门狗 + 心跳超时检测、响应时间三段式、掉电保护与 A/B 分区回滚、远程运维与批量监控、72 小时稳定性验收。
- 第 5 问踩分点："一个中心三重防护"五部分（安全管理中心 + 计算环境/区域边界/通信网络）必须逐条对应本题场景写整改措施，尤其点出"内部网络通信加密 + 边界最小化白名单 + 禁止互联网直连 + 账号统一认证与运维审计 + 日志留存 6 个月"；另需写出定级备案—建设整改—等级测评—复测的闭环流程。
- 全题采分倾向：题干每个缺陷点都对应一次"措施 + 理由"的成对作答，只写措施不写理由一般只给一半分。

## 记忆口诀

1. 企业架构四层：业务数据应用技，业务管做什么，数据管怎么存，应用管用什么，技术管怎么跑。
2. ADM 九步：愿景—业务—能力—目标—技术—要求—原则—过渡—治理，过渡架构分工作包。
3. 三种视图：组件贴业务，标准统规范，矩阵做裁剪。
4. 集成层次六级：基础设施、数据、应用、流程、门户、商业智能，一级比一级高。
5. 通信方式三兄弟：文件走批量，消息异步扛，RPC 同步快。
6. 接口直连三宗罪：绕过契约、无法审计、权限失控。
7. 网页抓取三宗罪：页面善变、状态难取、无幂等。
8. 分布式五问：异构开放可伸缩、部分故障难全局时钟；Paxos 三、找五、七最稳。
9. 锁的抉择：强一致用 etcd/ZooKeeper，别用 Redis 单节点 Redlock。
10. 缓存三兄弟：穿透防无效、击穿防热点、雪崩防过期。
11. 最终一致五招：可靠消息、binlog 订阅、定时对账、Saga 补偿、幂等去重。
12. 实时二分：硬实时误一次报废，软实时超时降质量；响应时间三段拆：中断 + 处理 + 排队。
13. 调度两条路：速率单调上限 69%，最早截止期 EDF 最通用。
14. 嵌入式可靠性三件套：看门狗复位、心跳超时重试、远程运维批量管。
15. 升级安全靠 A/B：双分区切换，失败自动回滚，掉电保护靠电容。
16. 等保口诀：一个中心三重防护，安全技术五要素，定级备案测评复测四步走。
17. 风险评估六步：资产识别、威胁识别、脆弱性识别、风险分析、风险定级、风险处置。
18. 技术选型一句话：老系统防腐层包适配，新系统 API 网关统一走，异步消息削峰扛峰值。
