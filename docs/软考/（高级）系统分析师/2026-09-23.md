## 今日核心概念

### 1. 结构化分析（SA）核心思想
定义：结构化分析是一种面向数据流的需求分析方法，采用"自顶向下、逐层分解"的方式，将复杂的系统功能分解为可管理的小块，强调数据流和数据结构的抽象建模，是软件开发生命周期中"做什么"的关键建模技术。
关键要点：
- 三大模型：数据流图（DFD）描述"做什么"、数据字典（DD）定义"数据是什么"、结构化语言/判定树/判定表描述"怎么做"
- 核心原则：抽象（忽略细节）、分解（分层处理）、模块化（高内聚低耦合）
- 建模阶段：现行系统物理模型→现行系统逻辑模型→目标系统逻辑模型→目标系统物理模型
- 与面向对象分析（OOA）的对比：SA基于功能分解，OOA基于对象封装；SA适合数据处理型系统，OOA适合业务复杂的现代系统
- 阶段产物：需求规格说明书（SRS）、数据流图、数据字典、判定表/树

### 2. 数据流图（DFD）四要素与分层
定义：数据流图是结构化分析的核心图形化工具，描述系统的逻辑模型（即系统做什么而不关心如何实现），由四种基本符号组成，通过分层（Context图→0层→1层→...）逐层细化数据加工过程。
关键要点：
- 四要素：外部实体（E，方框）、加工（P，圆圈或圆角矩形）、数据存储（D，开口矩形/横线）、数据流（→，带箭头的线）
- 分层规则：Context图（顶层）只画一个加工表示整个系统，与外部实体直接交互；0层图将顶层加工分解为若干主要子加工；逐层分解保持父图与子图平衡（输入输出数据流一致）
- 数据守恒：每个加工的所有输入数据流必须被加工产生输出（不能有输入无输出，也不能凭空出现输出）
- 命名规范：加工用"动词+宾语"（如"计算工资"），数据流用名词（如"员工信息"），数据存储用名词（"订单表"）
- 与UML活动图的区别：DFD强调数据视角（数据在系统中的流动），活动图强调控制视角（流程的顺序与分支）

### 3. 数据字典（DD）
定义：数据字典是与DFD配套的、用于精确定义系统中所有数据元素的词典，对DFD中的数据流、数据存储、加工的输入输出数据进行形式化描述，是需求分析阶段"数据契约"的标准化产物。
关键要点：
- 四类条目：数据流条目、数据存储条目、数据项条目（字段）、加工条目（处理逻辑）
- 数据项定义三要素：数据类型、长度、取值范围（如"员工编号：字符型，6位，范围000001-999999"）
- 符号约定：等号"="表示定义为、加号"+"表示连接、方括号"[]"表示可选、竖线"|"表示选择、大括号"{}"表示重复、m..n表示重复次数
- 示例：员工档案=[员工编号+姓名+部门+基本工资+奖金+扣除]，姓名=字母字符{字母字符}
- 与数据库DDL的区别：DD是面向需求的业务数据定义（与实现无关），DDL是面向实现的物理表结构定义；DD是DDL的设计输入
- 维护原则：DFD修改时必须同步更新DD，保持数据定义的一致性

### 4. 结构化设计（SD）模块设计
定义：结构化设计是在结构化分析基础上进行的"如何做"的设计技术，将SA得到的DFD转化为软件的模块结构图（MSD），强调模块独立性，追求高内聚低耦合，是面向过程软件设计的核心方法。
关键要点：
- 变换型 vs 事务型分析：从DFD判断系统类型，变换型（输入→处理→输出）采用"变换分析"映射为模块结构，事务型（中心调度分流）采用"事务分析"映射
- 模块独立性度量：内聚（模块内部元素的关联程度，7级由低到高）+耦合（模块间连接的松紧程度，7级由低到高）
- 设计优化原则：模块大小适中（扇出≤7）、深度合理（不超过5层）、作用域在控制域内、降低接口复杂度
- 模块结构图（MSD）四要素：模块（方框）、调用（→）、数据传递（实心圆=数据，空心圆=控制标志）、选择/循环结构（菱形）
- 与面向对象设计的区别：SD基于功能分解形成模块调用树，OD基于对象抽象形成类继承/关联图；SD适合计算密集型，OD适合业务复杂型

### 5. 业务流程建模（BPMN）
定义：BPMN（Business Process Model and Notation）是OMG制定的业务流程建模标准，通过一组标准化的图形元素描述业务流程的编排、协作和消息流，是企业流程治理和系统分析阶段"跨组织/跨系统流程建模"的主流方法。
关键要点：
- 五大基本元素：事件（圆圈，圆头=开始/收尾）、活动（圆角矩形，子流程=矩形+下边框）、网关（菱形，决策/合并）、流（实线箭头=顺序，虚线箭头=消息）、池与道（Pool/Lane划分责任主体）
- 网关类型：排他网关（XOR，单路径）、并行网关（AND，多路径并发）、事件网关（基于事件的路径）、复杂网关（自定义条件）
- 与DFD的区别：BPMN强调跨角色协作和流程编排（含人工/自动任务、消息、超时等），DFD强调系统内数据加工；BPMN是流程视角，DFD是数据视角
- 与UML活动图的区别：BPMN面向业务流程分析师（含业务补偿、消息流、池道等业务概念），活动图面向系统开发者（侧重对象行为与状态）；BPMN是业务建模，活动图是系统建模
- 落地工具：Camunda、Flowable、Activiti等BPMN 2.0执行引擎支持建模→执行→监控一体化

## 案例分析题

**题目**：某银行拟开发"信用卡额度智能调整系统"，通过分析客户收入、消费、负债等数据，结合风控模型动态调整授信额度。项目组采用结构化分析与设计方法（SA/SD），请回答下列问题：
1. 请绘制该系统顶层（Context）数据流图，并指出图中应包含哪些四要素符号？
2. 数据字典中"客户信用评分"数据项应如何定义？请用符号约定写出至少5个数据项的组合定义式。
3. 若系统主要加工为"输入客户数据→风控模型计算→输出额度调整结果"，属变换型DFD，请说明变换分析映射为模块结构的主要步骤。
4. 现有两个备选模块：A模块内部各元素为顺序执行的"打开连接→读取数据→关闭连接"，B模块内部各元素为完成"计算订单总价"单一功能。请判断A、B的内聚类型，并说明哪种更优。

**参考答案**：
1. Context图包含：外部实体（"客户"方框、"核心系统"方框）、一个中心加工（"信用卡额度智能调整系统"圆圈）、数据流（客户→系统："客户收入/消费/负债数据"；系统→客户："调整后额度通知"；核心系统→系统："客户基础信息"；系统→核心系统："额度调整指令"）。四要素齐全：外部实体、加工、数据存储（本层可省略）、数据流。
2. "客户信用评分"定义为：客户信用评分=数字型，长度3位整数，取值范围300-850（人行征信标准）。组合定义式示例：①客户信息=[客户编号+姓名+身份证号+月收入+负债总额]；②月收入=数字{1..7}位，取值≥0；③负债总额=数字{1..9}位，取值≥0；④客户信用评分=计算函数{月收入、负债总额、消费记录}；⑤额度调整结果=[客户编号+原额度+新额度+生效日期]。
3. 变换分析映射步骤（共6步）：①确定DFD的输入流、变换中心、输出流（边界划分）；②设计顶层和第一层模块（输入模块→变换中心模块→输出模块，主控模块调度）；④自顶向下设计输入分支模块（"取得客户数据"）；⑤自顶向下设计输出分支模块（"输出调整结果"）；⑥自顶向下设计变换中心模块（"风控模型计算"为加工核心）；⑦优化模块（合并/拆分，调整扇出）。
4. A模块三个元素"打开连接→读取数据→关闭连接"必须按特定顺序执行，属于过程内聚（procedural cohesion）；B模块"计算订单总价"单一功能，属于功能内聚（functional cohesion）。功能内聚是最高内聚等级（7级），过程内聚属中低内聚（4级），因此B模块内聚性更强，更优。

**踩分要点**：
- 第1题：必须包含外部实体（客户、核心系统）、中心加工、数据流三类符号，数据流方向和命名要正确（不能漏标箭头方向）。
- 第2题：数据项三要素（类型+长度+取值）必须齐全，符号约定要用对（=、+、[]、{}），至少5个组合式覆盖主实体、字段、复合数据、加工逻辑。
- 第3题：6个步骤顺序不能乱，"输入→变换中心→输出"的三段划分是核心，自顶向下逐层映射是关键。
- 第4题：内聚7级排序要记清（功能>顺序>通信>过程>时间>逻辑>偶然），功能内聚=单一功能最强，过程内聚=顺序执行次之。判断依据是"是否必须按特定顺序执行"。

## 记忆口诀

**结构化分析四件套**：SA三模DFD/DD/判（数据流图/数据字典/判定工具）—SA建模两阶段（现行→目标，两种模型：物理→逻辑）

**DFD四要素口诀**：外加存流（外部实体E、加工P、数据存储D、数据流→），分层Context→0→1→n（顶层到细节），父图子图守恒

**DD四类条目**：流存项加（数据流、数据存储、数据项、加工），符号约定：=定+连[]选|择{}复

**模块设计三原则**：内聚要高、耦合要低、扇出要小（≤7），深度要浅，变换事务两型映射

**内聚七级排序（由低到高）**：偶然逻辑时间过程通信顺序功能（口诀：巧（偶）洛（逻辑）鸡（时间）是（过程）公（通信）序（顺序）功（功能））

**耦合七级排序（由低到高）**：非标记数据控制外部公共内容（口诀：非标控外公公内——非直接/标记/数据/控制/外部/公共/内容）

**SA vs OOA对比口诀**：SA分解功能DFD为核，OOA抽象对象UML为基

**BPMN五元素**：池道流网活事（池/道、流、网关、活动、事件）——业务建模BPMN，系统建模活动图
