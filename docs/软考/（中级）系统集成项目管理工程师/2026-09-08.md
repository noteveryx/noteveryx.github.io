## 今日核心概念

### 1. 项目管理五大过程组与十大知识领域
定义：项目管理五大过程组是启动、规划、执行、监控、收尾的PDCA循环；十大知识领域是整合、范围、进度、成本、质量、资源、沟通、风险、采购、干系人管理，两者交叉构成项目管理知识体系。

关键要点：
- 五大过程组关系：启动（授权项目）、规划（制定路线图）、执行（按计划实施）、监控（测量偏差纠偏）、收尾（关闭项目或阶段）；监控过程组贯穿全程
- 启动过程组两过程：制定项目章程（授权PM+高层级需求）、识别干系人（识别受影响方+分析期望）
- 规划过程组二十二过程：核心规划（范围/进度/成本/质量/资源/沟通/风险/采购/干系人）+ 辅助规划（整合+需求+活动定义/排序/资源/历时估算/进度/成本估算/预算/质量/资源/沟通/风险/采购/干系人参与规划）
- 执行过程组八过程：指导与管理项目工作、管理团队、实施采购、管理干系人参与、实施质量保证、管理沟通、实施风险应对
- 监控过程组十二过程：监控项目工作、整体变更控制、范围确认/控制、进度控制、成本控制、质量控制、资源/沟通/风险/采购/干系人参与监控
- 收尾过程组两过程：结束项目或阶段、结束采购
- 十大知识领域速记：整合（Integration）+范围（Scope）+进度（Schedule）+成本（Cost）+质量（Quality）+资源（Resource）+沟通（Communication）+风险（Risk）+采购（Procurement）+干系人（Stakeholder）
- 中级系统集成项目管理工程师考纲重点：十大领域49个过程（高级为47个过程）覆盖80%考题，需熟练掌握每个过程的输入输出工具技术（ITTO）
- 过程间逻辑：启动→规划→执行→监控→收尾，监控贯穿全过程；每个过程的输出可能是另一个过程的输入（如项目章程是规划阶段多个过程的输入）
- 与PMBOK对应：系统集成项目管理工程师考纲基本对齐PMBOK第6/7版，部分过程命名调整需注意

### 2. 项目范围管理与WBS工作分解结构
定义：项目范围管理是确保项目包含且仅包含为完成项目目标所需全部工作的过程；WBS工作分解结构是范围管理核心工具，将项目可交付成果按层次分解为更小、更易管理的组成部分。

关键要点：
- 范围管理六大过程：规划范围管理（制定范围管理计划+需求管理计划）、收集需求（记录并管理干系人需求）、定义范围（制定项目范围说明书）、创建WBS（分解可交付成果）、确认范围（干系人验收可交付成果）、控制范围（监控范围状态管理变更）
- WBS创建方法：自上而下分解（从项目目标逐层分解到工作包）、自下而上汇总（识别工作包后归类组合）；常用分解维度：可交付成果（产品导向）、项目阶段（时间导向）、项目组织（部门导向）
- WBS 100%原则：所有WBS层级之和必须100%覆盖项目全部工作，不多也不少
- WBS分解层次：典型4-6层（项目→阶段→工作包→活动→任务）；工作包是最底层可管理可估算可分配单位
- WBS分解标准：8/80原则（每层8±0个节点，工作包粒度80小时以内或8小时以上）；每个工作包必须有明确的责任人
- WBS编码体系：常见方式1.1.1.1四段式，1代表主项目、1代表第一阶段、1代表第一个工作包、1代表第一个活动
- WBS与WBS字典：WBS是可视化结构图，WBS字典是每个工作包的详细说明（负责人、估算工期、交付物、验收标准）
- 范围基准三大件：范围说明书+ WBS + WBS字典，范围基准经CCB批准后所有变更必须走变更控制流程
- 范围确认 vs 范围控制：范围确认关注"可交付成果的验收"（干系人签字确认），范围控制关注"范围变更的监控"（避免范围蔓延Scope Creep和范围镀金Scope Gold Plating）
- 范围蔓延与镀金：范围蔓延是未经控制的范围扩大（多做了不该做的），范围镀金是主动做了客户没要求的功能（多做了没必要的）

### 3. 进度管理与关键路径CPM
定义：进度管理是确保项目按时完成的过程组；关键路径 CPM（Critical Path Method）是网络图中工期最长、决定项目最短工期的路径，是进度管理的核心方法。

关键要点：
- 进度管理七大过程：规划进度管理、定义活动（识别具体工作）、排列活动顺序、估算活动资源、估算活动持续时间、制定进度计划、控制进度
- 进度管理工具三件套：WBS分解（活动定义基础）、PDM前导图法（4种依赖FS/FF/SS/SF）、PDM优先图节点法（活动用方框，依赖用箭头）
- 四种活动依赖关系：FS（Finish-Start，完成-开始，最常用）、FF（Finish-Finish，完成-完成）、SS（Start-Start，开始-开始）、SF（Start-Finish，开始-完成，少用）
- 关键路径六时参数：ES最早开始、EF最早结束、LS最晚开始、LF最晚结束、TF总时差（LS-ES或LF-EF）、FF自由时差（不影响紧后活动最早开始的时差）
- 关键路径特征：网络图中TF=0的活动链为关键路径，可能有多条关键路径，关键路径决定项目最短工期
- 关键路径计算法：正推法计算ES/EF（取最大）、逆推法计算LS/LF（取最小），关键路径是所有TF=0的活动链
- 进度压缩两大方法：赶工（Crash，加资源缩短关键路径活动工期，成本增加）；快速跟进（Fast Tracking，并行执行关键路径活动，风险增加返工可能）
- 进度表示工具：甘特图（横道图，时间-任务二维可视化）、里程碑图（关键节点标记）、网络图（活动依赖关系）
- 工期估算方法：类比估算（自上而下，快速但不精确）、参数估算（基于历史数据数学模型）、三点估算（PERT 三角分布 PERT=(O+4M+P)/6）、自下而上估算（精确但耗时）
- 浮动与时差：总时差是活动可推迟的总时间（不影响项目总工期），自由时差是不影响紧后活动最早开始的时差
- 资源优化两方法：资源平衡（可能改变关键路径）、资源平滑（不影响关键路径）

### 4. 成本管理与挣值分析EVM
定义：成本管理是确保项目在批准的预算内完成的过程组；挣值分析 EVM（Earned Value Management）是综合范围、进度、成本三维度的绩效测量技术。

关键要点：
- 成本管理四过程：规划成本管理、估算成本、制定预算、控制成本
- 成本类型四件套：直接成本（人工/材料/设备）、间接成本（管理/办公/水电）、固定成本（折旧/房租）、可变成本（材料/计件工资）
- 成本估算方法：类比估算（粗略）、参数估算（数学模型）、自下而上估算（精确）、三点估算（PERT）、储备分析（应急储备+管理储备）
- 成本基准 = 管理储备 + 成本基准（控制账户 + 工作包成本估算 + 应急储备）；管理储备不纳入成本基准但属项目总预算
- 挣值三核心指标：PV 计划值（Planned Value，按计划应完成工作的预算成本）、EV 挣值（Earned Value，实际完成工作的预算成本）、AC 实际成本（Actual Cost，实际完成工作的实际成本）
- 挣值四偏差指标：SV = EV - PV（进度偏差，>0提前<0滞后）、CV = EV - AC（成本偏差，>0节约<0超支）
- 挣值四绩效指数：SPI = EV/PV（进度绩效，>1提前<1滞后）、CPI = EV/AC（成本绩效，>1节约<1超支）
- 挣值预测四指标：EAC = BAC/CPI（完工估算，当前绩效延续）、ETC = EAC - AC（剩余工作估算）、VAC = BAC - EAC（完工偏差）、TCPI = (BAC-EV)/(BAC-AC)（完工尚需绩效指数，>1难<1易）
- 完工预测公式变体：EAC = BAC/CPI（典型）、EAC = AC + BAC - EV（典型）、EAC = AC + (BAC-EV)/(CPI×SPI)（需同时改进进度和成本）
- 应用示例：项目BAC=100万，AC=60万，EV=50万，PV=80万。SV=50-80=-30（进度滞后30万）、CV=50-60=-10（成本超支10万）、SPI=50/80=0.625（进度落后）、CPI=50/60=0.833（成本绩效0.833）、EAC=100/0.833≈120万（预测完工成本120万）
- 储备金管理：应急储备（已知风险预留，包含在成本基准中）、管理储备（未知风险预留，不包含在成本基准中）；储备使用需走变更流程

### 5. 项目质量管理七种工具
定义：质量管理七种基本工具是质量规划、质量保证、质量控制过程中常用的结构化分析工具，又称"老七工具"；新七工具侧重于PDCA计划阶段。

关键要点：
- 质量管理三过程：规划质量管理（制定质量标准）、管理质量（QA过程审计、过程改进）、控制质量（QC产品检验、缺陷修复）
- 老七工具之因果图（鱼骨图石川馨图）：找出问题根本原因，4M1E人机料法环；使用方法：明确问题→确定大类→细化原因→识别根本原因
- 老七工具之流程图：展示过程步骤与决策点，识别质量问题可能环节；用于过程分析与优化
- 老七工具之核对单（Checklist）：基于历史经验的项目质量检查表，防止漏项
- 老七工具之帕累托图（二八法则图）：按问题频次降序排列柱状图+累计百分比折线；用于识别关键少数（占80%问题的20%原因）
- 老七工具之直方图：展示数据分布形态，判断过程能力是否稳定（正态分布为稳定）
- 老七工具之控制图：监控过程稳定性，控制线UCL/LCL均值±3σ；七点法则（同侧7点连续上升或下降判断为非随机）
- 老七工具之散点图：分析两个变量之间的相关性
- 新七工具之亲和图：归类汇总散乱想法，用于头脑风暴后整理
- 新七工具之关联图：展示多因素复杂因果关系，比鱼骨图更适合多目标问题
- 新七工具之树状图：分解目标到可执行任务，类似WBS
- 新七工具之矩阵图：展示多组数据之间的关联强度（L型/T型/Y型/X型）
- 新七工具之优先矩阵（PDPC过程决策程序图）：识别风险并制定应对方案
- 新七工具之活动网络图：项目活动排序与时间安排，类似网络图
- 新七工具之箭线图（ADM箭线图法）：网络图另一种表示方法，活动用箭头表示
- 七种工具应用阶段：因果图/流程图/核对单用于规划阶段；帕累托图/直方图/控制图/散点图用于控制阶段
- 质量与等级区别：质量是满足需求的程度，等级是功能特性多少；低质量是问题，低等级不一定是问题
- 预防胜于检查：质量应预防在前而非检查在后，检查成本远高于预防
- COQ质量成本：预防成本（培训/文档/设备）+ 鉴定成本（测试/检查）+ 内部失败成本（返工/废品）+ 外部失败成本（保修/召回/赔偿）；前两类是投入，后两类是损失

## 案例分析题

**题目**：
某政务"一网通办"系统集成项目，合同金额680万元，工期10个月。项目团队15人（项目经理1人+架构师2人+开发8人+测试3人+UI设计师1人）。项目进行到第6个月时，发生以下事件：

1. 项目启动时客户口头要求增加"电子证照"模块（不在原合同范围），项目经理安排开发但未走变更流程；
2. 第3个月一名核心架构师因个人原因离职，知识传承不到位导致新员工走弯路；
3. 第6个月进行挣值分析：PV=420万、EV=380万、AC=460万；
4. 客户在第5个月提出增加"区块链电子证照存证"功能（额外150万合同），但拒绝增加工期；
5. 测试团队发现已交付的"统一身份认证"模块存在严重缺陷但仍按期上线；
6. 第7个月供应商告知关键中间件版本存在安全漏洞，需停服升级；
7. 项目最终延期3个月，超预算180万，扣除合同款30%作为违约金。

问题：
(1) 根据第6个月挣值数据，计算SV、CV、SPI、CPI并分析项目绩效；
(2) 预测EAC（完工估算成本）和VAC（完工偏差），并说明项目当前应采取的纠偏措施；
(3) 该项目在范围、进度、成本、质量四个知识领域分别存在哪些问题？请逐项分析。

**参考答案**：

问题一：挣值分析计算

已知数据：PV=420万、EV=380万、AC=460万

计算过程：
1. 进度偏差 SV = EV - PV = 380 - 420 = -40万（进度偏差-40万，说明项目进度滞后）
2. 成本偏差 CV = EV - AC = 380 - 460 = -80万（成本偏差-80万，说明项目成本超支）
3. 进度绩效指数 SPI = EV/PV = 380/420 ≈ 0.905（SPI<1，说明项目进度效率仅90.5%，每投入1元工时应完成0.905元的进度）
4. 成本绩效指数 CPI = EV/AC = 380/460 ≈ 0.826（CPI<1，说明项目每花费1元仅完成0.826元的工作，成本绩效83%）

绩效分析：
- 双重偏差：SV<0且CV<0，说明项目"进度滞后+成本超支"双重不利
- SPI=0.905 表示完成计划工作量的90.5%，比计划少完成约9.5%
- CPI=0.826 表示项目每花1元仅产出0.826元的工作，资金使用效率偏低
- 当前状态下，项目可能延期且超支，必须立即采取纠偏措施

问题二：EAC预测与纠偏措施

1. 完工估算 EAC（假设当前绩效延续到项目结束）：
   - EAC = BAC/CPI = 680/0.826 ≈ 823万
   - 即项目完工时预计总成本约823万元

2. 完工偏差 VAC：
   - VAC = BAC - EAC = 680 - 823 = -143万
   - 即项目完工时预计超支约143万元

3. ETC 剩余工作估算：
   - ETC = EAC - AC = 823 - 460 = 363万
   - 即剩余工作还需约363万元才能完成

4. TCPI 完工尚需绩效指数（基于BAC）：
   - TCPI = (BAC-EV)/(BAC-AC) = (680-380)/(680-460) = 300/220 ≈ 1.364
   - TCPI>1.0 表示剩余工作必须达到1.364的成本效率才能按原预算完工，难度极大

5. 纠偏措施（成本与进度双重纠偏）：
   - 进度纠偏：
     1. 快速跟进：并行执行原计划串行的活动，缩短关键路径（增加返工风险）
     2. 赶工：投入更多资源到关键路径活动（成本增加）
     3. 资源平衡：调整非关键路径资源支持关键路径
     4. 范围调整：与客户沟通削减非关键功能或调整交付范围
   - 成本纠偏：
     1. 严格控制支出，暂停非必要采购
     2. 提高生产效率（如结对编程、自动化工具）
     3. 替换低绩效资源
     4. 加强质量控制，减少返工
     5. 重新谈判供应商合同
   - 综合纠偏：
     1. 立即召开项目评审会（PM+架构师+测试+客户四方）
     2. 重新审视WBS与进度计划
     3. 建立挣值监控机制（周粒度）
     4. 加强风险预警（每日风险评审）
     5. 与客户充分沟通现状与对策，争取理解

问题三：四知识领域问题分析

一、范围管理问题：
1. 客户口头要求增加"电子证照"模块，项目经理未走变更流程直接开发，违反范围变更控制流程（变更申请→影响分析→CCB评审→决策→实施→验证）
2. 范围蔓延（Scope Creep）：未对口头需求进行范围确认，造成范围基准失控
3. 第5个月新增"区块链存证"功能（额外150万合同），客户拒绝增加工期，导致范围扩大但工期不变，进度压力剧增
4. 未建立范围基线（范围说明书+WBS+WBS字典），范围变更无控制基准

二、进度管理问题：
1. SPI=0.905<1，进度滞后9.5%，未及时发现与纠偏
2. 核心架构师离职后未做知识传承，导致新员工走弯路，间接影响进度
3. 客户新增功能但拒绝增加工期，进度压力加剧
4. 未使用关键路径CPM方法识别关键活动，导致赶工和并行实施缺乏依据
5. 挣值监控机制缺失，直到第6个月才做挣值分析，已错过最佳纠偏时机

三、成本管理问题：
1. CPI=0.826<1，成本超支83%效率，未及时发现
2. 项目最终超预算180万，扣除30%合同款即204万，实际损失超过384万
3. 项目经理身兼多职无暇关注成本（"一人两项目"），成本控制缺位
4. 应急储备使用无明确审批流程，可能过度消耗储备
5. 缺乏EAC预测与定期成本基准对比

四、质量管理问题：
1. 严重缺陷仍按期上线，违反"预防胜于检查"原则，QA过程审计失效
2. 质量保证QA未发挥作用，应在上线前发现并阻止
3. 质量控制QC不充分，测试团队未在测试阶段发现严重缺陷
4. DoD完成定义（Definition of Done）执行不严，未达到上线标准仍发布
5. 关键中间件安全漏洞未做风险评估与定期漏洞扫描
6. 架构师离职导致代码知识断层，新员工可能引入更多缺陷

五、综合问题与改进建议：

1. 整合管理问题：
   - 项目经理未走变更控制流程直接开发，违反整合管理原则
   - 缺乏整体变更控制机制（CCB未实质运作）
   - 项目监控力度不足，每月挣值分析不及时

2. 资源管理问题：
   - 核心架构师单点风险，无AB角备份
   - 项目经理一人多项目，精力分散
   - 知识管理机制缺失（知识库/文档化）

3. 沟通管理问题：
   - 客户口头需求未形成书面记录与确认
   - 客户与项目团队对变更影响缺乏共识

4. 风险管理问题：
   - 核心人员离职风险未识别与应对
   - 中间件漏洞风险未识别
   - 需求蔓延风险未识别

5. 采购管理问题：
   - 合同违约金条款过高（30%），设计不合理
   - 中间件供应商SLA不明确

改进建议：
- 项目集/项目群治理：建立PMO统一管理类似项目
- 强制变更控制：所有变更必经CCB五步流程（申请→分析→评审→决策→实施→验证）
- 挣值监控常态化：周粒度挣值分析，红黄绿三色预警
- 质量门禁：建立DoD完成定义与质量门禁，严重缺陷禁止上线
- 知识管理：建立项目知识库，关键岗位AB角备份
- 风险预警：周风险评审会，应急储备+管理储备分离管理
- 合同优化：违约金条款控制在10-20%合理区间
- 沟通机制：周报+月报+里程碑评审+客户四方会议

- TCPI=(BAC-EV)/(BAC-AC)，>1难<1易
