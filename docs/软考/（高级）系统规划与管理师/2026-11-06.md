## 今日核心概念

### 1. 采购策略与合同模式选型

定义：采购策略是项目组在实施启动前对"买什么、怎么买、以什么价格结构买、风险由谁承担"作出的总体决策；合同模式（合同类型）是把这一决策法律化、条款化的工具组合。选型的正确性，决定了项目在 18 个月后是"按图施工"还是"边干边谈"。

关键要点：
1. **自制/外购（Make-or-Buy）分析四问**：①该能力是否属于组织战略核心（如数据主权、算法模型产权、规则解释权）——核心能力不宜整体外包；②内部产能是否可得、峰值是否够用；③全生命周期成本差异（含管理成本、质量风险成本、切换成本，而非仅报价）；④合规与安全风险能否被外部方承担。结论不是永久外购，政务类系统常见稳妥模式是"自建平台 + 委托运营 + 数据与规则留在体内"。
2. **合同类型三条主线**：①**总价类**——固定总价（FFP，价格风险归供方）、成本加固定费用（CPFF）、成本加激励费用（CPIF）；②**成本补偿类**——成本报销 + 管理费，需设费用上限与费率上限；③**工料类**——工时/材料实报实销，需设人工单价与用量上限。信息系统项目的高不确定性需求，常见"固定总价 + 暂定金额（Provisional Sum）+ 里程碑调价条款"三者叠加。
3. **合同模式选型矩阵三因子**：需求确定性高 → 固定总价；成本可估算性低但工作量可计量 → 工料/单价合同；供方与需方愿意共担风险 → 成本补偿 + 激励（CPIF/CPA）。**风险共担不等于风险不分担**，激励系数、目标成本、分享比例必须写死。
4. **风险分配四问法**（考试与实务通用）：该风险是否可被识别？识别后谁更有能力控制？控制成本是否低于转移成本？合同条款是否可验证？四问指向同一结论——**风险应分配给控制力最强、控制成本最低的一方**；无法分配的风险（如政策风险）则通过价格调整条款、免责条款或保险转移。
5. **信息系统项目的六类特有风险与对应条款**：需求不确定性 → 分阶段交付 + 变更计价机制；数据与知识资产权属 → 成果归属、背景知识产权与前景知识产权分离条款；合规与密评责任 → 等保测评、密评责任划分与不通过时的责任转移；云资源弹性与超量 → 云资源配额、账单上限、弹性扩容审批；第三方与开源组件合规 → SBOM 提供义务与侵权赔偿；接口与数据迁移责任 → 迁移范围、源数据质量责任与迁移失败的回退机制。
6. **计价与结算条款五要素**：计价方式（固定价 / 单价 / 成本加费率 / 里程碑）、结算周期与支付节点（预付款比例、里程碑比例、验收比例、质保金比例）、验收与付款的绑定关系、价格调整公式（可调因子：汇率、物价指数、人力成本、税制变化）、以及合同总价的**价格上限与变更累积重谈触发线**。
7. **招采合规红线**（简记即可）：必须招标的适用范围与限额标准；公开招标、邀请招标、竞争性谈判、竞争性磋商、单一来源的适用条件与法定时限；资格条件不得指向特定品牌或地域歧视；不得以"投标保证金+串通投标罪"威慑围标串标；单一来源须履行专家论证与公示程序。

### 2. 供方选择与合同谈判

定义：供方选择是在合同签署前完成"选谁、为什么选、条款谈到什么底线"的一组动作；合同谈判则把选型结论固化为双方权利义务。选型失当的代价在履约期才显现，而**权重与评分标准必须前置写死**，这是最易失分也最易被忽略的点。

关键要点：
1. **采购工作说明书（SOW）与采购管理计划**：SOW 描述"买什么"（范围、交付物、里程碑、服务内容、交付物清单），采购管理计划描述"怎么买"（采购方式、进度安排、供方选择与评审标准、合同类型、变更与索赔规则、履约监督机制、退出安排）。SOW 模糊是后续所有争议的源头。
2. **供方选择标准七维**：价格/成本、技术方案与既往业绩、团队资质与核心人员、地理位置与本地服务响应能力、财务稳健性与履约记录、风险与合规（安全认证、密评、涉密与行业资质）、社会责任（依法纳税、劳动保障、绿色采购与信创适配）。本地化服务能力在运维类项目中权重常被低估，却是 SLA 可达性的物理前提。
3. **加权评分模型五要点**：①**权重与评分细则在招标文件中预设，评标中不得事后调整**（评分标准未细化到可量化是招标争议第一来源）；②评分项不得使用"负分"或"不满足即否决"的模糊表述，应改为门槛条件 + 量化打分；③商务标与技术标分离评审，且技术评审成员不得与投标人存在利益关联并须签字回避；④演示答辩作为技术分的验证手段；⑤评标结果需公示并接受质疑投诉，投诉期间不得定标。
4. **合同谈判七要点**：需求澄清而非需求变更（澄清不改变合同实质，变更必须走整体变更控制）；价格—范围—进度的联动谈判（降价必须换范围或换付款条件，不做单方面让步）；质保金比例与缺陷责任期起算点；违约责任与服务信用扣罚上限（避免惩罚性条款被认定无效）；知识产权归属与许可范围（区分背景 IP、前景 IP、开源组件）；保密与数据安全条款（密钥所有权、审计权、驻场与远程访问边界）；退出与知识转移条款（源数据返还与销毁、人员交接、文档交付、连续 12 个月的过渡支持）。
5. **谈判与变更的边界**：合同签署前是"澄清与收敛"，签署后一切调整必须走**变更控制流程**（提出—评估—审批—执行—记录），不能用"补充协议""会议纪要""微信确认"绕开变更流程，否则变更签证率必然崩塌。
6. **供方分级与履约记录**：战略供方 / 合格供方 / 一般供方 / 观察与淘汰名单；四类违规必查——串通投标、资质挂靠、围标陪标、违规转包与违法分包；建立**供方履约档案**（质量、进度、成本、服务、配合度五维评分），作为下一轮采购的准入依据。

### 3. 合同履约管理与 SLA / KPI

定义：合同履约管理是签约之后，采购方对供方"交付是否符合合同约定"的持续监督、度量、纠偏与结算活动。它与项目管理的区别在于：**项目管理的基准是内部计划，合同管理的基准是双方约定的条款**，二者冲突时以合同为准，调整必须走变更。

关键要点：
1. **履约管理三条线**：交付线（范围—进度—质量—成本达成）、商务线（变更—支付—结算—索赔）、关系线（沟通—满意度—升级—续约）。三条线中，商务线的失控（未签证变更）会以最快速度传导为成本超支。
2. **SLA 四要素**：服务可用性指标、响应时限（受理响应）、解决时限（故障恢复）、服务范围与免责场景。缺任何一项，SLA 都不可执行。必须同时写明：统计口径、统计周期、分母范围（如"可用性 = 1 − 不可用时长/应服务时长"）、采集源（监控平台自动采集优于人工填报）、免责场景（需方基础设施故障、不可抗力、计划内维护须提前 N 小时报备）、扣罚方式与上限。
3. **SLI / KPI / SLA 三层区分**：SLI 是度量指标（可用性、时延、合格率），KPI 是组织内部目标，**SLA 是对外承诺**。合同只写 KPI 会导致履约时无可执行的扣罚依据；合同直接写业务 KPI 而无度量定义，等于没有 SLA。
4. **SLA 分层与服务信用**：按系统重要性分层（核心业务系统 7×24 一级响应，普通办公系统 5×8 二级响应），设分级服务信用（Service Credit）：一般违约扣减当月服务费 1%–5%，重大违约 5%–10%，连续重大违约触发整改、暂停服务直至解除合同；扣罚总额设上限，避免条款被认定为惩罚性而无效。
5. **履约监控四机制**：履约例会（周例会管交付、月度经营会管商务、季度考评管绩效）；阶段评审与里程碑验收（按合同约定的交付物清单逐项核验，缺证据不签认）；度量数据自动化采集（人工填报的数据在争议中不可采信）；履约看板（进度偏差、变更未签证比例、质量合格率、响应达标率、缺陷逃逸率、核心人员变更率六项预警指标）。
6. **绩效与激励挂钩**：把 10%–20% 款项设为绩效浮动部分，挂钩里程碑验收、缺陷修复时效、满意度评分与合规检查结果；同时明确罚则阶梯（扣款—暂停付款—暂停服务—索赔—解除合同）。
7. **人员与技术锁定条款**：核心岗位人员名单写入合同附件，更换须提前 15 日书面报批且须具备同等资历；离岗须完成**交接文档、知识转移、账号与密钥交接**并经采购方书面确认——这是 11-02 案例中"架构师离职无交接文档"的合同化解法。

### 4. 合同变更、索赔与争议管理

定义：合同变更是签约后合同内容的调整，索赔是因对方违约或风险事件而主张补偿，争议是二者无法自行解决时的外部介入。三者共用同一条铁律：**必须有书面、有审批、有计价、有时限**。

关键要点：
1. **变更五步闭环**：变更识别（需求变化、法规变化、环境变化、供方原因）→ 变更评估（范围、成本、进度、质量、风险五维影响分析）→ 变更审批（CCB 或合同约定的审批权限）→ 变更执行（签发变更令 / 合同变更通知，明确价款与工期调整）→ 变更记录（纳入变更日志与配置管理）。**评估与审批分离**：评估由提出方或项目管理团队做，审批由有权人做。
2. **变更计价三规则**：①合同设有单价表时按单价表执行；②无单价表时按"实际成本 + 管理费率"计价，管理费率须在合同中写明；③变更估价方法三选一——类比估算（最快，误差大）、详细估算（最准，成本高）、专家判断（紧急情形）。**累计变更超过合同额约定阈值（常设 5%–10%）时触发合同重谈或单价重议条款**，该阈值必须写入合同，否则变更会无上限累积。
3. **索赔成立三要件**：**事件**（与索赔方无关的违约或风险事件，如供方接口缺陷导致数据错误）→ **因果关系**（事件与损失之间存在可证明的直接因果链）→ **损失量化与证据**（金额或工期损失有客观计量依据）。三要件缺一，索赔不成立。
4. **索赔证据链六件套**：合同及全部附件与附件清单 → 往来函件（索赔通知、催告函、双方回执） → 会议纪要与签认单 → 变更指令与签证单 → 验收记录与计量/工时记录 → 财务凭证与工期影响记录（费用发生凭证、关键路径影响分析报告）。**证据链四性**：完整性、连续性、关联性、可采性。
5. **证据链断链四典型**：①口头承诺无书面确认（"领导说过按这个算"）；②关键节点无签认（现场确认单缺失导致计量无据）；③索赔超期未提（超出合同约定的索赔时限即丧失权利）；④单据缺因果说明（只列费用不说明与事件的关联）。答题时若只答"证据不足"而不能归类到四典型，得分打折。
6. **索赔与反索赔**：供方违约在先，但需方也存在违约（如逾期提供资料、变更未签认导致供方误工），需方对供方提反索赔；双方各自举证，可能出现"净额结算"，净额结算必须双方书面确认，否则按各自金额分别处理。
7. **争议解决四层级与衔接**：协商 → 调解（行业协会/主管部门/第三方调解机构）→ 仲裁 → 诉讼。**技术争议先走专家裁定**（独立工程师、监理单位、单方专家出具技术裁定意见），避免把工程问题拖入法律程序。争议期间遵循"**继续履行 + 保留权利**"原则：项目不停摆，权利不放弃（发出保留权利函，注明"本期结算暂缓，不构成对合同变更的认可"）。仲裁时效 3 年（民法典），需在合同中约定起算点为"争议发生日"而非"结算完成日"。

### 5. 合同收尾、采购绩效复盘与审计留痕

定义：合同收尾是"合同义务全部履行完毕并双方确认无争议"后的系统性关闭过程；采购绩效复盘是对这一次采购的效率、效果与合规性做出结构化评价，并沉淀为下一次采购的组织资产。**采购项目的最后 10% 精力，往往决定了组织能否从一次采购中真正获得能力。**

关键要点：
1. **合同收尾四步**：①合同终验与尾款结算（含缺陷责任期届满后的复验）；②质保金/预留款的核减与释放（核减依据是缺陷记录与违约扣罚记录，不是"到期自动还"）；③合同关闭（关闭确认书由双方授权代表签署，明确无遗留事项、无未决索赔）；④合同档案归集与知识沉淀（合同正本、附件、变更、签证、验收、结算、往来函件、履约评价表）。
2. **采购绩效复盘五指标**：成本绩效（实际支出 vs 报价、节超率、变更增支占比）、进度绩效（里程碑按期率）、交付质量绩效（一次验收合格率、缺陷密度与逃逸率）、履约与关系绩效（响应达标率、满意度、配合度）、合规绩效（招投标合规、签证完整率、分包合规率）。**变更增支占比**是最有价值的单一指标：它直接反映选型与估算质量。
3. **供应商绩效评价与分级**：质量 30%、交付 25%、成本 20%、服务与响应 15%、合规与安全 10%；结果分为 A（战略合作）、B（优先）、C（合格）、D（限期整改）、E（淘汰），并进入下一轮准入与份额分配。
4. **组织资产沉淀三件套**：**条款库**（标准合同条款集 + 谈判红线清单，如"不签无上限费用条款、不签无变更计价条款、不签无缺陷责任期起算点条款"）、**风险清单**（本项目实际发生的风险沉淀为可识别项）、**供方画像**（按项目分类的能力与诚信记录），并进入组织过程资产库供后续项目引用。
5. **合规与审计留痕四查**：查招投标文件与合同条款的一致性（有无前后不一致的实质性变更）；查变更签证完整性（金额、审批、影响分析、签署四要素齐全率）；查付款与验收匹配性（预付款、进度款、尾款分别对应什么）；查分包转包与人员合规（是否需审批、是否实名到岗、是否违规转包）。留痕不足在审计与巡视中直接构成问题线索。

## 案例分析题

**题目**：

S 省政务服务管理局建设"全省一体化政务大数据平台运营服务项目"，2026 年 1 月公开招标，3 家承建商中标，合同总额 6800 万元，服务期 3 年（2026-01 至 2028-12），合同模式与商务安排如下：

- 甲公司（数据治理）：固定总价 2600 万元，含 20% 质保金，缺陷责任期 12 个月；
- 乙公司（平台运维）：成本补偿合同，年度预算 800 万元，另计管理费，未设费用上限；
- 丙公司（智能分析）：固定总价 1800 万元。

履约 10 个月后（截至 2026 年 10 月）情况如下：

2. 针对上述问题提出改进措施（至少 8 条）。

**参考答案**：

**一、主要问题及理由（12 条）**

1. **合同模式与需求成熟度错配**。甲公司采用固定总价 2600 万元，但招标时功能清单未细化、数据口径与质量标准未定义，属"需求不确定却锁死价格"，导致变更争议与单价重议。理由：固定总价合同的风险分配前提是需求可定义、可验收；前提不成立时，应改用成本补偿 + 里程碑总价，或在合同中设置暂定金额与单价调整机制。
2. **未启动合同约定的重谈/重议程序即单方面变更**。甲公司自 2026 年 3 月起自行启动"单价重议"，绕过变更控制与重谈条款。理由：变更必须经评估、审批、签证，价格调整必须走合同约定的重谈触发程序，否则变更无授权、结算无依据。
3. **变更未签证比例过高，且已进入付款**。23 项变更中 14 项未审批（占 60.9%），涉及 310 万元，其中 210 万元已付款。理由：无签证的变更不具备付款条件，"先付后签"使采购方丧失合同价款控制权，也是审计高风险事项。
4. **成本补偿合同缺少费用上限与费率上限**。乙公司年度实际 980 万元超预算 180 万元（22.5%）。理由：成本补偿合同必须配套成本上限（Cap）、管理费率上限与里程碑预算上限，否则成本风险几乎全部留在采购方。
5. **未设置工单量与重复报单的技术与商务约束**。工单量由 3200 单/月升至 7100 单/月（涨 122%），存在重复报单、多次派单。理由：成本补偿 + 按量结算的组合必须设置工作量基线、去重规则与超量审批，否则形成"多报多得"激励失真，属典型的成本补偿类采购舞弊风险。
6. **SLA 缺少可执行的度量定义**。可用性 99.5% 未定义统计口径、分母范围、免责场景与采集源，实测 97.2% 却无法扣罚。理由：无度量定义的 SLA 不具备可执行性，履约争议中必然由供方解释；同时"政务外网链路故障不计入"的免责主张若未在合同中界定归属（属于需方还是供方责任链），将直接导致无法判定。
7. **违约责任与服务信用扣罚条款缺失**。合同未约定罚则，导致 SLA 违约、响应超时、重复报单等行为无成本约束。理由：SLA 必须与罚则配套（阶梯式扣罚 + 累计上限 + 连续重大违约的解除权），否则 SLA 只是一句愿望。
8. **索赔与反索赔缺少证据链支撑，且双方均可指责对方**。甲公司索赔 180 万元、乙公司反索赔 95 万元，协商 5 个月无果，争议金额 275 万元。理由：索赔成立需同时满足事件、因果关系、损失量化三要件，本案缺少接口缺陷的缺陷分析报告、并发压测与日志、源数据口径确认单、返工工时与费用凭证；证据链不完整将导致仲裁中举证不能。责任边界不清（SDK 由谁设计、谁运维、源数据口径由谁最终确认）是争议根因。
9. **争议期间停工配合违反"继续履行 + 保留权利"原则**。乙公司暂停争议相关接口的配合。理由：争议期间应继续履行合同义务并保留权利；单方停止履行构成违约，可能触发反索赔与工期索赔。
10. **核心人员与知识转移条款缺失**。3 名 DBA 中 2 人离职无交接，导致工单平均解决时长由 4.2 小时升至 11.6 小时（涨 176%）。理由：运维类合同必须锁定核心人员名单、更换报批与交接确认义务，并将响应时效 SLA 与人员稳定率挂钩；否则"人走了服务还在"只是账面合同。
11. **数据安全与密码密钥责任边界不清**。约定"乙方全责"但未明确密钥所有权、轮换机制、审计责任与访问边界。理由：全责条款在多方访问场景下不可执行（甲公司需访问核心库，密评要求甲公司具备密钥管理能力）；须按角色分层明确密钥所有权、轮换周期、审计日志留存与离场销毁义务。
12. **知识产权条款笼统且已被违反**。仅约定"成果归甲方"，未区分背景 IP、前景 IP、算法模型、数据加工成果与开源组件，甲公司已私自将自研算法模块申请软著。理由：需明确背景知识产权归属与许可范围、前景成果转让与授权、开源组件清单与合规义务（SBOM），并约定擅自申请权属的后果；否则成果权属存在争议且甲方权利受限。
13. **付款与验收脱节、质保金条款不可执行**。里程碑付款占 70%，验收标准为"功能可用"等非量化表述，62% 款项已在验收标准不明的情况下支付；质保金仅约定"验收合格后无息退还 20%"，未约定缺陷责任期起算点、期间服务义务与扣减机制。理由：付款必须与可量化验收标准绑定并设置留尾（保留不低于 5%–10% 至缺陷责任期届满），否则失去履约约束。
14. **分包合规与审计留痕缺失**。现场实施分包给第三方个人团队，未见禁止违规转包与分包审批条款；隐蔽工程与数据操作无审计留痕。理由：政务项目涉数据与场景，需实名到岗、禁止转包、违规分包解除权与操作审计日志四项刚性条款。

**二、改进措施（10 条）**

1. **重新评估甲公司合同模式**，把已完成部分转为"已交付工作量核定"，其余部分改为成本补偿 + 里程碑总价混合模式；对"口径确认"类工作单独立设置**口径确认子项目**（含口径字典、数据字典、争议裁定机制由第三方专家裁定），并设置暂定金额与单价表。
2. **立即停止"先付后签"**，对 14 项未签证变更（310 万元）做**补充追溯**：补齐变更评估、影响分析、审批与签证；已付 210 万元部分在补签前不得计入进度款与结算款；对 2026 年 3 月以来未经程序的单价重议结果不予认可，恢复合同原单价并按合同处理。
3. **建立变更控制制度并纳入合同**：变更五步闭环、变更金额分档审批权限（如 ≤50 万项目经理、≤200 万项目经理+分管领导、>200 万走集体决策）、变更单价重议触发线（累计变更超原合同额 10% 时启动重谈）、**所有变更须在 30 日内完成签证**，逾期视同放弃。
4. **补签乙公司成本上限与工作量基线**：追加年度费用上限（Cap）与管理费率上限；建立工单去重规则与"同一事件 24 小时内合并计费"条款；以 3200 单/月为基线，超基线部分须经变更审批方可计价；对已发生的 7100 单逐单审计，核减重复报单与多派单部分。
5. **补充 SLA 度量定义与违约救济**：明确可用性公式（1 − 不可用时长 / 应服务时长）、分母范围（剔除计划内维护窗口）、采集源（监控平台自动采集，人工填报不采信）、免责场景（需方外网链路故障的认定流程与举证责任）、扣罚阶梯（一般 1%–5%、重大 5%–10%、连续重大可暂停服务与解除）与年度扣罚上限。
6. **建立争议处理机制**：签署《争议解决备忘录》，明确"继续履行 + 保留权利"原则；引入独立第三方技术裁定（对 SDK 缺陷与源数据口径分别出具裁定意见）；明确举证责任分配与索赔时限（如事件发生后 15 日内发索赔通知、90 日内提交完整证据）；争议款与无争议款分开结算，不得以停工施压。
7. **补充人员锁定与知识转移条款**：将 3 名 DBA 及关键岗位写入合同附件，更换提前 15 日报批且须同等资历；离岗须完成交接文档、知识转移、账号与密钥交接并经书面确认；设置人员稳定率 SLA（核心人员年流失率 ≤10%）与响应时效挂钩。
8. **补签数据安全与密码密钥协议**：明确密钥所有权（需方）、密级与访问矩阵、轮换周期（≥90 天）、审计日志留存（≥6 个月）、远程接入（堡垒机 + 录屏）、离场数据销毁与承诺函；按角色分层落实密评责任。
9. **补签知识产权与开源合规附件**：列明背景 IP 与前景 IP 边界、算法模型权属与授权范围、开源组件清单与 SBOM 提交义务、禁止擅自申请权属；要求甲公司撤回或转让已申请的软著并承担违约责任。
10. **重构付款与验收结构**：把 70% 里程碑付款下调至 55%，保留 25% 与缺陷责任期挂钩、20% 质保金；将"功能可用"全部改为可量化指标（如接口成功率 ≥99.5%、数据合格率 ≥95%、报表时延 ≤5 分钟），建立"验收不达标不启动付款"与"证据不齐全不签认"两条硬规则；质保金条款写明缺陷责任期起算点（终验之日）、期间响应义务与扣减机制。
11. **补充分包与审计条款**：禁止转包与违规分包，分包须事先报批并提供人员名单与资质；关键操作（数据处理、接口变更、模型发布）留存可审计日志；单设"廉洁与合规"条款与违约解除权。
12. **建立采购全过程台账**：招标文件—评审记录—澄清与谈判纪要—合同及全部附件—变更与签证—验收与计量—结算与发票—履约评价，一事一档、全程留痕，以应对审计与巡视核查。

**三、挣值分析与关联判断**

计算：
- 进度偏差 SV = EV − PV = 4160 − 5100 = **−940 万元**，SPI = EV/PV = 4160/5100 = **0.816**（约 81.6%）；
- 成本偏差 CV = EV − AC = 4160 − 4530 = **−370 万元**，CPI = EV/AC = 4160/4530 = **0.918**（约 91.8%）；
- 完工估算 EAC（典型）= BAC/CPI = 6800/0.918 ≈ **7407 万元**，预计超支约 **607 万元**（约 8.9%）；
- 完工估算 EAC（非典型）= BAC + (BAC − EV) = 6800 + (6800 − 4160) = **9440 万元**，即若剩余工作按当前偏差继续，将超支 2640 万元；两型 EAC 差距悬殊（2033 万元），说明**成本走势高度不稳定**，主因正是成本补偿合同无上限与变更无签证。

判断：
1. 项目处于**成本超支 + 进度滞后**的双差状态，且属"进度比成本更差"的典型特征（SPI 0.816 < CPI 0.918），即并非单纯超花钱，而是**花钱没换来有效交付**。
2. 与合同管理的关联链条清晰：①需求与口径未定义 → 23 项变更、14 项未签证（310 万元）→ 进度滞后与变更增支；②成本补偿无上限 + 按量结算无基线 → 年度超支 180 万元、重复报单 → CPI 恶化；③SLA 无度量定义与罚则 → 97.2% 可用性无损失、处置时长恶化 176% → 业务价值未兑现；④变更与结算脱节 → 210 万元无依据付款 → 现金流出但价值未确认，进度款反而掩盖了真实偏差。
3. **纠偏次序建议**：先止漏（冻结无签证付款、核减重复工单单量、争议款单列），再补约（签补充协议：上限、度量定义、人员锁定、验收指标、知识产权与密钥），后调基（以补充协议为依据更新成本与进度基线并走整体变更控制），最后复盘（合同关闭后形成条款库与供方档案）。切忌在基线失真、口径不清的状态下直接做"赶工"——本案 11 月前已发生接口争议导致的 5 个月停滞，赶工将放大返工成本。

**踩分要点**：
1. **问题必须"问题 + 条款依据 + 后果"三段式作答**：只写"合同不完善"不得分；写出"未定义统计口径 → 无法扣罚 → SLA 形同虚设"才得分。
2. **成本补偿合同必答四点**：费用上限、费率上限、工时/工作量基线、超量审批。漏任何一条即失分。
3. **SLA 必答要素**：可用性公式、统计周期、分母范围、采集源、免责场景、扣罚阶梯与上限。**这是本题最高频的采分点**。
4. **索赔三要件 + 证据链**：事件、因果关系、损失量化；证据链六件套；断链四典型至少答出两类。
5. **知识产权与数据安全**：背景 IP / 前景 IP 区分、算法模型权属、开源组件（SBOM）、密钥所有权与轮换、审计日志留存期，两块各至少 2 点。
6. **变更管理**：五步闭环、补充追溯已付未签款项、单价重议触发线、30 日签证时限。
7. **付款与验收**：付款与量化验收绑定、保留质保与尾款比例、缺陷责任期起算点、验收证据要件。
8. **挣值必须给出算式**：SV −940 万、SPI 0.816、CV −370 万、CPI 0.918、EAC 7407 万（超支 607 万）、EAC 9440 万；并写出"SPI < CPI 说明花钱未换来交付"的结论性判断。
9. **踩分雷区**：①把挣值算成 SV = −640 万（把 EV − BAC 混用）；②只答"加强沟通、 加强管理"这类空话；③认为 EAC 只有一个值而不给两型；④未区分甲乙丙三家的问题归属，把成本补偿类问题写到甲公司身上；⑤回答中不出现具体数字（阈值、比例、时限）。
10. **答题结构建议**：按"采购与选型 / 合同条款缺陷 / 履约与变更 / 索赔争议 / 收尾与审计"五段分组作答，每段先列问题再列改进，便于阅卷人定位采分点。

## 记忆口诀

**合同三型记牢：**
"价稳用总价，量清单料钱，风险共担成本加；上限费率工作量，三缺一签必挨罚。"

**SLA 六要素：**
"口径周期分母源，免责扣罚上限全；人工填报不采信，SLA 不配罚则等于零。"

**索赔三要件与四断链：**
"事件因果损失量，缺一索赔不成立；口说无文、节点无签、超期不报、只列费不连因——四断链，哪条漏了都白干。"

**变更五步与重谈线：**
"识别评估审批执行记录，五步闭环别省；累计变更超一成谈，单价重议有门槛。"

**争议处理八字：**
"继续履行，保留权利；争议款单列，无争议款照付。"

**挣值速算口诀（本案专用）：**
"进度看 SPI 0.82，成本看 CPI 0.92；SPI 小于 CPI 一句话——钱花了，事没成；两型 EAC 一算，差距两千余万，说明走势不稳。"

**收尾三问：**
