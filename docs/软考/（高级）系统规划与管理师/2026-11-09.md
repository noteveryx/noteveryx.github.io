## 今日核心概念

### 1. 数据治理组织体系与角色职责

定义：数据治理是围绕数据资产管理建立的"组织 + 制度 + 流程 + 技术"四位一体体系，目标是把数据作为核心资产进行全生命周期管理，使其可发现、可理解、可信任、可消费。

关键要点：

1. **三类角色不可混淆**
   - 数据所有者（Data Owner，业务部门负责人）：决定数据标准、定义指标口径、审批访问授权、对数据质量与合规结果负责——**决策者**。
   - 数据管理员/数据管家（Data Steward，业务域专职岗）：执行标准、日常稽核、跟踪问题工单、编制数据字典——**执行者**。
   - 数据治理委员会（或数据治理办公室）：制定制度、裁决跨域争议、考核部门——**仲裁者**。
   - 典型错误：把数据治理等同于信息部门的事，业务部门不出 owner，标准永远落不了地。

2. **治理组织三种形态**
   - 集中式：数据治理中心直接管人管标准，权责清晰但人力瓶颈。
   - 联邦式：各业务域自治，总部只管原则与共享服务，落地快但标准易走样。
   - 混合式（主流）：标准与工具集中，域内执行自治，委员会统一裁决。

3. **制度四件套**：数据管理制度、数据标准管理办法、数据质量管理办法、数据安全分级与授权管理办法；必须配套操作规范与模板，否则制度空转。

4. **知识域框架（DAMA-DMBOK 十二域）**：数据治理与质量、数据架构与建模、数据安全与隐私、数据组织与角色、数据标准、元数据、主数据、数据质量、数据仓库与BI、数据生命周期管理、项目管理、度量与改进。

5. **落地三阶段**：现状评估（数据资产盘点 + 成熟度评估）→ 规划（标准体系、组织设计、路线图、工具选型）→ 落地执行（流程嵌入、平台建设、稽核考核、持续优化）。

6. **成熟度五级（数据治理成熟度模型）**：初始级（依赖个人经验）→ 重复级（局部规范、无统一口径）→ 已定义级（标准成文、组织到位）→ 已管理级（指标可度量、流程受控）→ 持续优化级（数据驱动业务改进）。评估维度：组织、制度、流程、技术、文化五项。

### 2. 数据标准与主数据管理

定义：数据标准是对数据的定义、编码、格式、取值域作出统一规范，是数据治理的技术底座；主数据管理（MDM）是对企业核心实体数据（客户、组织、供应商、员工、商品）建立唯一权威来源并全网分发。

关键要点：

1. **数据标准三个层次**
   - 基础通用类：日期时间、金额单位、代码集、计量单位、字符集。
   - 主题域类：业务术语、实体定义、指标口径、维度定义（供应链/财务/人力各域）。
   - 业务规则类：校验规则、默认值、派生逻辑、算法口径（如"有效订单=已审核未退货且付款完成"）。

2. **标准落地五步**：制定（业务 + IT + 治理三方共建，避免 IT 单方面定义）→ 宣贯培训 → 嵌入系统（源系统录入校验、下拉枚举、接口映射、库表类型约束）→ 检测稽核（跑批扫描违规率）→ 评估与改进（版本管理、废止与替代）。**未嵌入源系统的标准等于文档**。

3. **主数据识别四步**：识别候选（按共享性高、权威性强、变化少筛选）→ 定义与归并规则 → 匹配去重（精确匹配 + 模糊匹配 + 规则匹配 + 人工审核）→ 治理与分发（订阅式分发到各系统、变更同步）。

4. **MDM 三种模式与演进路径**：集中式（单一主数据系统）→ 共享式（中央平台 + 接口共享）→ 协同式（各系统内建 MDM、主数据共享）→ 再收敛到集中式。路径选择取决于组织成熟度与变革成本，不可一步到位。

5. **主数据 / 参考数据 / 交易数据的区分**（高频考点）：
   - 主数据：数量少、变化慢、权威唯一（客户、组织、供应商、员工、产品）。
   - 参考数据：被引用的标准查询表（行政区划代码、币种、汇率、税率表）。
   - 交易数据：量大、变化快、生命周期短（订单、流水、事件）。

6. **编码规则三原则**：唯一性（一物一码）、稳定性（编码不随组织调整而变）、扩展性（预留码段）。常见编码结构：层次码、顺序码、混合码。**主数据编码必须与组织架构解耦**，否则一次组织调整导致全网编码失效。

### 3. 数据质量管理（DQM）与质量稽核闭环

定义：数据质量管理是通过定义质量规则、检测问题、定位根因、责任到人整改并复核销号，持续提升数据符合使用要求的程度。

关键要点：

1. **六维度**：完整性、准确性、一致性、有效性、唯一性、及时性（扩展：可信性、可访问性、可追溯性）。考试常给案例问"属于哪个维度"，须能快速归类。

2. **三过程**：规则定义（DQ Rule，可自动执行的判断语句）→ 检测（跑批全量稽核 + 抽样复核 + 跨源比对）→ 处理（源头修正优先，登记问题工单并闭环）。

3. **典型规则与阈值设计**
   - 完整性：主键非空率 100%、关键字段填充率 ≥ 98%。
   - 准确性：与权威源（财务系统、地税、社保）比对，差异率 ≤ 0.1%。
   - 一致性：跨系统同名指标口径一致率 ≥ 95%（同名同义、同义同名）。
   - 唯一性：主数据重复率 ≤ 0.1%。
   - 有效性：值域符合、格式合规、枚举在册。
   - 及时性：数据更新时延 ≤ T+1。

4. **质量度量指标**：数据质量合格率（加权）、质量问题闭环率、平均修复时长、**根治率**（源头系统修复占比，目标 ≥ 60%）、规则覆盖资产比例、稽核覆盖率。

5. **根因五类**：源系统录入无校验；ETL 映射与转换错误；上游接口变更未同步；标准缺失或标准冲突；权责不清无人认领问题。

6. **稽核与考核闭环**：发现 → 定责 → 整改 → 复核 → 销号 → 知识沉淀（纳入标准修订）；配合手段是数据质量纳入部门绩效评分、纳入变更管理流程（涉及数据口径的变更必须同步影响分析）。

7. **常见误区**：只做"工具扫描 + 报告"，不落责任、不改源头，导致"报表月月扫、问题月月犯"。

### 4. 元数据管理与数据血缘

定义：元数据是"描述数据的数据"；数据血缘描述数据从来源系统经加工到消费的流转与依赖关系，是数据治理的"地图"和影响分析的底座。

关键要点：

1. **元数据三层次**
   - 技术元数据：库、表、字段、类型、分区、任务调度、数据质量规则、血缘。
   - 业务元数据：业务定义、术语、指标口径、责任部门、数据 owner。
   - 操作元数据：血缘关系、影响分析、执行统计、变更历史、访问日志。

2. **血缘三种粒度**：表级（表与表）、字段级（字段映射与转换逻辑）、报表级/服务级（指标到看板）。**字段级血缘是数据仓库建设中最难也最有价值的部分**。

3. **血缘两个方向**：正向血缘（结果→来源，看数出哪儿，用于溯源与质量根因定位）；反向血缘（来源→结果，看改一处影响哪儿，用于变更影响分析）。

4. **元数据驱动开发（MDD）**：以元数据为契约打通"需求 → 模型 → 调度任务 → 数据服务 → 看板"，实现模型可复用、影响可分析，避免重复建设。

5. **落地五要点**：自动采集优先（数据库日志、调度平台、代码仓库扫描）避免"人工登记即失效"；元数据与数据字典合一；数据地图按业务域组织检索；血缘覆盖纳入验收指标；元数据平台必须与调度、数据服务打通才能活。

6. **价值落点**：影响分析（改字段影响哪些报表）、根因定位（数据异常 3 天→30 分钟）、重复建设识别、交接与知识沉淀、审计与合规举证。

### 5. 数据仓库分层建模与商业智能决策支持

定义：数据仓库是面向主题、集成的、相对稳定的数据集合，用于分析决策；商业智能（BI）是在标准化、高质量数据基础上，通过指标体系、可视化与自助分析支撑经营决策的应用体系。

关键要点：

1. **分层模型五层**：ODS（贴源，保留原始形态）→ DWD（明细清洗与标准化）→ DIM/DWS（维度表与轻度汇总）→ DM/ADS（应用集市、主题汇总）→ BI 服务与报表。每层有明确边界，禁止跨层直取。

2. **维度建模（Kimball）**：事实表（度量值、稀疏、多个外键、含退化维度）＋ 维度表（代理键、代理键与业务键分离、含一致性维度）；三种形态：星型（维度不冗余、查询快，主流）、雪花（维度规范化、层次清晰，join 多）、星座（多个事实共享维度，主题域分析）。**一致性维度是跨主题可比的基础**。

3. **缓慢变化维四类型**：SCD1 覆盖更新（只留当前值）、SCD2 新增行（保留历史，带生效失效日期，**事实表关联推荐用**）、SCD3 历史列（历史值存多列）、SCD4 历史表。

4. **ETL 与 ELT 及湖仓**：ETL 先加工后入仓（强治理、数据量小）；ELT 先入湖再加工（灵活、存算分离）；湖仓一体（Lakehouse）= 开放表格式 + 分布式存储 + 元数据/事务层，兼顾性能与多引擎。

5. **指标体系四层**：原子指标（不可再拆，如"订单金额"）→ 派生指标（带计算与口径，如"月订单金额=sum(订单金额) where 状态=有效"）→ 复合指标（原子+派生组合，如"客单价=订单金额/订单数"）→ 主题指标（面向主题域的经营指标）。配套**指标字典 / 口径卡**，执行"一数一源"，即一个指标只有一个权威定义与唯一出口。

6. **BI 三层能力**：数据可视化（看板、报表）、自助分析（拖拽即席取数、自然语言取数）、决策支持（预测、预警、优化建议）。三层递进，不可跳级——**没有标准与质量，自助分析就是自助制造混乱**。

7. **BI 治理重点**：权限控制（行级/列级/字段脱敏）、指标版本管理与下线机制、看板复用与避免重复建设、口径变更的影响分析（改口径必须评估所有引用看板并同步告知用户）、使用度量（活跃看板数、看板复用率、人均取数次数、决策采纳率）。

8. **决策支持系统（DSS）**与 BI 差异：DSS 偏重模型驱动的分析、模拟与半结构化决策（线性规划、蒙特卡洛、预测模型），BI 偏重数据呈现与自助分析；系统规划与管理师常考"BI 不等于决策支持系统"，前者是数据消费层，后者是模型与决策层。

## 案例分析题

**题目**：

某省属能源集团 2025 年 3 月启动"数据治理与商业智能平台"建设项目，预算 6200 万元，工期 18 个月，由 3 家联合体承建，覆盖集团本部及 12 家分子公司共 87 套业务系统、约 6.4 亿条业务数据。2026 年 8 月组织验收评审，结论为"具备初步使用条件，遗留问题限期整改"。评审发现的主要情况如下：

1. 项目方案承诺"建成覆盖 9 大业务域的数据标准体系"，实际交付 3 份文本（编码规则、命名规范、数据字典模板），未覆盖核心实体定义；检查源系统发现，订单系统客户名称仍为自由文本录入，无标准校验规则。

2. 集团客户主数据 218 万条，去重后仅 181 万条，**重复率 17.8%**；销售系统与财务系统客户编码互不映射，财务应收台账仍有 37 万条"无法匹配"客户记录。

3. 月度经营分析会上出现口径冲突：财务口径营业收入 58.6 亿元，BI 平台口径 54.9 亿元，**相差 6.4%**（差 3.7 亿元）；财务总监拒绝在经营会上使用 BI 看板。

4. 数据仓库每日 ETL 批处理运行 6.5 小时，其中 3 个核心主题层任务频繁超时，**T+1 数据实际在 11:00 后才能产出**，早间经营例会只能使用 Excel 手工报表。

5. 上线 8 个月，BI 看板月活用户 320 人（合同目标 1500 人），仅 6 个部门使用，8 家分子公司未接入；用户普遍反馈"同一个指标在不同看板数字不一样，找不到口径说明"。

6. 项目组 12 人中数据治理岗仅 1 人（原计划 6 人），且该岗人员在实施中期离职未补齐；**无数据所有者制度文件，无质量稽核工单闭环记录**，质量报告只统计问题总数，无整改闭环率与根治率。

7. 变更 17 项中 9 项未履行审批程序；元数据平台仅覆盖 24% 的数据表，无字段级血缘，无法做影响分析。

8. 财务数据：计划价值 PV = 4340 万元，实际成本 AC = 3980 万元，挣值 EV = 3410 万元，项目总预算 BAC = 6200 万元。

**要求**：

1. 指出该项目在数据治理组织、数据标准、主数据、数据质量、元数据、BI 建设六个方面存在的主要问题（不少于 8 条），并说明对应的治理原则被违反之处。
2. 针对上述问题提出改进措施（组织、流程、技术、考核四类措施并重）。
3. 计算挣值指标，判断项目绩效状态，给出完工估算 EAC、剩余工作成本 ETC、基于预算的完工尚需绩效指数 TCPI，并说明后续应对措施。

**参考答案**：

**一、主要问题（12 条）**

1. **治理组织缺位**：数据治理岗 1 人（原 6 人）且离职未补，无数据所有者制度文件——违反"业务部门承担数据责任、信息部门提供支撑"原则，治理责任错置在承建方，治理不可持续。
2. **角色缺位**：无数据所有者（Data Owner）与数据管家（Data Steward）两级角色定义，无法裁决跨域口径冲突（如财务与 BI 口径之争）。
3. **标准覆盖面严重不足**：承诺 9 大业务域，实际仅 3 份通用文本，未覆盖核心实体定义——违反"标准先行"原则。
4. **标准未嵌入源系统**：订单系统客户名称自由文本、无校验枚举——标准停留在文档层，未形成技术强制力。
5. **主数据未收敛**：客户重复率 17.8%，无统一主数据系统与去重归并规则；主数据管理四步（识别—定义—匹配—治理分发）缺三。
6. **跨系统主数据未映射**：销售与财务编码体系割裂，37 万条无法匹配记录——缺少"一数一源"与主数据分发映射机制，直接导致财务对账缺口。
7. **指标口径未统一**：BI 口径与财务口径相差 6.4%（3.7 亿元），无指标字典/口径卡与口径裁决机制——违反"一数一源、口径唯一"原则，BI 结论不可用于经营决策，财务总监拒用是必然结果。
8. **数据质量无闭环**：无稽核工单、无整改闭环率与根治率，报告只统计问题总数——违反"发现—定责—整改—复核—销号"闭环原则，质量治理形式化。
9. **数据时效性不达标**：T+1 数据 11:00 后才产出，早会仍用手工 Excel——违反数据服务时效性约定（分级时效 SLA 未落地），BI 替代手工报表的目标失败。
10. **元数据与血缘严重缺失**：元数据覆盖仅 24%，无字段级血缘，无法做变更影响分析与根因定位——违反"元数据驱动"原则，故障排查与影响分析只能靠人工问人。
11. **BI 建设重形式轻使用**：月活 320 人（目标 1500），6/14 部门在用，8 家分子公司未接入，同一指标多看板数字不一——缺少指标版本管理、看板复用机制与用户运营，"建了不用"是典型失败模式。
12. **变更管控失效**：17 项变更中 9 项未履行审批——违反变更管理"先申请后实施、可追溯可审计"原则，直接导致口径变更、模型改造无影响分析，是数据错误蔓延的源头。

**二、改进措施（四类并重）**

**（一）组织措施**

1. 成立集团数据治理委员会（CEO/总工经任主任，数据域总监、分子公司代表为委员），下设数据治理办公室（3—5 人专职），统一裁决跨域口径冲突与争议。
2. 发布《数据治理组织与职责管理制度》，逐域任命**数据所有者**（业务分管副总级，有决策权）与**数据管家**（业务骨干兼职，2—3 人/域），签订数据责任书；**治理责任随业务走，信息部门只提供平台、工具与技术支持**。
3. 补齐治理岗位：按原计划补足 6 名数据治理岗（含 1 名主数据经理、2 名数据质量稽核员），建立人员离职的岗位备份与交接清单。
4. 建立治理成熟度评估机制：按组织、制度、流程、技术、文化五维度每年自评一次，目标两年内从"重复级"提升至"已定义级"，三年内进入"已管理级"。

**（二）流程措施**

1. **补齐标准体系**：以现有 3 份文本为底，按 9 大业务域逐一输出实体定义、主题域模型、指标口径三层标准，三个月内形成《集团数据标准手册》并纳入版本管理。
2. **标准嵌入系统**：在源系统增加标准校验（客户名称改为主数据选择 + 唯一性校验、枚举值下拉、码值格式强校验），把"标准"变成"系统约束"，存量数据做一次性清洗迁移。
3. **主数据收敛专项**：先做客户主数据——建立主数据系统与唯一客户编码，18 个月内完成 218 万条去重归并（精确 + 模糊 + 规则 + 人工抽审四路匹配），去重至 181 万条基础上继续消除同源重复；建立销售、财务、供应链三套编码映射表与订阅式分发机制，37 万条"无法匹配"记录 6 个月内清零。
4. **指标口径统一**：建立集团级指标字典与口径卡，原子/派生/复合/主题四层指标全部登记，明确唯一出口（BI 平台）与唯一责任域；财务与 BI 收入差异 3.7 亿元 30 天内完成逐项对账（时点差、含税与否、内部交易抵销、合并范围四类原因逐条定位）；口径变更必须走变更流程并评估所有引用看板。
5. **数据质量稽核闭环上线**：按六维度制定 DQ 规则库（含主键非空率 100%、跨源差异率 ≤ 0.1%、主数据重复率 ≤ 0.1%、关键字段填充率 ≥ 98% 等阈值），月度全量跑批 + 问题工单（定责—整改—复核—销号），质量报告增加**闭环率、平均修复时长、根治率**三指标。
6. **元数据与血缘补齐**：自动采集优先（调度平台日志 + 数据地图扫描），6 个月内元数据覆盖率从 24% 提升至 90% 以上，优先打通客户、订单、收入三类核心主题的**字段级血缘**，支撑影响分析与根因定位。
7. **BI 用户运营**：建立看板准入与复用评审（同类看板合并、指标卡随看板同屏展示）、分子公司接入专项计划（按 8 家分批接入，季度考核接入率与月活），把"用起来"纳入上线后运营计划；同步建立口径变更的用户告知机制。

**（三）技术措施**

1. 元数据平台与调度平台、数据服务打通，实现任务、口径、血缘、变更四联动；元数据覆盖率与字段级血缘覆盖率纳入系统验收指标（未达标不予终验）。
2. 数据仓库分层重构：核心主题层任务拆分 + 资源倾斜 + 关键路径 DAG 优化，将 ETL 窗口从 6.5 小时压到 3.5 小时以内，恢复 T+1 早 8:00 前供数能力；必要时引入湖仓一体（开放表格式 + 存算分离）支撑扩容。
3. 主数据系统建设：统一编码管理、多源匹配去重引擎、主数据分发订阅、变更同步与版本留痕；打通 MDM 与 ERP/CRM/供应链。
4. BI 平台治理能力：行级/列级权限、字段脱敏、指标版本管理与下线机制、看板复用检索、血缘可点击下钻。
5. 变更管控补强：在需求与变更流程系统中嵌入"影响分析"强制项，未提交影响分析报告的变更不得进入审批；补办 9 项未审批变更的追认与复核。

**（四）考核措施**

1. 数据质量闭环率、主数据重复率、指标口径一致率、元数据覆盖率、BI 月活与复用率**纳入分子公司与业务部门年度绩效考核**，权重不低于 5%。
2. 建立数据治理例会制度（月度质量会、半年度标准评审会、季度治理例会），问题清单挂账督办。
3. 试点"数据责任人考核 + 错误源头追责"：质量问题溯源到源系统录入或接口映射的，对源头部门扣分，引导根治而非长期在下游打补丁。

**三、挣值计算与绩效判断**

计算过程：

- 进度偏差 SV = EV − PV = 3410 − 4340 = **−930 万元**（进度落后）
- 成本偏差 CV = EV − AC = 3410 − 3980 = **−570 万元**（成本超支）
- 进度绩效指数 SPI = EV ÷ PV = 3410 ÷ 4340 = **0.786**（< 1，进度滞后）
- 成本绩效指数 CPI = EV ÷ AC = 3410 ÷ 3980 = **0.857**（< 1，成本效率差）
- 完工估算 EAC（典型，当前成本偏差将持续）= BAC ÷ CPI = 6200 ÷ 0.857 ≈ **7236 万元**，预计超支约 **1036 万元**（超支率 16.7%）
- 完工估算 EAC（非典型，偏差为偶发）= AC +（BAC − EV）= 3980 +（6200 − 3410）= **6770 万元**，超支约 570 万元
- 剩余工作成本 ETC = EAC − AC = 7236 − 3980 ≈ **3256 万元**（按非典型口径为 2790 万元）
- 基于预算的完工尚需绩效指数 TCPI =（BAC − EV）÷（BAC − AC）=（6200 − 3410）÷（6200 − 3980）= 2790 ÷ 2220 ≈ **1.26**
- 补充口径：若按 EAC = 6770 计算的 TCPI =（6770 − 3410）÷（3980 − 3410）= 3360 ÷ 570 ≈ **5.89**

绩效判断：

- 项目处于**进度落后与成本超支的双负象限**（最不利象限），且进度偏差（−930 万）大于成本偏差（−570 万），说明主因是**范围与工作量失控**而非单纯效率低下——与前述"标准未覆盖、口径反复、变更 9 项未审批"的问题互相印证。
- SPI 0.786 与 BI 目标用户达成率 320/1500 = 21.3%、主数据重复率 17.8% 高度一致，说明价值实现（受益）严重滞后于投入（消耗），符合**"花钱多、干活慢、见效少"**的典型症状。
- TCPI = 1.26 意味着要在原预算内完工，后续工作必须以 1.26 倍的效率完成；而按当前 CPI 0.857 的实际效率推算需要 5.89 的效率——**目标与现实差距约 4.7 倍**，靠自然恢复几乎不可能达成。
- 按 EAC 7236 万元测算将突破合同预算 6200 万元（超支 1036 万元），构成商务风险。

后续应对措施：

1. **范围控制（首选）**：以本案例暴露的"标准未覆盖、口径反复"为由，对未完成的 6 个业务域标准、8 家分子公司接入、血缘 76% 缺口三项内容做**范围变更**，明确"本期不做的部分与移交时点"，走正式变更流程并重新确认范围基准。
2. **成本纠偏**：冻结非必要开发与外购支出，压缩 ETL 重构之外的定制开发；对 9 项未审批变更中的超范围内容做**索赔与冲抵**，未签证部分不予付款。
3. **效率提升**：治理岗补齐 6 人并绑定业务域，指标口径 30 天内收敛以消除重复取数与返工（返工是成本超支主因）；ETL 优化释放的产能优先投向数据质量根治。
4. **绩效修正**：重设剩余期间的进度与成本基准（非典型偏差假设），按 1.26 的 TCPI 反推资源投入（增派 2 名架构师 + 1 名数据工程师专项攻坚），周度跟踪 SPI 回升轨迹。
5. **分期验收与资金挂钩**：将"遗留问题限期整改"细化为可量化里程碑（元数据覆盖率 ≥ 90%、主数据重复率 ≤ 1%、37 万条无法匹配清零、指标一致率 ≥ 95%、月活 ≥ 1000），与未签证的 20% 尾款及质保金挂钩。
6. **风险与合同处置**：超支 1036 万元若确认无法通过内部消化，提前按合同变更或索赔条款启动商务谈判，避免期末形成争议；同步完成项目后评价（组织、标准、工具、流程、人五个维度），沉淀为集团数据治理制度修订输入。

## 踩分要点

**第一问（问题识别）**

1. 先给**问题总数与分类结构**（组织 2 条、标准 2 条、主数据 2 条、质量 1 条、元数据 1 条、BI 与变更 2 条，共 10—12 条），再逐条展开，阅卷按点给分，条目不清直接丢分。
2. 每条问题必须写"**现象 + 违反的原则**"两段，只描述现象不点原则最多得一半分。
3. 高频踩分点：治理责任错置于承建方（必答）；标准未嵌入源系统等于无标准（必答）；主数据重复率 17.8% 与 37 万条无法匹配记录（必答）；BI 与财务口径差 6.4% 直指"一数一源"（必答）；元数据 24% 且无字段级血缘（必答）；9/17 变更未审批（必答）。
4. 常见失分：把"数据管家"与"数据所有者"职责写反；只写"加强管理"这类空话；漏掉时效性问题（T+1 延至 11:00）；漏掉元数据/血缘这一块。

**第二问（改进措施）**

1. 必须**四类措施齐全**：组织、流程、技术、考核，每类不少于 3 条。
2. 每条措施尽量与第一问问题**一一对应**，并给出**可量化目标值**（覆盖率、闭环率、重复率、一致率、时限），否则即使方向对也难拿满分。
3. 必答要点：治理责任归业务部门、数据所有者制度与任命、主数据系统与去重专项、指标字典与口径卡、DQ 规则与工单闭环、元数据自动采集与字段级血缘、ETL 窗口压缩目标、看板复用与用户运营、考核权重、数据责任人追责。
4. 常见失分：只写技术措施不写组织与考核；只写"加强培训"这类无闭环动作；不给量化目标；忽略合同与资金层面（未签证款与尾款挂钩、索赔冲抵）。

**第三问（挣值计算）**

1. 公式必须写全：SV、CV、SPI、CPI、EAC（典型与非典型两个）、ETC、TCPI。缺 EAC 非典型值一般扣 1 分。
2. 数值务必核对：SV = −930 万、CV = −570 万、SPI ≈ 0.79、CPI ≈ 0.86、EAC 典型 ≈ 7236 万、EAC 非典型 = 6770 万、ETC ≈ 3256 万、TCPI ≈ 1.26。
3. 判断必须落到"**双负象限 + 范围/工作量失控为主因**"，并把挣值结论与案例事实挂钩（SPI 与用户达成率 21.3% 互证），而不是只报数字。
4. 后续措施要点：**范围变更 + 分期验收与付款挂钩 + 资源与技术纠偏 + 合同商务处置（超支沟通、索赔冲抵、未签证款控制）+ 后评价**。只答"加强进度控制"不给具体动作最多得一半分。

## 记忆口诀

**治理组织**
角色三件套：**所有者定、管家管、委员会裁**；成熟度五级：**初始—重复—定义—管理—优化**；形态三选：**集中、联邦、混合**。

**数据标准主数据**
标准三层次：**基础通用、主题域、业务规则**；落地五步：**定—宣—嵌—检—评**；主数据四步：**识别—定义—匹配—分发**；编码三原则：**唯一、稳定、可扩展**；主数据/参考数据/交易数据：**少慢权威 / 标准表 / 大快短暂**。

**数据质量**
六维度口诀：**完准一有唯及**（完整性、准确性、一致性、有效性、唯一性、及时性）；闭环五步：**发—责—改—核—销**；根治率看**源头改**，报告必须带**闭环率、修复时长、根治率**三指标。

**元数据血缘**
元数据三层：**技术、业务、操作**；血缘三粒度：**表、字段、报表**；两个方向：**正向溯源、反向影响**；元数据驱动：**契约打通需求到看板**。

**数据仓库与BI**
分层五层：**ODS—DWD—DWS/DIM—DM/ADS—BI**；建模三形：**星型、雪花、星座**；缓慢变化维四型：**覆盖、新增行、历史列、历史表**；ETL 与 ELT：**ETL 先加工后入仓，ELT 先入湖再加工**；指标四层：**原子—派生—复合—主题**；BI 三层能力：**可视化—自助分析—决策支持**；总原则：**一数一源、口径唯一**。

**挣值计算**
偏差看**SV、CV**，指数看**SPI、CPI**，预测**EAC（典型 BAC/CPI、非典型 AC+BAC−EV）**，剩余**ETC=EAC−AC**，节支**TCPI=(BAC−EV)/(BAC−AC)**；双负象限主因常是**范围失控**，对策优先**变更范围、分期验收挂钩付款、后评价**。

**案例速判四问**
治理查**责任在谁**；标准查**是否进系统**；主数据查**是否一源**；质量查**是否闭环**；血缘查**能否做影响分析**；BI 查**是否真被用**。
