# 系统规划与管理师 第55次学习（2026-09-10）

## 今日核心概念

### 1. 信息系统项目管理与OPM组织级项目管理
定义：信息系统项目管理是在项目全生命周期内运用系统的方法、工具与技术对信息系统建设过程进行计划、组织、指挥、协调、控制的管理活动；OPM（Organizational Project Management）是组织级项目管理，是将项目战略与组织战略对齐的管理框架。

关键要点：
- 项目管理五大过程组：启动（Initiating）+规划（Planning）+执行（Executing）+监控（Monitoring & Controlling）+收尾（Closing）；PDCA循环
- 信息系统项目特点：技术含量高+涉及部门多+需求变更频繁+智力密集型+用户参与度要求高+生命周期长
- 信息系统项目生命周期四阶段：系统规划（立项+可研）+系统分析（需求分析）+系统设计（架构设计+详细设计）+系统实施（编码+测试+部署+运维）
- OPM三大支柱：战略对齐（Strategic Alignment）+治理与流程（Governance & Process）+文化与人才（Culture & Talent）
- PMO三种类型：支持型（Supportive，顾问咨询）+控制型（Controlling，强制合规）+指令型（Directive，直接管理项目）；随组织成熟度递进
- 项目集管理五大过程：定义授权项目集+规划项目集+管理项目集+交付项目集收益+收尾项目集
- 项目组合管理PPM五大过程：识别需求/类别+定义组合组件+分析组件+批准组件+监控绩效
- 项目治理与项目管理区别：治理定方向（Who/What），管理保执行（How）
- 治理委员会三层架构：董事会（战略层）+PMO/项目集经理（管理层）+项目经理（执行层）
- 项目集治理委员会PBG：高级发起人+业务部门高管+财务负责人+技术负责人+外部专家
- RACI责任矩阵：Responsible（执行）+Accountable（问责，唯一）+Consulted（咨询）+Informed（知情）
- 项目组合选择方法：BCG矩阵（明星/金牛/问题/瘦狗）+Ansoff矩阵（市场渗透/产品开发/市场开发/多元化）
- 商业论证Business Case：背景+问题/机会+推荐方案+收益预测+成本估算+风险与退出标准；定期更新

### 2. 信息系统项目立项与可行性研究
定义：项目立项是从项目识别、可行性研究、立项审批到项目启动的全过程管理；可行性研究是运用多种科学方法对项目技术、经济、社会等方面进行分析论证，为项目决策提供科学依据。

关键要点：
- 项目立项管理五大阶段：项目识别（需求调研+项目储备）→项目论证（可行性研究）→项目决策（立项审批）→项目准备（招标采购）→项目启动（项目章程）
- 可行性研究六大维度：技术可行性（Technology）+经济可行性（Economic）+社会可行性（Social）+运行可行性（Operational）+法律可行性（Legal）+时间可行性（Schedule）
- 项目必要性分析五维度：业务发展需求+技术升级需求+政策合规需求+服务提升需求+管理创新需求
- 可行性研究报告内容结构：项目背景与必要性+建设目标与规模+建设方案+投资估算与资金筹措+效益分析+风险分析+结论与建议
- 投资估算四方法：类比估算+参数估算+自下而上估算+三点估算（PERT=(O+4M+P)/6）
- 投资估算分解：硬件费+软件费+集成费+咨询费+运维费+预备费（应急储备10%+管理储备5%）
- 资金筹措渠道：财政资金+自筹资金+银行贷款+社会资本（PPP/政府购买服务）
- 经济效益评价指标：NPV净现值+IRR内部收益率+ROI投资回报率+投资回收期（静态/动态）
- 社会效益量化指标：服务覆盖人口+办理时长压缩率+群众满意度+跑动次数减少率+数据共享率
- 立项审批流程：申报单位→业务主管部门→发展改革部门→财政部门→政府常务会议（如需）→立项批复
- 立项批复文件三要件：项目批复文件（项目名称+建设内容+投资+工期）+资金来源证明+可行性研究报告批复
- 项目储备库管理：建立项目储备库（5-10年规划）+动态调整+优先级排序+分批启动
- 项目章程主要内容：项目目的+范围边界+主要干系人+总体里程碑+项目经理授权+风险等级
- 政府投资条例：政府投资资金应当投向市场不能有效配置资源的社会公益服务、公共基础设施、农业农村、生态环境保护、重大科技进步、社会管理、国家安全等公共领域的项目

### 3. 信息系统项目招投标与合同管理
定义：项目招投标是采购人通过法定程序选择合格承建方的采购过程；合同管理是对合同签订、履行、变更、终止全过程进行管理；变更控制是处理范围、进度、成本等方面变化的规范化流程。

关键要点：
- 招标方式六种：公开招标（原则）+邀请招标+竞争性磋商+竞争性谈判+询价+单一来源（政府采购法）
- 公开招标适用情形：单项金额≥200万（货物/服务）或≥400万（工程）
- 招标流程九步：招标备案→编制招标文件→发布招标公告→资格预审→发售招标文件→踏勘现场→投标答疑→开标评标→定标签订合同
- 招标文件七大组成：投标邀请书+投标人须知+合同条款+投标文件格式+技术规格书+评标办法+附件与附图
- 投标保证金：一般不超过项目估算价2%，最高不超过80万元
- 履约担保：中标人向招标人提供，金额一般不超过合同价10%
- 评标委员会组成：5人以上单数（一般5-7人）+技术经济专家≥2/3+业主代表≤1/3；专家随机抽取
- 评标方法两类型：综合评估法（价格+技术+服务综合打分）+最低评标价法（满足实质性要求最低报价）
- 废标情形：投标文件未密封+未按时提交+未响应实质性要求+串通投标+弄虚作假
- 招投标法核心原则：公开+公平+公正+诚实信用
- 合同类型三族系：总价合同（FFP/FP-EPA/FPIF）+成本补偿合同（CPFF/CPIF/CPAF/CPPC）+工料合同（T&M）
- 合同条款六件套：标的物+价款+履行期限地点方式+违约责任+争议解决方法+变更与解除条件
- 合同变更五步法（CCB五步）：变更申请→影响分析→CCB评审→变更实施→变更验证
- 变更影响五维度：进度+成本+范围+质量+风险
- 变更分类：重大变更（影响>10%）+一般变更（≤10%）+紧急变更（24小时ECAB）
- 变更累计跟踪：建立变更累计影响登记表；变更累计超原合同10%须重新招标
- 索赔管理：索赔识别→索赔通知（28天内书面）→索赔证据收集→索赔谈判→索赔解决
- 合同争议解决四步：协商→调解→仲裁→诉讼（终局）
- 信息系统合同特殊条款：知识产权归属+源代码交付+技术文档交付+培训服务+质保期与免费维护期

### 4. 信息系统项目进度管理与成本管理
定义：进度管理是确保项目按时完成的过程组；成本管理是确保项目在批准的预算内完成的过程组；挣值管理（EVM）是综合范围、进度、成本三维度的绩效测量技术。

关键要点：
- 进度管理七大过程：规划进度管理+定义活动+排列活动顺序+估算活动资源+估算活动持续时间+制定进度计划+控制进度
- 进度管理工具三件套：WBS分解+PDM前导图法（FS/FF/SS/SF四种依赖）+网络图（活动依赖可视化）
- 关键路径CPM：网络图中TF=0的活动链为关键路径，决定项目最短工期；可能有多条关键路径
- 关键路径六时参数：ES最早开始+EF最早结束+LS最晚开始+LF最晚结束+TF总时差+FF自由时差
- 关键路径计算法：正推法计算ES/EF（取最大）+逆推法计算LS/LF（取最小）
- 进度压缩两大方法：赶工Crash（加资源缩短工期，成本↑）+快速跟进Fast Tracking（并行执行，返工风险↑）
- 工期估算五方法：类比估算+参数估算+三点估算PERT（O+4M+P）/6+自下而上估算+储备分析
- 甘特图（横道图）：时间-任务二维可视化；用于进度计划与实际进度对比
- 成本管理四过程：规划成本管理+估算成本+制定预算+控制成本
- 成本类型四件套：直接成本（人工/材料/设备）+间接成本（管理/办公/水电）+固定成本（折旧/房租）+可变成本（材料/计件工资）
- 挣值管理EVM三值：PV计划值+EV挣值+AC实际成本
- 挣值四指标公式：SV=EV-PV（进度偏差）+CV=EV-AC（成本偏差）+SPI=EV/PV（进度绩效）+CPI=EV/AC（成本绩效）
- 挣值预测四指标：EAC=BAC/CPI（完工估算）+ETC=EAC-AC（剩余工作）+VAC=BAC-EAC（完工偏差）+TCPI=(BAC-EV)/(BAC-AC)（完工尚需绩效指数）
- EAC三种公式：EAC=BAC/CPI（当前绩效延续，最常用）+EAC=AC+BAC-EV（当前绩效不延续）+EAC=AC+(BAC-EV)/(CPI×SPI)（需同时改进）
- 储备金管理：应急储备（已知风险，包含在成本基准）+管理储备（未知风险，不包含在成本基准）
- 偏差分析三步：偏差识别→偏差原因分析（5Why根因）→纠偏措施（预防+纠正）
- 进度控制工具：Project/P6（专业项目管理软件）+甘特图+网络图+挣值分析
- 进度偏差判断：SPI<0.9 严重滞后（必须纠偏）+SPI 0.9-1.0 轻微滞后（关注）+SPI=1.0 符合计划+SPI>1.0 提前
- 信息系统项目成本特点：智力密集型（人力成本占比高60-80%）+软硬件比例变化大+运维成本长期化

### 5. 信息系统项目质量管理与配置管理
定义：质量管理是确保信息系统满足用户需求与质量标准的全过程管理；配置管理是识别、控制、追踪系统配置项变更的工程活动。

关键要点：
- 质量管理三过程：规划质量管理+管理质量（QA过程审计）+控制质量（QC产品检验）
- QA vs QC 区别：QA过程导向（关注过程合规）+QC产品导向（关注产品合格）；QA预防胜于检查
- 软件质量六大特性（ISO/IEC 25010）：功能性+可靠性+易用性+效率+可维护性+可移植性
- 老七质量工具：因果图（鱼骨图4M1E人机料法环）+流程图+核对单+帕累托图（80/20法则）+直方图+控制图（UCL/LCL=均值±3σ）+散点图
- 新七质量工具：亲和图+关联图+树状图+矩阵图+PDPC过程决策程序图+活动网络图+箭线图
- 软件测试四阶段：单元测试→集成测试→系统测试→验收测试
- 测试覆盖率四指标：语句覆盖（最低）+分支覆盖+条件覆盖+路径覆盖（最严）；MC/DC（航空DO-178B要求）
- DoD完成定义（Definition of Done）：代码评审通过+单元测试覆盖率≥70%+接口测试通过+UAT用户验收通过+部署预发环境+文档完整
- 配置管理四大活动：配置项识别+配置项控制+配置状态报告+配置审计
- 配置项CI分类：基线配置项（FB/AB/PB）+非基线配置项
- 配置管理基线三件套：功能基线FB（需求分析后）+分配基线AB（概要设计后）+产品基线PB（详细设计后）
- 配置库四类型：开发库（动态库，程序员工作）+受控库（主库，已审核通过）+产品库（静态库，交付给用户）+备份库（灾难恢复）
- 配置项变更控制流程：变更申请→变更评审→变更批准→变更实施→变更验证→变更发布→基线更新
- 版本控制策略：主分支main/master（生产）+develop（开发）+feature（特性）+release（发布）+hotfix（热修复）
- 配置审计两类：配置项审计+基线审计
- 配置管理工具：SVN（集中式版本控制）+Git（分布式版本控制）；企业级配置库 GitLab/Gitee/Azure DevOps

## 案例分析题

**题目**：
某省人社厅启动"金保工程"三期信息化建设项目，建设覆盖全省5000万参保人的智慧社保服务平台。系统涉及人社、医保、财政、税务、银行等多部门数据共享，包含核心业务经办、基金监管、公共服务、决策分析四大子系统。项目预算8500万元，工期24个月。

项目启动阶段问题：
1. 项目经理由厅信息中心技术骨干兼任，同时承担其他3个信息化项目，每周投入本项目精力约40%；
2. 招标文件要求"具有HIS系统开发经验"（注：此处应为"具有社保行业系统集成经验"）+CMMI5级认证资质，全国仅7家IT企业获此资质；
3. 监理费按工程总投资1.5%计算（约127.5万元），符合行业惯例但偏低；
4. 商业计划书预算7500万元，立项批复8500万元，但1000万元资金缺口未明确来源；
5. 项目涉及5000万参保人数据共享，但未制定数据安全保护专项方案。

实施阶段问题：
6. 第6个月进行挣值分析：PV=3000万、EV=2500万、AC=2800万；
7. 第8个月核心业务子系统对接时，发现省人社数据中心机房PUE=2.4，远高于国家1.5标准，散热严重；
8. 第10个月省人社厅要求增加"区块链电子社保卡"功能（合同外，预算300万，工期+3个月）；
9. 第12个月发现承建方将模块开发违规分包给3家无资质公司；
10. 第15个月发生重大事故：电子社保卡系统被境外IP攻击，500万参保人身份证信息泄露；
11. 第18个月监理发现承建方未做等保三级测评擅自上线；
12. 第20个月承建方提交的变更申请累计影响达+1500万元（占原合同17.6%），超10%需重新招标。

问题：
(1) 请计算第6个月挣值指标SV、CV、SPI、CPI，分析项目绩效并预测EAC；
(2) 请从项目治理、招标采购、数据安全三个维度分析本项目的主要问题；
(3) 针对事件8（增加区块链功能）和事件10（数据泄露），监理应如何处理？

**参考答案**：

问题一：挣值分析计算

已知数据：PV=3000万、EV=2500万、AC=2800万

计算过程：
1. 进度偏差 SV = EV - PV = 2500 - 3000 = -500万（进度偏差-500万，项目进度严重滞后）
2. 成本偏差 CV = EV - AC = 2500 - 2800 = -300万（成本偏差-300万，项目成本超支）
3. 进度绩效指数 SPI = EV/PV = 2500/3000 ≈ 0.833（SPI<1且<0.9，进度效率83.3%）
4. 成本绩效指数 CPI = EV/AC = 2500/2800 ≈ 0.893（CPI<0.9，成本绩效89.3%）

绩效分析：
- 双重偏差：SV<0且CV<0，项目进度严重滞后且成本超支
- SPI=0.833 表示完成计划工作量的83.3%，比计划少完成16.7%
- CPI=0.893 表示项目每花1元仅产出0.893元的工作，资金使用效率偏低
- 当前状态项目可能延期且超支，必须立即采取纠偏措施

预测EAC：
- EAC = BAC/CPI = 8500/0.893 ≈ 9519万
- 即项目完工时预计总成本约9519万元，超支约1019万元

ETC剩余工作：
- ETC = EAC - AC = 9519 - 2800 = 6719万

TCPI完工尚需绩效指数：
- TCPI = (BAC-EV)/(BAC-AC) = (8500-2500)/(8500-2800) = 6000/5700 ≈ 1.053
- TCPI>1.0 表示剩余工作必须达到1.053的成本效率，难度较大

VAC完工偏差：
- VAC = BAC - EAC = 8500 - 9519 = -1019万

问题二：三维度问题分析

一、项目治理维度：
1. 项目经理身兼4职（厅技术骨干+本项目经理+其他3个信息化项目），每周投入精力40%严重不足
2. 商业计划书预算7500万vs立项批复8500万，1000万资金缺口未明确来源
3. 监理费1.5%（约127.5万元）虽符合行业惯例但偏低，难以保证监理投入
4. 项目集/项目组合管理缺失：未与其他3个信息化项目做优先级排序
5. 项目治理委员会未实质运作，决策机制不清晰
6. 项目启动阶段未建立完善的变更控制机制

二、招标采购维度：
1. CMMI5级资质要求存在明显指向性：全国仅7家具备，构成不合理条件
2. 该条款违反《政府采购法》及《公平竞争审查制度实施细则》关于不得设置不合理资质排斥潜在投标人的规定
3. 应采用CMMI3级或CMMI4级（适应本项目实际需求），避免指向特定主体
4. 承建方将模块违规分包给3家无资质公司，违反《招标投标法》关于禁止违法分包的规定
5. 总包对分包商管理失控，未对分包商资质严格审核
6. 分包合同管理缺位：未签订规范分包合同，未明确分包范围与责任

三、数据安全维度：
