## 今日核心概念
### 1. 信息系统战略规划（ISSP）
定义：以组织的业务战略为输入，识别信息系统建设目标、范围与演进路径，形成支撑业务发展的信息技术蓝图，是 IT 治理与 IT 战略对齐的核心方法论。
关键要点：
- 三层对齐：业务战略 → IT 战略 → 信息系统实施，必须自上而下分解、自下而上支撑
- 规划周期：3-5 年为典型规划窗口，每年滚动修订一次
- 主流方法：业务驱动（BSP）、数据驱动（ISP）、方法驱动（CSF）、战略驱动（SAM）
- 关键产出：IT 战略规划报告、信息系统建设方案、项目组合视图、年度实施计划

### 2. 信息技术服务管理（ITSM）
定义：以 ITIL 框架为核心，将 IT 活动抽象为"服务"并通过流程化、标准化、可度量的方式实现 IT 服务全生命周期管理的方法体系。
关键要点：
- 服务生命周期：战略 → 设计 → 过渡 → 运营 → 持续改进
- 十大核心流程：事件、问题、变更、发布、配置、事件、请求、可用性、容量、服务连续性、财务
- 服务台是单一联系点（SPOC），承担事件受理、分派、跟踪与用户沟通
- 与 IT 治理关系：ITSM 是治理落地工具，治理是 ITSM 的制度保障

### 3. SLA 服务级别协议
定义：服务提供方与客户（业务部门、用户）之间签订的、明确服务范围、可用性指标、响应/恢复时限、违约责任的正式协议，是 ITSM 中服务交付的"度量衡"。
关键要点：
- 关键指标：可用率（%）、MTTR（平均恢复时间）、MTBF（平均故障间隔）、RTO/RPO、首次响应时长
- 分级设计：核心服务 ≥ 99.99%、关键业务 ≥ 99.9%、一般系统 ≥ 99%
- 违约处罚机制：按未达标时长累计积分，对应服务费减免或补偿
- 评审周期：每季度回顾，每年至少一次重大修订，与业务需求同步

### 4. IT 治理成熟度模型
定义：评估组织 IT 治理水平从初始级到优化级的渐进式评估体系，用于识别治理短板并制定改进路线图。
关键要点：
- L1 初始级：流程临时、依赖个人、救火式管理
- L2 可重复级：关键流程标准化、项目级管理
- L3 已定义级：组织级流程统一、标准化文档体系
- L4 量化管理级：基于度量数据决策、CMMI/SOX 等量化合规
- L5 优化级：持续改进、量化反馈、变革驱动治理

### 5. 项目组合（Portfolio）管理
定义：在组织战略目标指导下，对多个项目群和项目进行优先级排序、资源分配、风险平衡与价值最大化管理的活动，是 PMO 的核心职责。
关键要点：
- 三层结构：战略 → 项目组合 → 项目群 → 项目，自上而下授权
- 关键决策：立项 / 暂缓 / 终止、优先级排序、资源再分配
- 平衡维度：战略一致性、收益、风险、资源消耗四象限评分
- 与单项目管理区别：组合管理关注"做正确的事"，单项目管理关注"正确地做事"

## 案例分析题
**题目**：某省政务云平台已运行 3 年，承载 47 个厅局委办的核心业务系统，近期出现以下问题：
1. 客户投诉：故障平均恢复时间由原 SLA 承诺的 4 小时升至 7.2 小时，月度服务可用率从 99.95% 降至 99.62%；
2. 内部审计：变更失败率由 5% 升至 18%，多次出现未经审批的紧急变更；
3. 资源层面：CPU 平均利用率达 78%，内存使用率 82%，存储 IO 接近瓶颈；
4. 组织层面：服务台人员年流失率 38%，3 名 ITIL 资深工程师相继离职。

请结合 IT 治理与 ITSM 相关知识，分析该平台存在的主要问题，并提出系统性改进建议。

**参考答案**：

【问题诊断】

1. **流程层面失效**
- 变更管理失效：未经审批紧急变更占比上升，变更评审与 CAB（变更咨询委员会）机制形同虚设；
- 事件/问题管理脱节：故障恢复时间劣化，但未触发问题根本原因分析（RCA），重复故障频发；
- SLA 管理失能：可用率与恢复时间双双超标，却未启动违约处置与服务改进计划。

2. **资源与容量管理缺位**
- CPU/内存/存储均接近瓶颈，但未启动容量评估与扩容规划；
- 容量管理流程缺失或未按周期执行预测性扩容。

3. **人员与知识管理危机**
- 关键岗位高流失率，未建立知识库与备份机制；
- 缺乏 ITIL 能力体系，岗位胜任力与培训机制不健全。

4. **治理层面失衡**
- 未建立 IT 治理委员会或委员会决策失能；
- 服务质量度量未纳入组织 KPI，缺少 PDCA 闭环。

【改进建议】

1. **治理强化（1-3 个月）**
- 重建 IT 治理委员会，由 CIO 牵头，业务部门负责人参与；
- 将可用率、SLA 达成率、变更合规率纳入服务商考核 KPI；
- 引入第三方治理成熟度评估，明确改进基线。

2. **流程整改（3-6 个月）**
- 强化变更管理：所有变更必须经 CAB 评审，紧急变更强制事后评审；
- 建立问题管理与重大事件复盘机制，强制 5-Why / 鱼骨图根因分析；
- 重新签订 SLA，将可用率、恢复时间、违约处罚条款量化。

3. **容量与资源规划（3-6 个月）**
- 启动容量评估与未来 12-24 个月需求预测；
- 制定分阶段扩容方案，优先解决 IO 与内存瓶颈；
- 建立资源使用基线与预警阈值（CPU >70% 预警、>85% 紧急扩容）。

4. **人员与知识管理（持续）**
- 建立关键岗位 AB 角与知识库；
- 推行 ITIL 能力认证，建立岗位胜任力模型；
- 改善激励与职业通道，降低核心人才流失。

5. **持续改进机制**
- 引入 CSI（持续服务改进）七步法，定期评审服务度量数据；
- 建立 PDCA 闭环：每月服务质量评审，每季度 SLA 回顾，每年治理复盘。

**踩分要点**：
1. 答出"治理-流程-技术-人员"四层结构，体现系统性思维（4 分）
2. 准确识别变更管理失效、SLA 失能、容量管理缺位三大核心问题（6 分）
3. 给出可落地的改进措施，含 CAB、容量预警、CSI 等专业术语（6 分）
4. 体现"PDCA 闭环 + 量化度量"的 ITSM 治理理念（4 分）
