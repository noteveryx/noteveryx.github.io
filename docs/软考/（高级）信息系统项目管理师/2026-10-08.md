## 今日核心概念

### 1. 项目成本管理的4个过程（规划、估算、预算、控制）

定义：项目成本管理包括为使项目在批准的预算内完成而对成本进行规划、估算、预算、融资、筹资、管理和控制的过程。

关键要点：
1. **规划成本管理**：制定成本管理计划，规定如何规划、估算、预算、管理、监督和控制项目成本。输入：项目章程、项目管理计划；输出：成本管理计划。
2. **估算成本**：对完成项目活动所需货币资源进行近似估算。可在详细程度不同的层级进行（粗略量级、确定性估算、预算估算）。
3. **制定预算**：汇总所有单个活动或工作包的估算成本，建立一个经批准的、成本基准。输出：成本基准+项目资金需求。
4. **控制成本**：监督项目状态以更新项目成本和管理成本基准的变更。全程贯穿监控成本偏差。

---

### 2. 挣值管理（EVM）三大基本值与四大指标

定义：挣值管理是将项目范围、进度、成本综合起来衡量项目绩效和进展的方法。

关键要点：
- **三大基本值**：
  - **PV（计划值 Planned Value）**：计划在某一时间点应完成工作的预算成本
  - **EV（挣值 Earned Value）**：实际完成工作的预算成本
  - **AC（实际成本 Actual Cost）**：实际完成工作的实际花费
- **四大指标**：
  - **CV = EV − AC**（成本偏差，>0节约、<0超支）
  - **SV = EV − PV**（进度偏差，>0提前、<0滞后）
  - **CPI = EV / AC**（成本绩效指数，>1节约、<1超支）
  - **SPI = EV / PV**（进度绩效指数，>1提前、<1滞后）

口诀记忆：CV/SV差值比零，CPI/SPI指数比一。

---

### 3. 完工估算（EAC）的四种典型公式

定义：EAC（Estimate at Completion）是完成所有项目工作的预期总成本，基于当前绩效和未来展望。

关键要点：
- **EAC = BAC / CPI**：当前 CPI 将影响未来所有剩余工作（典型/一致偏差）
- **EAC = BAC / (CPI × SPI)**：当前 CPI 和 SPI 同时影响（异常偏差）
- **EAC = AC + (BAC − EV)**：剩余工作按原计划执行（一次性异常）
- **EAC = AC + 自下而上的 ETC**：重新估算剩余工作成本（管理层干预后）

公式选择：偏差持续 → 用 BAC/CPI；偏差已纠正且未来按计划 → 用 AC+BAC−EV。

---

### 4. 成本估算方法（十大工具）

定义：根据项目范围、资源需求、历史信息，采用合适方法计算成本近似值。

关键要点：
1. **类比估算**：自上而下，依赖历史项目数据，精度低、速度快
2. **参数估算**：基于统计关系（如单位造价×面积），精度取决于参数模型
3. **自下而上估算**：先估算每个工作包，再汇总，精度最高但耗时
4. **三点估算**：(O + 4M + P) / 6（PERT） 或三角分布 (O+M+P)/3
5. **储备分析**：应急储备（应对已知-未知）+ 管理储备（应对未知-未知）
6. **质量成本**（COQ）：预防+评估+失败（内部+外部）成本权衡
7. **项目管理软件**：建模、跟踪、预测成本
8. **卖方投标分析**：多家供应商报价对比
9. **群体决策**：德尔菲法、头脑风暴
10. **专家判断**：咨询资深人员

---

### 5. 应急储备与管理储备的区别

定义：两种储备均是为应对不确定性预留的成本，但审批层级与用途不同。

关键要点：
- **应急储备（Contingency Reserve）**：含在成本基准内；应对"已识别风险"；项目经理有权动用；不需高层审批；动用在BAC中体现。
- **管理储备（Management Reserve）**：不含在成本基准内，但属于项目总预算；应对"未识别风险"或不可预见工作；动用需高层管理层审批。
- 计算关系：**总预算 = BAC + 管理储备**；**BAC = 工作成本 + 应急储备**。
- 挣值公式默认"剩余BAC"中包含应急储备，不包含管理储备。

---

## 案例分析题

**题目**：

某软件开发项目工期6个月，预算BAC=120万元，第3个月末项目状态报告如下：
- 第3个月末PV（计划值）= 60万元
- 第3个月末EV（挣值）= 45万元
- 第3个月末AC（实际成本）= 54万元

请回答以下问题（每题5分，共20分）：

（1）计算当前的成本偏差CV、进度偏差SV、成本绩效指数CPI、进度绩效指数SPI，并判断项目当前的成本和进度状态。

（2）若项目按当前绩效趋势继续，请估算完工估算EAC和完工偏差VAC。

（3）若项目经理决定采取纠正措施后，剩余工作将按原预算计划执行，请重新计算EAC和VAC。

（4）针对当前成本超支、进度滞后的情况，请提出至少3条具体的纠偏措施。

---

**参考答案**：

（1）指标计算与状态判断：
- CV = EV − AC = 45 − 54 = −9万元（负值 → **成本超支**）
- SV = EV − PV = 45 − 60 = −15万元（负值 → **进度滞后**）
- CPI = EV / AC = 45 / 54 ≈ **0.83**（<1 → 成本超支，每投入1元只完成0.83元的工作）
- SPI = EV / PV = 45 / 60 = **0.75**（<1 → 进度滞后，实际完成工作量仅占计划75%）

结论：项目当前**成本超支、进度滞后**，绩效较差，需立即采取双重纠偏。

（2）按当前绩效趋势（典型偏差）：
- EAC = BAC / CPI = 120 / 0.83 ≈ **144.58万元**
- VAC = BAC − EAC = 120 − 144.58 ≈ **−24.58万元**（即完工时预计超支约24.58万元）

（3）纠正后剩余按原计划执行：
- EAC = AC + (BAC − EV) = 54 + (120 − 45) = **129万元**
- VAC = BAC − EAC = 120 − 129 = **−9万元**（超支9万元）

（4）纠偏措施（至少3条）：
1. **赶工**：在关键路径上追加资源（人力加班、外包）以压缩工期；同时评估赶工引发的成本增加能否被延误罚款抵消。
2. **快速跟进**：将串行的活动并行执行（如测试与开发文档同步），降低进度滞后；但需关注返工风险和沟通成本。
3. **范围与成本基线重审**：与发起人/客户沟通，看是否可剔除低优先级需求（缩减范围），或申请追加预算；必要时走变更控制流程。
4. **加强成本与进度监控**：细化WBS，把挣值分析下沉到工作包层级；引入挣值趋势分析（EVT），早期识别绩效恶化趋势。
5. **排查根本原因**：鱼骨图分析超支原因（需求变更、返工、人员能力不足、采购成本高），针对性解决。

---

**踩分要点**：

1. **公式书写规范**：CV/SV必须明确为"EV−AC""EV−PV"，CPI/SPI必须明确为"EV/AC""EV/PV"，避免用反或漏写单位。
2. **正负号与判断表述**：偏差为负 → 超支/滞后；指数<1 → 超支/滞后。结论必须呼应计算结果，不可只算不算。
3. **EAC公式选择**：题目说"按当前绩效趋势"→ 用 BAC / CPI；"剩余按原计划执行" → 用 AC + (BAC − EV)；"重新估算"→ AC + 自下而上ETC。三种情境分清。
4. **纠偏措施落地性**：不可只写"加强管理"等套话；需具体到"赶工""快速跟进""范围变更""资源平衡"等术语。
5. **变更控制意识**：超出BAC的纠偏、范围调整必须走变更控制流程（CCB审批），这是高级考试的隐性得分点。

## 记忆口诀

### 口诀1：挣值三大值（PV / EV / AC）

"**PV是计划要花的，EV是干完该值多少钱，AC是实际花了多少**"

- PV：Plan Value（计划值）→ 计划工作的预算成本
- EV：Earned Value（挣值）→ 完成工作的预算成本
- AC：Actual Cost（实际成本）→ 完成工作的实际成本

### 口诀2：挣值四大指标判断

"**CV/SV比零，CPI/SPI比一；大于零或一就是好，小于就是糟**"

- CV > 0 节约，< 0 超支
- SV > 0 提前，< 0 滞后
- CPI > 1 节约，< 1 超支
- SPI > 1 提前，< 1 滞后

### 口诀3：EAC完工估算四公式

"**一除CPI乘SPI，二除CPI单变量，三是AC加剩余BAC，四是AC加新ETC**"

- 公式1：EAC = BAC / (CPI×SPI) 双重影响
- 公式2：EAC = BAC / CPI 仅成本影响
- 公式3：EAC = AC + (BAC−EV) 一次性异常
- 公式4：EAC = AC + 新ETC 重新估算

### 口诀4：成本管理四过程

"**规划估算加预算，控制贯穿管到底**"

- 规划成本管理 → 估算成本 → 制定预算 → 控制成本

### 口诀5：储备两层区别

"**应急在基准内、管理在基准外；应急项目经理动，管理要请高层批**"

- 应急储备 ⊆ 成本基准（BAC）→ PM可批
- 管理储备 ⊆ 项目总预算但 ∉ 成本基准 → 高层审批

### 口诀6：偏差率与绩效指数的关系

"**偏差率 = 1 − 1/指数**"

- 成本偏差率 = 1 − 1/CPI
- 进度偏差率 = 1 − 1/SPI
- 例：CPI=0.83 → 成本偏差率 = 1 − 1/0.83 ≈ −20%，即成本超支约20%。

# 第54次学习·项目资源管理与团队绩效域

## 今日核心概念

### 1. 项目资源管理六过程

定义：在项目中对人力、设备、材料、资金等资源进行规划、估算、获取、建设、管理与控制的全过程管理过程组，是项目成功的关键知识领域。

关键要点：
规划资源管理（Plan Resource Management）：编写资源管理计划，明确角色、职责、报告关系、获取/建设/管理/释放资源的策略与流程，输出资源管理计划与团队章程。
估算活动资源（Estimate Activity Resources）：依据WBS、工作包与活动清单，估算完成每个活动所需的资源类型、数量与规格，输出活动资源需求与资源分解结构（RBS）。
获取资源（Acquire Resources）：通过招聘、内部调拨、采购、外包、租赁等方式获取项目所需资源，输出实物资源分配单与团队组建文件，注意虚拟团队与预分派的特殊情况。
建设团队（Develop Team）：通过培训、团建、跨职能协作等方式提升团队整体能力与凝聚力，输出团队绩效评价，核心是个人与团队能力双提升。
管理团队（Manage Team）：跟踪团队成员绩效、解决冲突、协调变更、提供反馈与激励，处理人事问题，输出变更请求与项目管理计划更新。
控制资源（Control Resources）：按资源管理计划监督资源使用情况，识别偏离并采取纠偏措施，输出工作绩效信息与变更请求，确保资源按计划高效利用。

### 2. 激励理论五经典

定义：解释如何激发员工工作积极性与主动性的心理学理论体系，是团队建设与管理的理论基础。

关键要点：
马斯洛需求层次理论（Maslow）：生理→安全→社交→尊重→自我实现，五层递进，高级需求出现前必须先满足低级需求。
赫茨伯格双因素理论（Herzberg）：保健因素（薪酬、工作环境）防止不满意，激励因素（成就、认可、晋升）带来满意，二者独立作用。
麦格雷戈X理论与Y理论（McGregor）：X理论假设人性本懒需强制管控，Y理论假设人性本勤可自我激励，现代项目管理偏向Y理论。
弗鲁姆期望理论（Vroom）：激励力=效价×期望值×工具性，员工相信努力→绩效→奖励的链条才能被激励。
亚当斯公平理论（Adams）：员工会横向对比投入产出比，感觉不公平会降低积极性，薪酬体系设计必须考虑内部公平性与外部竞争性。

### 3. 团队发展五阶段

定义：布鲁斯·塔克曼（Bruce Tuckman）提出的团队从组建到成熟的演化过程模型。

关键要点：
形成期（Forming）：成员相互试探、礼貌客气、依赖领导指导，团队领导需明确目标与角色定位。
震荡期（Storming）：观点冲突、个性碰撞、目标分歧最严重，团队领导需采用协商型/引导型风格化解冲突，建立基本规则。
规范期（Norming）：磨合完成、信任建立、合作默契形成，团队开始高效协同。
成熟期（Performing）：自组织、自管理、高效产出，团队领导转向授权型，仅在例外时介入。
解散期（Adjourning）：项目结束或团队重组，需完成经验总结、知识归档、人员释放与表彰激励。

### 4. 领导力风格五类型

定义：项目经理在不同情境下可切换的领导行为模式，PMI强调情境领导力。

关键要点：
权威型（Authoritative）：单向指令、明确分工、紧急情况高效，但压制团队主动性，适用于震荡期或危机处理。
引导型（Democratic）：集体决策、充分讨论、提升参与感，但效率偏低，适用于规范期需共识的场景。
协商型（Facilitative）：协调利益、平衡冲突、促成合作，资源谈判与跨团队协作首选。
推动型（Coaching）：关注个人成长、教练式辅导、培养下属长期能力，1对1沟通与能力建设适用。
教练型（Coaching）：结合引导与教练、目标导向+成长导向双轮驱动，复杂环境与创新项目最佳。

### 5. 团队绩效域（PMBOK第七版）

定义：PMBOK第七版八大绩效域之一，聚焦团队文化、领导力与高绩效团队建设的成果导向领域。

关键要点：
关键成果：团队文化、领导力、高绩效团队三大成果，区别于过程导向的十大知识领域。
团队文化：建立透明、诚信、尊重、多元包容的心理安全感环境，鼓励建设性意见与试错文化。
领导力：项目经理通过服务型领导、情商管理与情境领导力激发团队潜能，而非命令控制。
高绩效团队：成员互信、目标一致、协作高效、持续学习，具备自组织与自适应能力。
与过程区别：绩效域强调"做什么成果"而非"按什么流程做"，是价值导向与原则导向的统一。

### 6. 责任分配矩阵（RACI）与RBS

定义：资源管理两个核心工具，前者明确谁做什么，后者明确资源如何分解。

关键要点：
RACI四角色：Responsible执行（干活的人）、Accountable问责（最终责任人唯一）、Consulted咨询（双向沟通）、Informed知会（单向通知）。
RBS（Resource Breakdown Structure）：资源分解结构，按资源类别（人力、设备、材料、资金）逐层分解到具体资源类型，是WBS在资源维度的镜像。
避免误区：每项活动只能有1个A（问责），可多个R，避免A太多导致责任真空或冲突。
虚拟团队与远程办公：RACI矩阵配合沟通管理计划与协作工具，解决跨时区跨地域协作责任界定问题。
实战案例：政务系统建设项目可按模块+角色双维度构建RACI，明确市局/区局/厂商/监理四方职责。

## 案例分析题

**题目**：

某市政务服务平台升级项目工期紧、涉及12个委办局数据对接，项目经理小李组建了30人的项目团队（含开发、测试、运维、产品、UI五类角色），团队成员来自不同厂商与政府部门。开发阶段出现严重冲突：开发组认为需求频繁变更影响进度，需求组指责开发对业务理解不到位；测试组发现缺陷但开发组以"业务要求必须如此"拒绝修改；两名核心开发因加班问题产生矛盾出现冷战；新入职的产品助理不熟悉流程常问基础问题被老员工嫌弃；项目中途一名架构师因高薪被挖走需紧急补充。

问题：
1. 试分析该项目团队目前处于塔克曼五阶段中的哪个阶段？说明判断依据。
2. 小李应分别采用哪种领导力风格处理以下三个问题：①化解开发组与需求组冲突；②处理两名核心开发冷战；③辅导新入职产品助理？
3. 小李应如何运用激励理论留住即将被挖的架构师？请给出至少两种理论的具体应用策略。
4. 请绘制该项目核心WBS工作包的RACI矩阵片段（要求覆盖需求分析、系统设计、代码开发、测试验收四个工作包，角色包含项目经理、开发组、需求组、测试组四方）。

**参考答案**：

问题1：
当前团队处于震荡期（Storming）。
判断依据：①角色冲突明显，开发组与需求组目标分歧严重；②人际冲突显现，两名核心开发冷战；③对新成员排斥（老员工嫌弃新助理）；④频繁出现职责与流程争议；⑤团队尚未建立统一规则与信任关系。
特征表现符合塔克曼震荡期的典型形态。

问题2：
①化解开发组与需求组冲突：采用引导型（协商型）领导力风格，组织三方联席会议，引导各方表达诉求、共同分析变更根因、建立需求变更控制流程（如CCB审批），达成共识后形成书面协议。
②处理两名核心开发冷战：采用协商型（Facilitative）领导力风格，分别1对1沟通了解真实诉求，组织非冲突情境下的合作任务（如结对编程），引入团建活动缓解对立，必要时调整分工避免直接冲突。
③辅导新入职产品助理：采用教练型/推动型（Coaching）领导力风格，指定导师1对1带教，编制标准化新人checklist，设定30/60/90天成长目标，定期回顾反馈，帮助快速融入并建立成就感。

问题3：
激励策略组合应用：
弗鲁姆期望理论：向架构师明确"留下来"能获得的具体回报（如股权激励、项目奖金、晋升承诺、培训机会），提高效价；同步提供能力提升通道（如参与架构决策），提高期望值。
亚当斯公平理论：调研行业同类架构师薪酬水平，结合内部薪资体系调整到市场75分位以上，确保内部公平性与外部竞争力，避免因不公平感流失。
马斯洛需求层次：识别架构师当前主导需求（若看重尊重与自我实现，则提供技术布道、团队带教、对外交流等机会），精准满足而非一刀切加薪。
赫茨伯格双因素：在保健因素（薪酬、工作环境）达标基础上，重点强化激励因素（赋予架构决策权、参与十四五规划项目、授予技术专家称号），让架构师获得成就感与认可。

问题4：RACI矩阵片段

| 工作包 | 项目经理 | 开发组 | 需求组 | 测试组 |
|---|---|---|---|---|
| 需求分析 | A | C | R | I |
| 系统设计 | A | R | C | C |
| 代码开发 | A | R | I | I |
| 测试验收 | A | I | C | R |

说明：
A（Accountable）问责，每个工作包唯一，确保责任清晰；
R（Responsible）执行，需求分析由需求组主导，设计与开发由开发组主导，测试由测试组主导；
C（Consulted）双向沟通，需求分析需开发组对可行性意见，设计需需求组确认业务理解、测试组提出可测试性建议，测试验收需需求组确认业务覆盖；
I（Informed）单向知会，开发过程对需求组/测试组透明，测试过程对开发组透明。

**踩分要点**：

阶段判断题：答对阶段名（1分）必须配判断依据（2分），依据要扣"冲突表现、人际冷战、新成员排斥、规则缺失"四点各0.5分。
领导力匹配题：领导力风格名称写对1分+适用场景描述清楚2分，风格与场景必须对应（如震荡期→协商型，不是权威型）。
激励理论题：至少答出2种理论名称（各1分），每种理论给出具体应用策略（各1.5分），避免泛泛"加薪晋升"必须扣理论关键词（如效价、期望值、公平、激励因素）。
RACI矩阵题：四角色填对（2分）+每行A唯一（1分）+R角色对应正确（1分），错误样例：每行有多个A或没有A都扣分。

## 记忆口诀

### 口诀1：资源六过程口诀

"**规划估算获取先，建设管理控制连**"

- 规划资源管理 → 估算活动资源 → 获取资源 → 建设团队 → 管理团队 → 控制资源

### 口诀2：RACI四角色口诀

"**问责唯一执行多，咨询双向知会单**"

- A（Accountable）问责，唯一不可多；
- R（Responsible）执行，可多个；
- C（Consulted）咨询，双向沟通；
- I（Informed）知会，单向通知。

### 口诀3：塔克曼五阶段口诀

"**形震规成解**"

- 形成期 Forming → 震荡期 Storming → 规范期 Norming → 成熟期 Performing → 解散期 Adjourning

### 口诀4：激励五理论口诀

"**马斯赫麦弗亚**"

- 马斯洛需求层次、赫茨伯格双因素、麦格雷戈XY理论、弗鲁姆期望理论、亚当斯公平理论

### 口诀5：领导力五风格口诀

"**权引协推教**"

- 权威 Authoritative → 引导 Democratic → 协商 Facilitative → 推动 Coaching → 教练型
- 情境切换不教条，震荡期选协商，规范期可放手，成熟期只管例外。

### 口诀6：PMBOK7绩效域八口诀

"**相关团队开规工交测不**"

- 相关方、团队、开发规划、项目工作、交付、度量、不确定性（八大绩效域核心八）

### 口诀7：RBS三层分解口诀

"**资源类别→资源类型→具体资源**"

- 人力（开发测试运维产品UI）→ 张三李四王五
- 设备（服务器笔记本测试机）→ XX型号XX台

### 口诀8：团队建设踩坑口诀

"**震荡期硬压反弹，规范期放手自驱**"

- 震荡期：禁止权威压制，必须协商引导；
- 规范期：禁止事事干预，应充分授权；
- 成熟期：仅在例外时介入。

### 口诀9：高频考点口诀

"**六过程排序不能乱，RACI四角色A唯一，激励必考双因素与期望，团队阶段塔克曼**"

- 资源六过程顺序是命题陷阱；
- RACI中A每行唯一是必考点；
- 激励理论赫茨伯格+弗鲁姆是高频组合；
- 团队发展五阶段塔克曼是经典老题。

### 口诀10：政务项目资源口诀

"**厂商政府双线管理，RACI四方对齐**"
