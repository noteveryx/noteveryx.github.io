## 今日核心概念

### 1. IT服务运营管理核心流程
定义：IT服务运营管理是对IT服务日常交付活动进行规划、协调、控制和改进的管理过程，核心目标是保障服务质量和业务连续性。
关键要点：事件管理——尽快恢复正常服务、最小化业务影响；事件分类包括硬件故障、软件故障、网络故障、安全事件、服务请求；事件优先级由影响和紧急程度决定；问题管理——找出事件根本原因并消除，防止重复发生；主动问题管理通过趋势分析预防问题；变更管理——标准变更（低风险预授权）、一般变更（CAB评审）、紧急变更（ECAB快速决策）；变更七步法包括提出变更请求RFC、影响评估、审批、计划、测试、实施、回顾；发布与部署管理——规划发布、构建发布、测试发布、部署发布、回顾发布；发布策略包括大爆炸发布、滚动发布、蓝绿发布、金丝雀发布；配置管理——CMDB配置管理数据库记录所有CI配置项及其关系；配置项包括硬件、软件、网络、文档、人员；配置管理确保变更可控、故障可定位；服务请求管理——处理用户的服务需求而非故障，如账号申请、权限开通、软件安装；通过服务目录和自助门户提高处理效率。

### 2. 系统可用性管理与容量管理
定义：可用性管理是确保IT服务达到约定可用性水平的过程；容量管理是确保IT基础设施容量能够满足当前和未来业务需求的过程。
关键要点：可用性公式——可用性=MTBF/(MTBF+MTTR)，其中MTBF平均故障间隔时间、MTTR平均修复时间；可用性指标——99.9%（年停机8.76小时）、99.99%（年停机52.56分钟）、99.999%（年停机5.26分钟）；高可用设计——冗余（双机热备、集群、负载均衡）、故障转移（主备切换、自动切换）、容错（RAID、多活架构）；容量管理三层次——业务容量（业务增长预测）、服务容量（服务能力规划）、组件容量（CPU/内存/磁盘/网络/数据库连接池）；容量管理流程——监控→分析→预测→规划→实施→回顾；容量预测方法——趋势分析、回归分析、模拟仿真；性能监控指标——CPU利用率、内存使用率、磁盘I/O、网络带宽、响应时间、吞吐量、并发数、错误率；容量不足预警信号——资源利用率持续超过80%、响应时间明显增长、频繁出现资源争用、高峰期系统接近瓶颈；容量规划输出——容量计划、扩容建议、预算申请。

### 3. 数据治理与数据安全管理
定义：数据治理是对数据资产进行管理、控制和保护的体系化活动；数据安全管理是确保数据机密性、完整性、可用性的技术和管理措施。
关键要点：数据治理六要素——数据标准、数据质量、元数据、主数据、数据安全、数据生命周期；数据标准——统一数据定义、编码规则、数据格式、接口规范；数据质量维度——完整性、准确性、一致性、及时性、唯一性、有效性；元数据管理——记录数据来源、含义、负责人、更新频率、血缘关系；主数据管理——对组织核心业务实体（客户、供应商、物料、人员、机构）建立唯一权威数据源；数据生命周期——产生、采集、存储、处理、使用、共享、归档、销毁；数据分类分级——公开数据、内部数据、敏感数据、核心数据；数据安全保护——传输加密TLS/SM2、存储加密AES-256/SM4、数据脱敏、访问控制、审计日志、备份恢复；个人信息保护——最小必要原则、告知同意、敏感信息特殊保护、跨境传输评估；数据安全法要求——数据分类分级保护、重要数据目录、数据安全风险评估、数据出境安全评估；隐私计算技术——多方安全计算MPC、联邦学习、差分隐私、可信执行环境TEE。

### 4. 网络管理与高可用技术
定义：网络管理是对网络设备、链路、流量、安全进行监控、配置、故障处理和性能优化的活动；高可用技术是通过冗余和快速切换保障网络服务持续可用的设计方法。
关键要点：网络管理五大功能域——故障管理、配置管理、计费管理、性能管理、安全管理（FCAPS）；SNMP协议——简单网络管理协议，包括NMS网络管理站、Agent代理、MIB管理信息库、Trap告警；网络监控工具——Zabbix、Nagios、Prometheus、Cacti、SolarWinds；网络性能指标——带宽、时延、抖动、丢包率、吞吐量；负载均衡技术——DNS轮询、硬件负载均衡器F5、软件负载均衡Nginx/LVS/HAProxy；负载均衡算法——轮询、加权轮询、最少连接、源地址哈希、最小响应时间；高可用协议——VRRP虚拟路由冗余协议、HSRP热备份路由协议、堆叠技术、链路聚合LACP；故障检测技术——BFD双向转发检测、IP SLA、Ping/Traceroute；网络冗余设计——核心交换机双机热备、链路双上行、多ISP出口、数据中心双活；SDN软件定义网络——控制平面与数据平面分离，集中式控制器动态下发流表；SD-WAN软件定义广域网——智能选路、链路聚合、云网融合。

### 5. 智能运维AIOps与监控体系
定义：AIOps是结合人工智能与大数据技术，对IT运维数据进行智能分析，实现异常检测、根因分析、告警收敛和自动化处置的运维模式。
关键要点：AIOps三大数据源——指标Metrics、日志Logs、追踪Traces；AIOps五大能力域——数据采集合规、异常检测、根因分析、告警收敛、智能预测；监控体系三层——基础设施监控（服务器/网络/存储）、应用性能监控APM（代码级性能分析）、业务监控（业务指标实时监控）；可观测性三支柱——Metrics指标、Logs日志、Traces链路追踪；告警收敛方法——时间窗口合并、相似事件聚合、依赖关系抑制、机器学习降噪；根因分析技术——关联分析、因果推理、知识图谱、拓扑影响分析；自动化运维——脚本自动化、配置管理Ansible/SaltStack/Puppet、容器编排Kubernetes、CI/CD流水线；ChatOps——在即时通讯工具中集成运维机器人，实现命令执行、告警通知、协作处理；SRE站点可靠性工程——用软件工程方法解决运维问题，强调错误预算、SLI/SLO/SLA、自动化；AIOps应用场景——容量预测、故障预测、异常检测、智能告警、自动扩缩容、变更影响分析。

## 案例分析题

**题目**：
某市政务云平台承载全市40个委办局的200多个政务应用，日均访问量约500万次，高峰期并发约10万。平台采用传统烟囱式运维模式，各委办局各自管理，存在以下问题：

1. 故障响应慢：平均故障发现时间30分钟，平均恢复时间4小时，年度可用性仅99.5%；
2. 告警风暴：监控平台每天产生约1万条告警，其中80%为无效告警，运维人员疲于应对；
3. 容量不足：每年电子政务高峰期（如两会、双十一期间）平台多次出现CPU利用率超过95%、数据库连接池耗尽；
4. 数据孤岛：40个委办局数据标准不统一，同一市民在不同系统中存在多个编码，数据共享困难；
5. 网络单点：核心交换机仅一台，一旦故障整个云平台中断；互联网出口仅一条运营商链路；
6. 安全事件：近期发生一次勒索病毒攻击，导致3个委办局业务中断12小时，部分数据被加密。

请回答：
(1) 请设计政务云平台统一运维管理体系；
(2) 请给出可用性提升与容量管理方案；
(3) 请给出数据治理与数据安全方案；
(4) 请给出网络高可用与安全加固方案。

**参考答案**：

(1) 统一运维管理体系设计

一、运维组织架构：
1. 成立市级政务云运维管理中心，统一负责全市政务云运维。
2. 设立三线运维体系：一线服务台（统一受理、初步分拣、工单派发）、二线专业技术团队（系统/网络/数据库/安全/应用）、三线厂商支持（云服务商、软硬件原厂）。
3. 建立值班经理制度，7×24小时值守，重大事件30分钟内升级至负责人。

二、运维流程体系：
1. 事件管理：统一事件受理渠道（电话、邮件、工单系统、监控自动派单），按影响和紧急程度分级P1-P4，明确SLA：P1级15分钟响应、2小时恢复；P2级30分钟响应、4小时恢复。
2. 问题管理：对重复性事件、重大事件开展RCA根因分析，形成已知错误数据库KEDB和永久修复方案。
3. 变更管理：所有变更走RFC流程，重大变更经CAB评审，紧急变更ECAB事后补审，变更窗口避开业务高峰。
4. 发布管理：制定发布计划、回滚方案、灰度发布策略，发布前在测试环境验证。
5. 配置管理：建立CMDB，纳管服务器、虚拟机、网络设备、应用系统、数据库、中间件、依赖关系。

三、监控与AIOps：
1. 建设统一监控平台，覆盖基础设施、应用性能、业务指标、安全态势。
2. 引入AIOps进行告警收敛和根因分析，将每日1万条告警压缩至200条以内有效告警。
3. 建立运维知识库和自动化运维脚本库，提升故障处理效率。

四、服务目录与SLA：
1. 制定统一服务目录，明确服务内容、服务标准、服务流程。
2. 与40个委办局分别签订SLA，约定可用性、响应时间、恢复时间、服务报告。

(2) 可用性提升与容量管理方案

一、可用性提升目标：
1. 将年度可用性从99.5%提升至99.95%（年停机从43.8小时降至4.38小时）。
2. 故障发现时间从30分钟缩短至5分钟，平均恢复时间从4小时缩短至1小时。

二、高可用架构改造：
1. 应用层：无状态化设计，多实例部署，通过负载均衡自动分发流量，单点故障自动剔除。
2. 数据库层：采用主从复制+读写分离，关键数据库使用MGR或主备集群，RTO<15分钟，RPO<5分钟。
3. 中间件层：Redis Cluster、RocketMQ集群、Nacos集群部署，避免单点。
4. 引入同城双活或异地灾备架构，关键业务实现秒级切换。

三、容量管理方案：
1. 建立容量监控基线，对CPU、内存、磁盘、网络、数据库连接池等关键指标持续监控。
2. 每年开展两次容量评估，结合业务增长预测制定扩容计划。
3. 建立自动伸缩机制，高峰期自动扩容虚拟机/容器实例，低谷期自动缩容。
4. 数据库连接池优化：根据并发量合理设置最大连接数，引入连接池监控和慢查询治理。
5. 业务高峰期前开展压力测试和容量演练，提前发现瓶颈。

(3) 数据治理与数据安全方案

一、数据治理体系：
1. 成立数据治理委员会，制定《政务云数据标准规范》《数据共享交换管理办法》。
2. 建立统一数据资源目录，明确40个委办局数据资产清单、数据责任主体、共享属性。
3. 建设主数据管理平台，统一市民、法人、机构、事项等核心实体的编码和数据标准。
4. 建立数据质量规则，定期开展数据质量检查和清洗，确保数据完整、准确、一致。
5. 建设数据共享交换平台，通过API网关、消息队列、数据接口等方式实现安全共享。

二、数据安全方案：
1. 数据分类分级：将数据分为公开、内部、敏感、核心四级，敏感个人信息、政务核心数据重点保护。
2. 数据加密：传输层TLS/SM2加密，存储层AES-256/SM4加密，密钥由KMS/HSM管理。
3. 数据脱敏：非授权场景下对身份证号、手机号、银行卡号等敏感字段脱敏。
4. 访问控制：基于RBAC+ABAC模型，最小权限原则，敏感数据操作需审批留痕。
5. 数据备份：3-2-1备份策略，关键数据异地备份，定期演练恢复。
6. 数据审计：对数据访问、导出、修改全量审计，日志保留≥180天。
7. 勒索病毒防护：终端安装EDR、网络部署防病毒网关、关闭高危端口、定期漏洞扫描和补丁更新、禁止U盘等外接存储。

(4) 网络高可用与安全加固方案

一、网络高可用：
1. 核心交换机双机热备：部署两台核心交换机，通过VRRP或堆叠实现冗余，单台故障自动切换。
2. 互联网出口多链路：至少接入两家不同运营商链路，通过负载均衡或智能DNS实现冗余。
3. 链路聚合：服务器双网卡绑定，接入交换机双上联，消除单链路故障。
4. 数据中心网络分区：划分为互联网区、政务外网区、内部管理区、数据库区，各区之间通过防火墙隔离。
5. 引入SDN或SD-WAN技术，实现网络流量智能调度和快速故障切换。

二、安全加固：
1. 边界防护：部署下一代防火墙、WAF、入侵检测/防御系统、抗DDoS设备。
2. 零信任架构：不信任任何内外部访问，所有访问需经过身份认证、设备认证、最小授权。
3. 安全域隔离：不同委办局业务划分独立安全域，东西向流量实施微分段。
4. 漏洞管理：定期开展漏洞扫描、渗透测试，建立漏洞修复闭环。
5. 安全运营中心SOC：7×24小时安全监控，关联分析安全事件，快速响应勒索病毒等攻击。
6. 应急响应：制定网络安全事件应急预案，明确勒索病毒、DDoS、数据泄露等场景处置流程，定期开展演练。

**踩分要点**：
- 统一运维体系必须包含三线运维、事件/问题/变更/发布/配置管理流程、服务台、SLA、CMDB、AIOps告警收敛
- 可用性提升必须包含可用性公式、高可用架构（应用/数据库/中间件集群）、RTO/RPO、容量管理（监控/评估/预测/自动伸缩）
- 数据治理必须包含数据标准、主数据、元数据、数据质量、数据共享交换；数据安全必须包含分类分级、加密脱敏、访问控制、备份、审计、勒索病毒防护
- 网络高可用必须包含核心交换机冗余、多ISP出口、链路聚合、网络分区；安全加固必须包含边界防护、零信任、安全域隔离、SOC、应急响应
- 关键数字：40委办局/200应用/500万日访问/10万并发/99.5%→99.95%/30分钟→5分钟发现/4小时→1小时恢复/1万告警→200有效
