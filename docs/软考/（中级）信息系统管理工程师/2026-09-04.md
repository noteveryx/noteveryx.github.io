## 今日核心概念
### 1. 项目风险管理
定义：在项目全过程中对风险进行识别、评估、应对和监控，以最小化威胁、最大化机会的系统化管理活动。
关键要点：
1. 风险≠问题：风险是未来不确定事件（可能发生也可能不发生），问题是已经发生的事件。
2. 风险四要素：风险事件、概率、影响、时间窗口；评估时既要给概率也要给影响。
3. 七大过程：规划风险管理、识别风险、定性风险分析、定量风险分析、规划风险应对、实施风险应对、监控风险。
4. 风险登记册是核心工具：贯穿整个项目周期，从识别→分析→应对→监控持续更新。
5. 消极风险（威胁）四策略：规避、转移、减轻、接受；积极风险（机会）四策略：开拓、提高、分享、接受。
6. 风险定性用概率影响矩阵（P-I矩阵）；定量分析用蒙特卡洛模拟、决策树分析、EMV期望货币值。
7. 储备金分类：应急储备（已知风险、成本基准内）+管理储备（未知风险、需变更流程动用）。

### 2. 项目采购管理
定义：从外部获取项目所需产品、服务或成果的全过程管理，确保采购过程合规、成本可控、质量达标。
关键要点：
1. 四大过程：规划采购管理、实施采购、控制采购、结束采购。
2. 五种采购方式：公开招标、邀请招标、竞争性谈判、询价采购、单一来源；政府采购200万以上公开招标。
3. 采购文件四件套：SOW工作说明书、RFI信息邀请书、RFQ报价邀请书、RFP建议书邀请书。
4. 供方选择四技术：最低成本、加权打分、筛选系统、独立估算；谈判是通用辅助。
5. 控制采购要点：管理采购关系、监督合同绩效、变更控制、付款审核、索赔管理。
6. 采购收尾三步：合同收尾（验收、关闭合同）、档案归档（采购文件保存5年）、经验教训总结。
7. 低于成本价调查程序：投标人报价低于成本或高于最高限价时，评标委员会应要求其说明理由。

### 3. 项目合同管理
定义：对合同签订、履行、变更、收尾全过程进行管理，确保合同双方权利义务清晰、风险可控、争议及时解决。
关键要点：
1. 合同三类型：总价合同（FFP固定总价/FPIF总价加激励）、成本补偿合同（CPFF/CPIF/CPAF/CPPC）、工料合同（T&M）。
2. CPIF激励费公式：实际成本+（目标成本-实际成本）×分担比+激励费；卖方低于目标成本越多分得越多。
3. 合同条款六件套：标的、价款、履行、违约责任、争议解决、变更。
4. 合同变更五步：申请→评审→批准→实施→验证；不能以口头协议代替书面变更。
5. 合同收尾三件套：验收（功能/性能/文档）、行政结算（尾款、保证金）、合同档案归档。
6. 质保金：通常5%-10%，缺陷责任期满后退还；质保期一般1-2年。
7. 争议解决四路径：协商→调解→仲裁→诉讼；仲裁一裁终局、诉讼可上诉。
8. 索赔四要素：索赔依据（合同条款）、28天时限通知、证据（同期记录）、报告（详细计算）；反索赔同步进行。

### 4. 项目收尾管理
定义：项目或阶段正式结束的全过程管理，包括合同收尾、行政收尾和经验教训总结，确保项目成果可交付、可归档、可复用。
关键要点：
1. 两大子过程：合同收尾（核实已完成工作、合同条款关闭、最终付款）+行政收尾（资源释放、档案归档、经验教训）。
2. 合同收尾六步：履约验证→验收测试→合同条款关闭→担保释放（如质保金）→最终付款→合同档案归档。
3. 行政收尾五件套：项目档案、经验教训、资源释放报告、移交报告、最终通知。
4. 经验教训三原则：客观（基于事实）、结构化（按过程域分类）、可复用（形成OPA组织过程资产）。
5. OPA组织过程资产三类：流程资产（模板、流程）、数据资产（数据库、知识库）、知识资产（最佳实践、教训）。
6. 收益后评估五维度：战略对齐、财务收益、用户满意度、运维质量、风险后效；分3月/6月/12月三次评估。
7. 未决索赔必须在28天内正式提出，否则视为放弃；变更审批必须走CCB五步流程。

### 5. 项目干系人管理深化
定义：在项目全过程中识别、分析、干系人参与、监控干系人参与的系统化活动，确保干系人期望合理、管理一致、风险可控。
关键要点：
1. 四大过程：识别干系人、规划干系人管理、管理干系人参与、监控干系人参与。
2. 权力利益方格四象限：高权力高利益重点管理、高权力低利益让其满意、低权力高利益随时告知、低权力低利益监督即可。
3. 凸显模型三维度：权力（Power）、紧迫性（Urgency）、合法性（Legitimacy）；三维度都高是核心干系人。
4. 参与程度五级别：不知晓、抵制、中立、支持、领导；目标是从不知晓/抵制提升到支持/领导。
5. CD差距分析法：当前状态C vs 期望状态D；差距=需要弥合的参与度调整。
6. 干系人登记册：身份信息、评估信息、干系人分类（内外/支持反对）、沟通需求；是核心管理工具。
7. 干系人变更控制：新干系人出现时必须更新登记册；离职或调岗的干系人也要及时清理。

## 案例分析题
**题目**：某市数据局2026年3月启动"智慧城市数据底座"项目，工期12个月，预算1800万元。项目包括数据采集、数据治理、数据共享、数据安全四个子系统。承建单位A公司采用总价合同FFP（1800万），关键路径为：数据采集(60天)→数据治理(90天)→数据共享(90天)→数据安全(60天)+并行测试验收(60天)。

项目执行过程中发生以下事件：

事件一：第3个月数据采集子系统中标后，A公司发现某项核心数据接口须对接市应急局，但应急局要求按其专有协议定制开发（约增80万元成本）。A公司认为属于"原合同范围"，拒绝增加费用；数据局认为属于"未预见条件"，要求A公司承担。双方僵持3周未决。

事件二：第6个月项目盘点时，项目经理小王发现：项目已发生62项风险，其中高风险15项，但风险登记册仅更新到第2个月初版，5项高风险未制定应对措施；近一个月连续发生"数据治理规则冲突""接口联调超时""A公司核心开发李工离职"三起事件。

事件三：第9个月数据共享子系统中标后又新增3家政府部门（应急局、城管局、市场监管局）要求接入，应用集成商B公司提出追加接口开发费120万元；A公司以总价合同为由拒绝，数据局领导口头答应"先做后谈"。

事件四：第12个月项目验收前，数据局审计发现：A公司实际成本1850万元（超预算50万），但合同为FFP；数据治理子系统交付延迟45天；18项已识别高风险中6项已转化为问题；项目未做阶段性的经验教训总结。

请回答：
1. 针对事件一中的争议，你作为第三方顾问应如何判定？依据是什么？应采取哪些争议解决措施？
2. 事件二反映出项目风险管理存在哪些问题？应如何整改？写出风险应对四策略并结合本场景举例。
3. 事件三中"口头答应先做后谈"是否合规？项目合同变更应遵循哪些原则？写出合同变更五步流程。
4. 事件四反映出项目收尾管理存在哪些问题？写出行政收尾五件套、经验教训三原则和收益后评估五维度的内容。
5. 综合上述四个事件，给出该项目的复盘总结（不少于200字）。

**参考答案**：
1. 争议判定：
   - 判定结论：应认定为"有经验的承包商也无法合理预见"的未预见条件，属于合同变更情形，A公司有权索赔但不能擅自拒绝履行。
   - 判定依据：①《民法典》合同编第533条（情势变更）+第770条（承揽合同）；②总价合同FFP适用于范围清晰、风险可控的情况，但"未预见条件"属于例外；③如合同专用条款约定"原合同范围"，应按FIDIC红皮书关于"不利物质条件"条款处理；④不可抗力、异常恶劣气候、不利物质条件等可作为变更依据。
   - 争议解决措施：①先协商（争取3个工作日内达成补偿共识）；②协商不成由争议调解小组介入；③调解无效按合同约定提交仲裁委员会（合同应明确仲裁机构）；④仲裁一裁终局，对方不履行可申请法院强制执行。
   - 整改建议：①立即签订补充协议，明确应急局接口开发范围、费用、进度调整；②暂列费用80万元从管理储备金中支取；③补充应急局接口技术规格、验收标准；④同步更新WBS、进度基准、成本基准；⑤分析A公司索赔权利，确保不超28天时限。

2. 风险问题及整改：
   - 风险问题：①风险识别不全面（62项风险说明风险库已建立但更新滞后）②风险登记册未持续更新（停留在第2月初版）③风险定性/定量分析缺失（高风险15项未明确概率和影响）④风险应对措施制定不足（5项高风险无应对）⑤风险监控不到位（已转化为问题的风险未及时识别）⑥风险责任人未明确（"李工离职"风险无预案）。
   - 整改措施：①每两周召开风险评审会，更新风险登记册；②对15项高风险做定量分析（EMV、概率×影响）；③制定每项高风险的应对策略和触发条件；④将"李工离职"等人员风险纳入应对计划（AB岗、知识共享）；⑤建立风险预警机制（黄灯/红灯）；⑥储备金分配：应急储备金（已知风险）+管理储备金（未知风险）。
   - 风险应对四策略举例：①规避（如取消高风险第三方依赖、改用自研）；②转移（给核心数据购买保险或外包给B公司）；③减轻（要求A公司核心开发AB岗、关键模块双备份）；④接受（签批承担剩余风险，如预算浮动5%以内）。

3. 合规性与变更流程：
   - 不合规理由：①"口头答应"不具合同效力，违反书面变更原则；②未做影响分析，盲目扩大范围；③绕过了CCB审批流程；④违反《政府采购法》及《民法典》合同变更条款；⑤未签订补充协议将留下法律隐患。
   - 合同变更原则：①书面原则（任何变更必须签订书面协议）；②影响分析原则（范围/进度/成本/质量/风险）；③审批原则（CCB或采购委员会批准）；④先谈后做原则（达成一致再实施）；⑤变更追溯原则（归档、可审计）。
   - 合同变更五步流程：①变更申请（提出方提交，含变更理由和期望目标）→②评审（项目经理组织影响分析，CCB审批）→③批准（CCB决策，调整范围/进度/成本基线）→④实施（按变更后方案执行，先测试后上线）→⑤验证（确认变更效果、归档）。
   - 本场景整改：①立即停止未经审批的接口开发；②组织CCB评审三项新增接入的影响；③按追加成本协商三方（A公司+B公司+数据局）签订补充协议；④调整进度基准和成本基准；⑤更新采购文件和合同。

4. 收尾管理问题：
   - 问题：①合同收尾不全（FFP合同超预算50万未明确责任，未按合同条款索赔/补偿）；②阶段经验教训缺失（未做阶段性复盘）；③风险闭环不到位（6项风险已转化为问题未记录）；④延迟交付未走违约处理（延迟45天按合同应扣违约金）；⑤文档归档滞后。
   - 行政收尾五件套：①项目档案（技术文档、管理文档、合同文档）；②经验教训（项目过程中获得的知识沉淀）；③资源释放报告（人员、设备、资金的释放）；④移交报告（向运维方/客户的正式交付）；⑤最终通知（项目正式结束的通告）。
   - 经验教训三原则：①客观（基于事实，避免主观评价）；②结构化（按十大过程域或PMBOK知识领域分类）；③可复用（形成模板、检查单、最佳实践，纳入OPA）。
   - 收益后评估五维度：①战略对齐（项目是否支撑组织战略）；②财务收益（投资回报率ROI、净现值NPV）；③用户满意度（核心干系人满意度评分）；④运维质量（系统可用率、故障率、MTTR）；⑤风险后效（已发生风险的处置效果、剩余风险）。
   - 本场景整改：①按FFP合同处理超支50万（A公司承担）；②按合同扣违约金（延迟45天×日均合同额×违约金比例）；③补做月度经验教训总结；④风险闭环报告；⑤启动12个月后的收益后评估。

5. 综合复盘总结：
   本项目暴露的核心问题在于"四重四轻"：重建设轻规划、重进度轻风险、重技术轻合同、重实施轻收尾。具体表现为：①采购阶段对未预见条件评估不足，FFP总价合同约定不明导致争议；②风险管理体系空转，登记册停在第二月初版，未形成闭环；③合同变更依赖领导口头承诺，违反书面原则和CCB审批程序；④收尾管理流于形式，缺乏阶段性的经验教训沉淀和收益后评估机制。整改建议：①完善采购文件的不可预见条件条款，建立应急费用池；②建立风险月度评审机制，强制高风险闭环；③严格执行合同变更五步流程，杜绝口头承诺；④将项目复盘纳入里程碑强制节点；⑤建立收益后评估3-6-12月三级跟踪机制，确保信息化投资发挥实效。

**踩分要点**：
1. 风险≠问题是常考易混点，必答；风险四要素必答出3个以上。
2. 消极风险应对四策略（规避/转移/减轻/接受）必答全；积极风险应对四策略必答全。
3. 概率影响矩阵P-I、蒙特卡洛模拟、EMV决策树是定量分析核心工具。
4. 合同三类型必答出FFP/CPFF/T&M的区别；总价合同适用于范围清晰项目。
5. 合同变更五步流程（申请→评审→批准→实施→验证）必答出。
6. 争议解决四路径（协商→调解→仲裁→诉讼）必答出，仲裁一裁终局是常考点。
7. 索赔四要素（依据/28天时限/证据/报告）是高频踩分点。
8. 行政收尾五件套必答全；经验教训三原则（客观/结构化/可复用）必答出。
9. 收益后评估五维度必答出至少4个；3-6-12月三级评估时间点必答。
10. 口头变更不合规必答；FFP合同超支由承包商承担必答。

## 记忆口诀
### 风险管理七过程口诀
**「规识定定应实监」**
- 规划风险管理（规划）
- 识别风险（识别）
- 定性风险分析（定性）
- 定量风险分析（定量）
- 规划风险应对（应对规划）
- 实施风险应对（实施）
- 监控风险（监控）

### 风险四要素口诀
**「事概影时」**
- 风险事件（什么可能发生）
- 概率（多大可能发生）
- 影响（发生后后果多严重）
- 时间窗口（何时会发生）

### 消极风险四策略口诀
**「规转减接」**
- 规避 Eliminate（取消高风险活动）
- 转移 Transfer（保险、外包）
- 减轻 Mitigate（降低概率或影响）
- 接受 Accept（签批承担残余风险）

### 积极风险四策略口诀
**「开提分接」**
- 开拓 Exploit（确保机会实现）
- 提高 Enhance（增加概率或影响）
- 分享 Share（与第三方共担）
- 接受 Accept（把握机会但不主动追求）

### 采购四过程口诀
**「规实控结」**
- 规划采购管理
- 实施采购
- 控制采购
- 结束采购

### 政府采购五方式口诀
