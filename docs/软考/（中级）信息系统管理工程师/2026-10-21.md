## 今日核心概念

### 1. 信息化体系六要素与信息化发展战略

定义：信息化体系六要素是信息化建设的整体框架，包括信息化政策法规、信息化规划、信息化基础设施、信息技术应用、信息化人才、信息化管理体系六个方面，缺一不可、互相支撑。

关键要点：
1. 政策法规是前提与保障，起导向和约束作用；规划是先导；基础设施是基础；技术应用是核心；人才是关键；管理体系是支撑。
2. 信息化发展战略三个层次：信息化总体发展战略、信息化战略规划（信息化专项规划）、信息化部署战略（区域/行业/企业部署）。
3. 国家信息化发展战略六方面：坚持 aiding 经济转型升级、推进社会信息化、发挥政府主导作用、加强保障、改善信息安全、缩小数字鸿沟（不同版本表述略有差异，以"经济社会信息化主攻方向、政府主导、企业主体、社会参与"为总纲）。
4. 新型信息化发展的核心要求：统一顶层设计、统筹技术创新、推进产业数字化转型、强化数据要素赋能、保障网络安全。
5. 数字化转型与信息化的区别：信息化解决"有没有、用没用"，数字化转型解决"业务模式、价值创造方式的重构"，以数据要素为关键支撑，以业务价值为导向。

### 2. IT治理体系（COBIT + ITIL + ISO/IEC 38500）

定义：IT治理是为实现组织战略目标，对IT系统的决策权归属与责任框架，负责评估IT的价值、风险与资源，是连接战略与执行的桥梁。

关键要点：
1. IT治理五域（COBIT 2019 五大领域）：治理与目标（EDM）、信息和技术寻求服务（APO）、创建交付和支持服务（BAI）、监控评估调整过程与风险（DSS）、管理安全与风险（MEA）。
2. 治理与目标域（EDM）的五大实践：评估与选择战略、评估与选择价值交付、评估与选择资源优化、评估与选择风险、评估与监控信息和技术，其中价值交付评估与风险评估是最高频考点。
3. IT治理的关注点三要素：IT资源使用效率（价值）、IT风险可控性（风险）、IT投资合规性（合规/资源）。
4. ISO/IEC 38500 是 IT治理国际标准，核心原则六条：责任（Responsibility）、战略（Strategy）、获取（Acquisition）、绩效（Performance）、遵从（Conformance）、行为（Behaviour）。
5. 三体系定位：COBIT 管"该不该做、做得对不对"（治理与控制目标）、ITIL 管"怎么做得好"（服务价值交付）、ISO/IEC 38500 管"整体方向与责任"（治理原则）。
6. 企业架构规划（EAP）是从业务架构、数据架构、应用架构、技术架构、安全架构五个层面进行全局规划，是IT治理落地的重要工具。
7. 治理失效的典型信号：IT与业务两张皮、决策无单一责任人、投入无人负责产出、审计发现问题后无人整改。

### 3. 信息化组织体系与岗位职责

定义：信息化组织体系是为承担信息化职能而在组织内部建立的部门、岗位与协作机制，通常实行"信息化的CIO负责制"。

关键要点：
1. 信息化组织三职能：信息化领导与决策（信息化领导小组/CIO）、信息化管理与执行（信息中心/信息化部门）、信息化服务与支持（运维、服务台、外包供应商）。
2. 信息化的组织模式三层次：分散式（各自为政，信息孤岛）、集中式（统一建设，强管控）、混合式（集中规划+分散实施），政务领域普遍采用混合式。
3. CIO（首席信息官）核心职责六项：参与组织战略规划、统筹信息化总体架构、管理信息化预算与资源、组织重大信息化项目、推进信息技术应用、承担信息化安全责任。
4. 信息化领导小组职责：审定信息化规划与年度计划、审定重大信息化项目、协调跨部门资源、推进制度与标准、督促考核评估。
5. IT治理中的权责对等原则：重大信息化项目必须明确"决策人（发起人）、责任人（项目经理）、验收人、审计人"，避免多头管理与责任真空。
6. 信息化岗位常见序列：系统管理员、网络管理员、数据库管理员、信息安全管理员、运维工程师、数据工程师；中级及以上应掌握岗位职责边界与任职要求（掌握软考证书、相关工作经验）。

### 4. 信息化战略规划与实施（EGIT + ISS）

定义：信息化战略规划是对组织信息化未来发展的总体谋划，包括信息化规划体系、规划方法、实施路径与保障措施。

关键要点：
1. EGIT 规划方法四步：环境审查（Environment）→ 目标确定（Goals）→ 信息技术应用规划（IT Applications）→ 信息技术规划（IT），其中目标确定需通过业务流程再造与信息系统规划实现。
2. 规划四步骤对应产出：业务流程再造方案、信息系统总体方案、系统架构设计、系统功能与性能规格说明。
3. 规划过程三阶段（信息系统规划）：现状分析与差距诊断、目标蓝图与体系设计、实施计划与路径设计。
4. ISS（Information System Strategy）方法包含现状调查、目标系统描述、逻辑功能与数据设计、物理实现方案、实施计划六部分，强调自顶向下逐步求精。
5. 战略实施路线图常用三阶段：夯实基础（基础设施、标准、安全）、重点突破（业务系统集成、数据治理）、全面提升（智能决策、数据驱动）。
6. 信息化规划必须与组织战略对齐，规划文本应包含现状、目标、差距、任务、指标、保障六要素，并纳入组织年度考核。
7. 规划变更是常态，规划调整应走变更控制流程（提出、评估、审批、发布、归档），并同步修订资源预算与项目组合。

### 5. IT投资管理与信息化绩效评估

定义：IT投资管理是对信息化项目的经济性、战略契合度、风险水平进行事前、事中、事后全过程管控，确保IT投资产生预期价值；绩效评估则是用量化指标衡量信息化建设的成效。

关键要点：
1. IT投资决策常见方法：成本收益法（ROI = 收益/成本）、投资回收期（PP）、净现值（NPV）、内部收益率（IRR）；信息化项目评估应同时考虑财务收益与非财务（战略、效率、服务、竞争力）收益。
2. 信息化绩效评估四维度：经济绩效、管理绩效、技术绩效、社会（服务）绩效。
3. 绩效评估流程六步：明确目标与指标 → 采集数据 → 设定基线 → 定期监测 → 分析比对 → 反馈改进与应用。
4. 常用信息化指标：系统覆盖率（已建系统占应建系统比例）、业务系统集成度、设备完好率、网络可用率、系统平均无故障时间（MTBF）、故障平均修复时间（MTTR）、用户满意度、信息系统投资效益比。
5. 常见评估方法：平衡计分卡（BSC，财务/客户/内部流程/学习成长四维度）、层次分析法（AHP 定权与打分）、TOPSIS 多目标综合评价。
6. 运维成本常用度量：硬件与软件占比、运维外包比例、IT 运维费用占信息化总投入比重（业内经验值宜低于 20%~25%）。
7. 评估失败的常见原因：目标不可量化、指标与业务脱节、数据不可得、只评项目不评成效、缺少前后对比基线。

## 案例分析题

**题目**：

某市为推进"数字政府"建设，2023—2025年累计投入信息化建设资金 6.8 亿元，建成各类业务系统 87 个，覆盖全市 42 个委办局。上级审计发现以下问题：

1. 全市 87 个系统中，有 61 个由各部门自行建设、自行运维，平均每个系统仅 1.2 名技术人员；市级"数据共享交换平台"已接入 31 个系统，但 12 个系统至今未按要求提供数据，平台日均调用量不足设计能力的 5%。
2. 该市 2022 年成立"市信息化建设领导小组"，但组长由一位分管科技的副市长兼任，办公室设在市政务服务管理局，5 年内更换了 3 名 CIO，2 名 CIO 任期不足一年；领导小组自成立以来未召开过一次正式会议，亦未审定过任何年度信息化项目计划与预算。
3. 2024 年某委办局提出建设"智慧监管平台"，理由是"兄弟地市都已建成"，未开展业务流程梳理与需求论证，未做数据共享可行性分析，项目预算 3800 万元，因"支持国产化"仓促上马，建成后使用率不足 15%，年运维费 320 万元，被迫二次立项整改。
4. 财政评审报告指出，全市 87 个系统分散建设，平均单系统投资仅 78 万元，但硬件采购占投资总额 61%，软件开发占比不足 18%，运维经费占总投入比例达 34%，远超建设投入的合理比例。
5. 审计同时发现，2023 年至 2025 年，该市投入信息化建设资金逐年增长（1.6 亿、2.1 亿、3.1 亿），但未开展任何信息化绩效评估，没有建立信息化投资绩效指标体系，也没有对已建系统开展集约化整合与"僵尸系统"清理。

问题：
（1）指出该市信息化管理中存在的主要问题。
（2）针对上述问题，提出改进建议。

**参考答案**：

（1）主要问题：

1. 缺乏有效的 IT 治理与集中统筹。信息化建设领导小组形同虚设，长期未开会、未审定计划与预算，实际处于"挂名运行"状态，信息化决策无单一责任主体，权责不清。
2. CIO 岗位频繁变动（5 年换 3 人、2 人任期不足一年），信息化管理队伍缺乏稳定性和连续性，"CIO 负责制"名存实亡，重大决策出现"多头负责、无人负责"的真空。
3. 缺少总体规划与统一标准。87 个系统由 42 个部门分散自建、自管，无全市统一的信息化总体规划、技术标准规范和数据标准，必然造成信息孤岛与重复建设。
4. 共享平台建设重形式轻实效。平台已接入 31 个系统但调用量不足设计能力 5%，说明建设导向偏向"接入了事"，未明确数据提供方的责任、考核与约束机制，数据共享流于形式。
5. 项目论证与需求分析严重缺失。"兄弟地市都已建成"不构成需求依据，未做业务流程梳理、需求论证和共享可行性分析，导致建设盲目、需求外溢、成功即失败（使用率不足 15%）。
6. 投资结构失衡。硬件采购占比 61%、软件与开发不足 18%，运维经费占总投入 34% 且超过正常区间，表明重硬件采购、轻软件开发、轻运维管理，典型的"重建设轻运营、重采购轻应用"。
7. 缺乏绩效评估与资产全生命周期管理。投入逐年增长但无绩效评估、无指标体系、未开展系统整合与"僵尸系统"清理，信息化投入与产出严重脱钩，财政资金使用效益低。
8. 运维能力不足。平均每系统仅 1.2 名技术人员，运维力量与系统规模严重不匹配，且分散自运维模式无法支撑 87 个系统的稳定运行。

（2）改进建议：

1. 建立健壮的 IT 治理机制。明确由市政府主要领导或分管领导任组长、设专职执行办公室的常态化信息化建设领导小组，赋予其规划审定、预算审批、重大项目决策、资源协调、监督考核五项实质职权，年初审定年度信息化项目计划与预算，年终听取绩效报告。
2. 落实 CIO 负责制并稳定管理队伍。设立不随行政职务频繁变动的专职 CIO 岗位，明确其六项核心职责（参与战略规划、统筹总体架构、管理预算资源、组织重大项目、推进技术应用、承担安全责任），建立任职资格、任期保障与考核评价制度。
3. 编制全市信息化总体规划与统一标准体系。制定包含现状、目标、差距、任务、指标、保障六要素的总体规划，出台统一的技术架构、数据标准、接口规范、安全要求，从源头消除各自为建。
4. 强化数据共享的权责机制。明确数据提供部门的主体责任，将数据质量、及时性、完整性纳入部门绩效考核；同时建立平台调用量、响应时延、接口复用率等数据共享效能指标，对 12 个未提供数据的系统限期整改并通报。
5. 严格项目全生命周期管理。立项前必须完成需求论证、业务流程梳理、数据共享可行性分析和投资效益测算；实行"无共享不新建、无复用不立项"，所有新建系统须先查存量系统，能复用坚决复用，把 61 个分散系统纳入统一目录并开展整合与"僵尸系统"清理。
6. 优化投资结构。压减硬件采购比重，将资金重点向软件开发、数据治理、复用整合类项目倾斜；将运维经费占比控制在总投入的合理区间（约 20%~25%），对已建系统开展集约化运维（统一服务台、统一监控、统一备份）。
7. 建立信息化绩效评估体系。制定包含经济、管理、技术、服务四个维度的绩效指标体系（系统覆盖率、数据共享率、系统可用率、MTBF、MTTR、用户满意度、投资效益比等），采用平衡计分卡与 AHP 相结合的方式，每年开展一次评估，评估结果与下一年度预算安排、领导考核直接挂钩。
8. 加强运维队伍与外包管理。建立集中运维中心与 7×24 小时服务台，按系统分级（核心/重要/一般）设定差异化响应与保障标准；对非核心系统引入运维外包并严格设置服务水平协议与考核扣款条款。

**踩分要点**：

1. 问题定位要分层：先答"治理层"（领导小组形同虚设、CIO 频繁变动、权责不清），再答"规划层"（无总体规划、分散建设、信息孤岛），再答"项目层"（论证不足、需求缺失、投资结构失衡），最后答"运营层"（运维能力不足、共享流于形式、无绩效评估）。阅卷按点给分，答满四层才能拿满。
2. "共享平台调用量不足设计能力 5%"这类数据是送分点，务必点明"重建设轻实效、数据共享流于形式"，并答出"责任到部门 + 纳入绩效考核 + 调用效能指标"三件套。
3. "兄弟地市都已建成"必须批为"以盲目攀比为决策依据，缺需求论证"，这是判断项目决策科学性的关键陷阱。
4. 运维费占比 34% 高于建设投入合理比例，要答出"重硬件轻软件、重建设轻运营"，并给出压减硬件、控制运维占比至 20%~25% 的量化建议。
5. "投入逐年增长但无绩效评估"必须答"建立四维度绩效指标体系 + 平衡计分卡/AHP 方法 + 评估结果与预算挂钩"，只答"加强考核"不得分。
6. 建议部分必须与问题一一对应，前面提了几条问题，后面就要有几条建议，且要带出具体抓手（统一目录、无共享不新建、集约化运维、7×24 服务台、SLA 扣款），只写原则性表述难以得分。
7. 涉及金额、比例、时限的数字建议明确写出（如运维占比控制在 20%~25%、12 个系统限期整改），体现可操作性。

## 记忆口诀

1. 体系六要素：政、规、基、用、人、管（政策法规、规划、基础设施、技术应用、人才、管理体系）；顺序口诀"政策规划打地基，技术应用是核心，人才关键管理撑"。
2. IT治理三体系：COBIT 管对错（EDM/APO/BAI/DSS/MEA 五领域），ITIL 管做好（价值交付），ISO 38500 管方向（责任、战略、获取、绩效、遵从、行为六原则）。记"COBIT 治、ITIL 治事、38500 治道"。
3. 组织三职能：领导决策（CIO）、管理执行（信息中心）、服务支持（服务台/外包）；CIO 六职责：战略、架构、预算、项目、应用、安全。
4. EGIT 四步：环（环境审查）—目（目标确定）—应（应用规划）—技（技术规划），倒过来"技术、业务、应用、数据"即 ISS 自顶向下。
5. 绩效四维度：经、管、技、服；指标五类：覆盖、集成、可用、满意、效益；评估方法 BSC 四维度 + AHP 打分。
6. 本次总口诀：**六要素筑基、三体系定治、三职能管人、四步做规、四维度量效**。
