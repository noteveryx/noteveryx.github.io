# 2026-11-16 寓言故事 · 七营的火漆

> 每天一个研究生水平概念，借一个故事让它在心里生根。

---

## 故事

七座营寨，围着一座城。

攻城前一日，七营主将立下铁约：第二日鸡鸣第一声，要么七营同时擂鼓，要么七营同时收兵。先动的那个人，替其余六个死。

消息只能靠人跑。跑一趟要半夜。这半夜里，城里会出兵，城外会起风。

第一夜无事。

第二夜，城守遣使到东营，请主将单独赴宴。赴宴的主将回营后对左右说：城已破，明日不必擂鼓，各营且退。

这话当天夜里传到了北营。北营主将说：我没听说。可是从北营再传出去时，到了西营耳朵里，已经变成：东营主将已与城守约定共同退兵。

消息在七营之间滚了一夜，每个营听到的都不同。同一句话，到第七营时，已经成了三个版本：城破了、城快破了、不打就破。

天还没亮，西营擂鼓了。孤军冲进护城河，船早备好，一支箭没射就退回来。

败因不在于哪一营听错了，而在于：在这七座营寨之间，没有任何办法在不借助外部见证的前提下，判定谁说的是真话。

于是老营的人提出封蜡：凡转述某营主将的话，必须连同那营的印鉴一起送到。火漆压出的凸纹转手时改不了，假造者要仿，就得连蜡纹一起仿。可蜡纹是可以仿的——所以只靠一枚印不够。

真正管用的是"多数"。

七营里有两营可能是叛徒。什么叫叛徒？不是"坏了"。崩坏的营会沉默：你喊它，它不吭声，你自会绕开它。叛徒营会应答，而且两面三刀：它对东营说城已破，对北营说城未破，对自己人说我一直在和你们周旋。它说的每句话都不假——"东营主将说城已破"是真的，"东营主将没说过"也是真的，只是对象不同。

要判断一个传言是真是假，只能问足够多的人，而且要求他们交出能互相印证的凭据。传言要传遍七营，还得让每营事后都能自查自己手里的疑点少过能造出假象的人数。

算下来：两营可能是叛徒时，七营刚好够用。若每份消息都带能验真的亲笔签押和可核对的火漆——也就是身份可验——五营就够了。签押一旦能验真，叛徒就不能同时冒充三个人开口。

"差这一营"让老营的人夜里睡不着。三营的探子来报：叛徒不在营里，在野外的另一支军。

第二年，七营换了个法子：不再靠夜里的传言，而是每天正午当众开议，议定的事刻在城门口的碑上，所有人看同一块碑。碑只写最后一次，写完封泥，七营各按一份印。

七营还发现一件更麻烦的事：就算叛徒被抓住、就算所有诚实者心里都同意，若消息要跑的路没有上界，谁也不能保证一定能在鸡鸣之前达成一致。老营主将说：法子再对，若天永远不亮，我们就没有明天。

这句话，被记在营志的最后一页。

## 这个故事在讲什么

**概念:拜占庭故障与拜占庭容错共识(Byzantine Fault Tolerance, BFT;拜占庭将军问题,Byzantine Generals Problem)。**

拜占庭故障指的是节点不"坏掉"，而是**任意作恶**：撒谎、只对一部分人说真话、串谋、伪造身份、在被质疑后改口。它比"崩溃故障"(进程直接停机、从此不说话)强得多——崩溃故障可以靠"喊它不答应"识别出来，拜占庭故障不能，你永远无法从外部区分"沉默的叛徒"和"沉默的诚实节点"。

目标是让所有**诚实**节点在以下三条性质下达成一致(这是共识问题的标准三件套)：

1. **一致性(Agreement)**：所有诚实节点决定同一个行动；
2. **有效性(Validity)**：若某个诚实节点决定采取行动 a，则所有诚实节点最终都决定 a(不能大家一起决定一个谁都没提议的选项)；
3. **终止性(Termination)**：在有限轮内必须有定论，不能永远议而不决。

**核心可行性条件**(故事里"七营刚好够用""五营就够"对应)：

- **无身份认证(口头消息，OM(0))**：需要 n > 3m，即至少 3m+1 个节点，m 为最大叛徒数。故事里 m=2、n=7，正是 3m+1。
- **有身份认证(带签名消息，PM(1))**：需要 n > 2m，即至少 2m+1 个节点。故事里 m=2 时，五营即够。签押可验真，叛徒就无法一个人冒充三个人说话，阈值随之降低。
- **同步性假设**：终止性依赖**部分同步**(网络延迟有已知上界，只是上界未知)。完全异步网络下，不可能既保证安全又保证终止——这是 FLP 不可能性(1985)的结论。故事结尾"若天永远不亮，我们就没有明天"正是这句。

**与近义概念的边界**：

- 与**崩溃容错共识**(Paxos/Raft)区别：后者只要求"多数派"存活(容忍 < n/2 崩溃)，节点一旦被多数派认定不响应就可被排除；BFT 必须防一个"活着但系统性撒谎"的节点，阈值从 n/2 抬到 3m+1。
- 与**一般共识/分布式共识**区别：这是同一个问题家族，拜占庭版本是最强故障模型下的版本。
- 与**容错拜占庭复制(BFT 状态机复制)**区别：拜占庭将军问题是"能不能达成一致"的判定问题；PBFT/CBFT 是"怎么高效做到"的具体协议(Shostak 的 OM/PM 理论是可行性证明，PBFT 是三阶段实用协议)。

### 陷阱一：把叛徒当成"会坏的机器"

最常见的错误是想当然：机器坏了会停机，恶意节点应该也会"被检测出来"，于是照搬多数派逻辑。故事里东营主将不是坏掉，他还在正常应答、正常出操；他两面三刀，每句话单独看都是真的。把叛徒当崩溃故障处理，系统会在"看起来一切正常"的假象里错得最惨。

### 陷阱二：以为"多数派"就够了

多数派只是必要条件，不是充分条件。要真正落地，还得同时具备：**可验证的身份**(签押、公钥体系，否则一个人能冒充全营)、**值本身可核对**(不能只传"城已破"三个字，要能被核验)、**消息量的可控**(朴素口头消息协议要 O(n²) 条消息且轮数随叛徒数增长，PBFT 把轮数固定在 3 轮、消息数仍是 O(n²) 但常数极小，实际系统再用聚合签名压到 O(n))。

### 陷阱三：用超时冒充"敌人在哪"

工程上最常见的误用：某节点超时没回应，就断定它叛徒并排除。但网络抖动也会造成超时，而真叛徒可以准时回复骗过超时机制。**超时只能用来切换视图、换一批提问对象，不能用来直接定罪**；再加上"不确定时不排除、累积到证据足够再定罪"的机制。

### 陷阱四：以为终止性是免费的

很多设计只顾"不会做错决定"(安全性)，却让系统陷入"永远不决定"(活性失败)。故事结尾把这一点单独点破：即便所有人都同意，若消息延迟无上界，共识就无法在有限时间内达成。真实系统必须显式引入部分同步假设：超时时间随轮次递增、视图切换、 pacemaker(定时器节点)。

### 拜占庭容错的 5 层用途

1. **分布式账本与联盟链**：共识层的基本盘，容忍节点串谋而不只是宕机；
2. **多签与门限签名**：把"签名阈值"从"必须全部诚实"放宽到"作恶者不超过阈值"，是密钥资产托管的基础；
3. **容错存储与复制**：副本不一致时，用可验证的裁决协议而不是简单多数投票；
4. **安全关键系统**：航空、电网、核电控制器的表决机制，面对的是"被攻击后仍会乱说话"的节点；
5. **随机化共识与抗量子迁移**：当算力足够高时，采用基于随机性的拜占庭协议(Bardet 等)，用概率而非纯计数获得更优的通信复杂度。

## 故事里的隐喻，对应着什么

| 故事元素 | 学术对应 |
|---|---|
| 七座营寨围城 | n 个节点的分布式系统 |
| 铁约：同时擂鼓或同时收兵 | 共识的 agreement(一致性)+ validity(有效性)目标 |
| 消息靠人跑，跑一趟要半夜 | 异步网络的消息延迟无上界 |
| 叛徒两面三刀、每句都真 | Byzantine fault：系统性撒谎、选择性发送，外部不可检测 |
| "崩坏的营会沉默" | crash fault 与 Byzantine fault 的区分 |
| 传言滚一夜变三个版本 | 消息被伪造/曲解，一致性被破坏 |
| 孤军冲进护城河 | 少数派独自行动 = 一致性破缺 |
| 封蜡与凸纹 | 消息认证(message authentication) |
| 亲笔签押可验真 | 数字签名 / PKI，阈值降到 2m+1 |
| "问足够多的人" | 复制、投票与交叉验证 |
| 七营刚好够用(两叛徒) | 无认证时 n > 3m |
| 带签押五营就够 | 有认证时 n > 2m |
| "叛徒在野外的另一支军" | 故障节点可能不在你直接管控的集群内 |
| 正午当众开议、刻碑封泥 | 确定性的消息轮次 + 可验证的最终公告 |
| "若天永远不亮，我们就没有明天" | 活性依赖部分同步；FLP 不可能性 |

## 一句话总结

> 拜占庭容错的核心洞见是：面对一个会当面撒谎的节点，你唯一能依靠的不是信任、不是超时，而是**可验证的身份加上足够的交叉验证冗余**——7 个人防 2 个叛徒靠的是互相印证，而不是靠信任。

这就是 拜占庭故障与拜占庭容错(BFT)。

## 记忆口诀

- 口诀 1：不崩不说话，撒谎才可怕；**故障模型定上限，3m+1 无签名，2m+1 有签名**。
- 口诀 2：三条性质一条都不能少——**一致、有效、终止**，安全与活性分开谈。
- 口诀 3：**超时只能换视角，不能给人定罪**；排除叛徒要靠可验证的证据链。
- 口诀 4：**安全是免费的，活性要买**，买的是部分同步假设、递增超时和视图切换。
- 口诀 5：军事比喻翻译过来就是——**口令+签名+多路验证+定期公布+超时升级**。
